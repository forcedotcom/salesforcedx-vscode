# Observability is spans-only

All *new* telemetry flows through OpenTelemetry spans — there are no separate metrics or logs pipelines for new code. Spans route by configuration: all spans to local console/OTLP debug exporters; top-level and command spans to App Insights and O11y. See [observability/README.md](../../packages/salesforcedx-vscode-services/src/observability/README.md).

The legacy event-based `TelemetryService` API (`sendCommandEvent`, `sendException`, `sendEventData`) is preserved only because it is part of the frozen `salesforcedx-vscode-core` API surface (see [ADR-0006](./0006-core-api-frozen-sunset.md)) with external consumers; it is not a pattern for new code. Its implementation no longer constructs `TelemetryReporter` / App Insights / O11y reporter instances — each call is bridged to a synthetic span via the services `getLegacyTelemetrySender`, and the span exporters convert it to App Insights customEvents / O11y events downstream. Legacy spans retain caller-specific O11y opt-in, endpoint, and product-feature routing; Node App Insights also routes by caller key. Web App Insights keeps its existing fixed connection string.
