# W-23574066: Group trace-flag user picker by UserType

## Approach

Replace the flat `toUserQuickPickItems` conversion with one exported pure helper that excludes the current user, maps each supported Salesforce `UserType` to a fixed localized section, sorts records by section priority then last and first name through `effect/Order`, and injects a plain `QuickPickItemKind.Separator` before each populated section. Map unknown or empty values to the final `Other` section. Keep SOSL, debounce, picker lifecycle, and selected-user handling unchanged.

## Evidence

- `packages/salesforcedx-vscode-apex-log/src/traceFlags/traceFlagJsonSync.ts:35-49` defines `UserRecord` and the current flat conversion; it already excludes `excludeUserId` and renders names, usernames, and raw UserType descriptions without icons.
- `packages/salesforcedx-vscode-apex-log/src/traceFlags/traceFlagJsonSync.ts:79-86` requests active users with `UserType`, then assigns converted search results to the picker.
- `packages/salesforcedx-vscode-apex-log/src/traceFlags/traceFlagJsonSync.ts:97-147` owns the debounced QuickPick lifecycle; grouping changes only the generated `picker.items`.
- `packages/salesforcedx-vscode-apex-log/src/commands/traceflags/traceflagsCommands.ts:91-105` passes the current user's ID to `pickOrgUser` and uses the selected `userId`; the current-user command remains a separate path.
- `packages/salesforcedx-vscode-org/src/orgPicker/orgList.ts:168-184` establishes the repository separator pattern: sorted items followed by `flatMap` insertion of `QuickPickItemKind.Separator` entries.
- `packages/salesforcedx-vscode-apex-log/src/statusBar/traceFlagStatusBar.ts:29-31` and `packages/salesforcedx-vscode-apex-testing/src/commands/apexTestSuite.ts:35-39` establish deep `effect/Order` imports and composed field ordering.
- Existing Apex Log trace-flag unit specs live in `packages/salesforcedx-vscode-apex-log/test/unit/traceFlags` and import focused exports directly from `traceFlagJsonSync.ts`.

## Phases

### Phase 1: Build grouped user QuickPick items

- Add separator-label messages to `packages/salesforcedx-vscode-apex-log/src/messages/i18n.ts`, reusing the existing `trace_flag_tooltip_users` and `trace_flag_tooltip_other` messages only where their text exactly matches. In `traceFlagJsonSync.ts`, define the fixed sections and localized labels: `Standard` -> `Users (Standard)`; `AutomatedProcess` -> `Automated Process`; `PowerPartner` -> `Partner`; `PowerCustomerSuccess`, `CustomerSuccess`, `CsnOnly`, `CspLitePortal`, and `SelfService` -> `Customer/Portal`; `Guest` -> `Guest`; all other or empty values -> `Other`.
- Assign numeric priorities in that exact order, with `Other` last. Keep mapping and priority in one source of truth so sorting and separator labels cannot diverge.
- Export `UserRecord` and a pure `buildUserQuickPickItems(records, excludeUserId): vscode.QuickPickItem[]` helper for direct tests. Preserve selectable items as `UserQuickPickItem` values carrying `userId`; separator values carry only `kind` and `label`.
- Compose `Order.Order<UserRecord>` values for section priority, `LastName`, and `FirstName`, then sort the filtered records with `toSorted`. Use deterministic string ordering without changing displayed names or username/UserType descriptions.
- Convert sorted records to selectable items, then mirror `buildOrgQuickPickItems` with `flatMap`: prepend a separator at index 0 and whenever the mapped section changes. Add no icon fields or icon syntax to items or separators.
- Update `searchUsersEffect` to assign `buildUserQuickPickItems(toUserRecords(searchRecords), currentUserId)` while preserving SOSL fields, active-user predicate, debounce, failure handling, current-user exclusion, and picker selection behavior.

### Phase 2: Unit-test grouping and sorting

- Add `packages/salesforcedx-vscode-apex-log/test/unit/traceFlags/userQuickPickItems.test.ts` in a separate test-only phase, importing the exported type and helper directly.
- Assert mixed records produce only populated separators in fixed order: Users (Standard), Automated Process, Partner, Customer/Portal, Guest, Other.
- Assert records within one section sort by `LastName`, then `FirstName`, and retain `userId`, visible name, username, and UserType description.
- Assert every mapped API value enters its declared section, including all 5 Customer/Portal values.
- Assert unknown and empty UserType values fold into the final `Other` section rather than creating dynamic headers.
- Assert the supplied current-user ID is absent before grouping, including no empty separator for that user's former section.
- Assert item and separator objects contain no icon properties or icon-prefixed labels.
