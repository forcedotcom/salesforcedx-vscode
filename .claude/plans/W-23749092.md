# W-23749092: Disable telemetry for Gov Cloud orgs

## Context

- Classification comes only from Services' current AuthInfo-backed identity and future default-org changes.
- Affected egress: Services production App Insights/O11y spans and legacy App Insights/O11y events.
- Console, file, local OTLP, and localhost diagnostic sinks remain outside the policy.

## Phases

1. **Own private identity and one policy context**
   - Keep public `TargetOrgRef` and exported `DefaultOrgInfoSchema` unchanged. Add a private Services-owned `SubscriptionRef` identity feed carrying `{ orgId, instanceName }`; `ConnectionService.maybeUpdateDefaultOrgRef` updates it from the same desktop/Web Console `AuthInfo` capture that updates the sanitized public ref. No public API snapshot/change exposes `instanceName`.
   - Add accessor-enabled `OrgTelemetryPolicy` under `packages/salesforcedx-vscode-services/src/observability/`. Its one scoped observer consumes the private feed's current snapshot and changes; trim `instanceName`, classify `/^usa9/i` as `gov`, every other present value as `nonGov`, and absence as `unknown`. Store session state in `SubscriptionRef`, make transitions atomic and Gov-monotonic, and expose lookup/change operations without raw identity data.
   - Reorder `activate()` to build one scoped private-feed/policy context before any `ServicesSdkLayer()`. Provide that exact context to Web Console `fileSystemSetup`, the retained `internalLayers` SDK, `globalLayers`/`prebuiltServicesDependencies`, and the published Services runtime. Keep it alive through SDK shutdown; deactivate the retained runtime and SDK resources before closing its scope. Replace the deactivation-only `ServicesSdkLayer()` with the retained runtime/context so activation, Web Console bootstrap, and teardown never construct another policy or observer.
   - Add `OrgTelemetryPolicy` to the explicit `prebuiltServicesDependencies` union and expose its service tag/accessors on `SalesforceVSCodeServicesApi`; this additive contract lets consumers provide the same instance, not construct one. Missing/invalid Services API remains a typed initialization failure for governed egress and fails closed.
   - Update `packages/effect-ext-utils/src/allServicesLayer.ts` so `SdkLayerFor(context)` receives `Layer.succeedContext(api.services.prebuiltServicesDependencies)`. Migrate Lightning, Metadata, SOQL, and Visualforce inline factories to this shared `buildAllServicesLayer`, preserving each localized fallback channel name and managed runtime.
   - Contract tests cover sanitized public `TargetOrgRef` initial snapshots/changes, private desktop/Web Console identity updates, matching/trimming/unknown/Gov-wins, one policy object across both Services SDK construction paths and consumers, and exactly one private-feed observer.

2. **Implement one canonical governed dispatcher**
   - Add the sole lifecycle model in `packages/salesforcedx-vscode-services/src/observability/governedEgressDispatcher.ts`. Boundary adapters submit immutable `{ orgId, payload }`; the dispatcher yields `OrgTelemetryPolicy` and owns a globally ordered, org-partitioned pending store capped at 1000.
   - Model atomic `open | closing | closed` state in one Effect `Ref`. In `open`, admission drops missing-org/Gov items, forwards known non-Gov items directly, and stores unknown items while evicting the global oldest. Classification resolution atomically claims only one org's pending items for send or discard. Shutdown atomically enters `closing`, rejects new admission, stops resolution claims, awaits already-claimed sends, discards only unclaimed pending items, finalizes the lazy sink once, then enters `closed`.
   - One scoped classification fiber drives resolution. No mutable arrays, duplicate queues/maps, timers, retries, fallback classification/sink, or parallel adapter-specific race protocol. Typed sink failures are structurally logged with `orgId`, disposition, and counts, never payloads, and do not terminate later policy processing.

3. **Gate Services production spans**
   - Stamp creation-time `orgId` in `SpanTransformProcessor.onStart` on every production-eligible top-level and command/child span. Governed exporters read only that immutable stamp; existing redaction/validity ordering remains intact.
   - Make `GatedSpanExporter` a thin callback adapter over the Phase 2 dispatcher. A mixed `export` batch admits/discards every span atomically and invokes the original callback exactly once without waiting for unknown resolution; later delegate callbacks cannot re-call it. `forceFlush` waits for submissions, claimed sends, and the initialized delegate. `shutdown` delegates to the canonical close transition.
   - Construct production App Insights/O11y delegates only on the first claimed non-Gov send. Unknown/Gov-only sessions create no transport, Statsbeat, retry storage, connection, sink batcher/timer, or upload hook. Local processors bypass the dispatcher.
   - Provide the Phase 1 policy context to every `ServicesSdkLayer` and per-extension `SdkLayerFor`; no extension runtime owns classification state.

4. **Gate legacy production events once per extension**
   - Make `TelemetryService` own one scoped Phase 2 dispatcher per extension. At initialization, acquire the exact `OrgTelemetryPolicy` from `SalesforceVSCodeServicesApi.prebuiltServicesDependencies`; a missing/invalid API or absent policy records a typed closed dispatcher, so production events drop without private policy construction or unknown forwarding.
   - Snapshot the initial sanitized Services identity once and assign fresh reporter identity objects before registration. Each send snapshots cached creation-time `orgId` into one immutable envelope before enablement/dispatch; later org changes affect only later envelopes.
   - Route each governed envelope once through the dispatcher, then fan an allowed envelope to lazy App Insights/O11y sink adapters. Keep `TelemetryFile` and `LogStream` direct. Internal-host and user/config enablement remain additional allow gates, never Gov overrides.
   - Keep reporters as sink adapters: App Insights creates transport/retry storage on first forwarded envelope; O11y registers inertly and initializes once on first forwarded envelope. Typed initialization failure drops claimed envelopes, remains failed for the session, and is not retried. `TelemetryService.dispose` closes its dispatcher and initialized sinks once.

5. **Add focused unit coverage**
   - Identity/policy/API: Phase 1 contracts, including `usa9*`, sandbox suffix, case, trim, ordinary/missing identity, switching, and conflicts.
   - Dispatcher: missing/Gov drops, direct send, per-org FIFO resolve/discard, global oldest overflow, concurrent admission/resolution, send failure containment, and every `open | closing | closed` race.
   - Spans: both span shapes, mixed batches, creation-time switching, callback once, lazy delegates/storage, flush, and shutdown.
   - Legacy: initial and switched identity, one dispatch/fan-out, precedence, lazy/no-retry sinks, failed-closed Services API, and disposal.
   - Boundaries: no `instanceName` in public refs, spans, envelopes, logs, or policy accessors; local sinks remain direct.

6. **Add deterministic Playwright coverage**
   - Add a production-shaped dependency-injection boundary for identity source and governed delegate factories. Production and tests use the same interfaces; prohibit `NODE_ENV`/extension-mode branches, globals, and exported test mutators in production modules. A separate test-harness entrypoint supplies synthetic identity and counting delegates through those factories, registers control commands, and is bundled only by Playwright-specific esbuild configs. Assert normal production/VSIX bundles contain neither entrypoint nor command IDs; command invocation fails when the harness is absent.
   - The harness command surface atomically resets a test-scoped marker, injects `{ orgId, instanceName }`, waits until the policy reports that exact org's classification, emits marked top-level and command spans, requests dispatcher/delegate quiescence, and returns durable per-host state: policy instance ID, observer-start count, delegate constructions, accepted sends by marker/span shape, and quiescence generation. Commands fail when injection/probes are not installed. The probe replaces governed production delegates only; local/localhost sinks are untouched.
   - Add one Services web spec using the existing UI command-palette bridge to invoke harness commands. Configure its Playwright bundle with `salesforcedx-vscode-salesforcedx.enableFileTraces=true`; configure `playwright.config.web.ts` with a second managed `webServer` running `npm run spans:server -w salesforcedx-vscode-services` on port 3003, with isolated startup/teardown and no stale-server reuse. Snapshot existing span files before the test, use a unique marker, and poll only newer matching JSONL rows.
   - Web sequence: require probe-ready state; inject exact synthetic org ID as non-Gov; await observed classification; emit both span shapes; await returned quiescence generation; assert the same injected delegates' construction/send counts increase. Reset marker counters; inject the same org ID as Gov; await observed Gov; emit uniquely marked spans; await a newer quiescence generation; assert no count increase while matching local span rows appear. Local rows prove bypass only, not suppression.
   - Preserve Lightning's existing one-test `telemetryOutput.desktop.spec.ts` diagnostic unchanged. Add a separate one-test `govTelemetry.desktop.spec.ts` and dedicated fixture based on the current minimal-org fixture. After real-org activation settles, the harness targets one synthetic stamped org ID, waits for that exact policy classification before each emit, and uses the same positive-control/Gov/quiescence/count sequence. Real `DefaultOrgRef` updates for `MINIMAL_ORG_ALIAS` cannot satisfy or overwrite assertions for the synthetic ID. Poll uniquely marked probe/span artifacts; use no reload, toast, elapsed wait, or localhost zero count.
   - Isolate markers, counters, and span snapshots per test/extension host so `fullyParallel` runs and existing JSONL files cannot contaminate assertions. Unit/contract tests prove both Services SDK paths report the same policy instance and one observer; Playwright verifies the activated host exposes that same topology.
