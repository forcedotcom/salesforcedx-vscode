# W-23506243: Use Effect.filterOrFail for LWC bundle-kind guard

## Context

- `packages/salesforcedx-vscode-lwc/src/commands/renameLwc.ts:55-60` manually compares `getBundleKind(bundleUri)` with `'lwc'` and fails with `NotInBundleError`.
- `getBundleKind` returns `LightningComponentKind | undefined`; `kind === 'lwc'` rejects both Aura and unknown kinds.
- Scope: replace only this guard. Preserve bundle discovery, the exact `NotInBundleError` payload, and downstream rename behavior. The current message is a string literal, not an i18n lookup, so no localization-file change is needed.

## Phases

### Phase 1: Replace the bundle-kind guard

- Yield `Effect.succeed(getBundleKind(bundleUri)).pipe(Effect.filterOrFail(kind => kind === 'lwc', () => new NotInBundleError(...)))` so the synchronous discriminator participates in the command's Effect pipeline.
- Remove the manual `if` / `return yield*` guard; no downstream value or control-flow changes.
- Preserve `sourceUri: resolvedSource.toString()` and `message: 'Source path is not within an lwc bundle'` exactly.
