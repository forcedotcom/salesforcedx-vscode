# W-24233838

Replace TransmogrifierService hand-rolled mappers with Schema decode/transform.

## Context

`TransmogrifierService` (`packages/salesforcedx-vscode-services/src/core/transmogrifierService.ts`) still builds `SObject` / `SObjectSemanticModel` with hand-rolled functions. `decodeSObject` already uses `S.decodeUnknown(SObjectSchema)`.

Hand-rolled, delete as each phase lands:

- REST: `mapToSObject`, `mapRestFieldToSemanticField`, `mapRestDescribeToSemanticModel`
- workspace: `isRecord`, `metadataValue`, `asArray`, `optionalString`, `optionalNumber`, `optionalBoolean`, `workspaceFieldType`, `simpleFieldName`, `workspacePicklistValues`, `mapWorkspaceField`, `mapWorkspaceSObjectToSemanticModel`
- shared sort: `compareName`

Output schemas stay the `to` side: `SObjectSchema` in `packages/salesforcedx-vscode-services/src/core/schemas/sObject.ts`, `SObjectSemanticModelSchema` in `packages/salesforcedx-vscode-services/src/core/artifactProjection.ts`. Do not edit those files. Do not change `toMinimalSObject`, `decodeSObject`, `toSemanticModel`, or `TransmogrifierError`. Call sites stay on the service.

Approach: `Schema.transform` / `Schema.transformOrFail` in `transmogrifierService.ts`, decoded with `Schema.decodeUnknown`. `toSemanticModel` maps decode failure to the existing `TransmogrifierError`. No second mapper left in place.

Behavior contract is `packages/salesforcedx-vscode-services/test/jest/core/transmogrifierService.test.ts` (minimal SObject, REST semantic model, workspace metadata with no `runtimeCapabilities`). Do not edit that test in the same commit as `src`.
