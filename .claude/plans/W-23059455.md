# W-23059455 — Consumer NUTs (plugin-apex/plugin-flow) vs apex library PRs

## Context

- CI regression net for `packages/salesforcedx-apex` (`@salesforce/apex-node`). Adopt salesforcedx-templates pattern: on library-src change, checkout consuming CLI plugin, swap its `@salesforce/apex-node` dep for this branch's build, run plugin's `test:nuts`.
- Consumers = `salesforcecli/plugin-apex` + `salesforcecli/plugin-flow`. Both: yarn-classic (`yarn.lock`), `type: module`/ESM, wireit `build`, `test:nuts = nyc mocha "**/*.nut.ts" --parallel`, dep `@salesforce/apex-node ^8.x`.
- Migration (W-23051181) already landed: `packages/salesforcedx-apex` present, publishable (`files: ["lib/src"]`, `main lib/src/index.js`).
- **Pattern refs**:
  - Prior `forcedotcom/salesforcedx-apex` `xNuts` job → `salesforcecli/github-workflows/.github/workflows/externalNut.yml@main` (packageName `@salesforce/apex-node`, externalProjectGitUrl plugin-apex, os matrix).
  - salesforcedx-templates `test.yml` `external-test`: checkout plugin → `yarn remove @salesforce/templates` → `yarn add forcedotcom/salesforcedx-templates#SHA` → build → `yarn test:nuts`.
- **Cannot reuse externalNut.yml**: it does `yarn add ${{ github.repository }}#${{ github.sha }}` = install whole git repo as single-pkg dep. This repo is a monorepo; apex is a subdir pkg → git-dep install fails. Bespoke job required. Swap via `npm pack` tarball (ships prebuilt `lib/src`) → `yarn add file:$TGZ` in the checked-out plugin.
- **Deep-path issue (BLOCKER for green baseline)**: plugin-apex `src/reporters/jsonReporter.ts:17` + 3 NUT files import `@salesforce/apex-node/lib/src/tests/types.js` (`TestRunIdResult`/`ApexTestRunResultStatus`). Migration added an `exports` map (`.` + `./lib/src/utils` only); upstream had `exports: null` (any deep path worked). Verified: current map → `ERR_PACKAGE_PATH_NOT_EXPORTED` on `pkg/lib/src/tests/types.js`. Evidence gathered shows exactly ONE concrete deep subpath is consumed by any known external consumer (`lib/src/tests/types.js`); plugin-flow has ZERO deep imports. Fix = add that ONE explicit subpath entry (mirroring the existing `./lib/src/utils` precedent), NOT a full-subtree wildcard. All known consumers request the `.js` form, so Node exports resolution needs the key `"./lib/src/tests/types.js"` verbatim (a wildcard `"./lib/src/*"` would open the whole `lib/src` tree — streaming, logs, reporter internals — to any npm consumer, widening the public API far beyond the one path needed). Without the fix the plugin-apex NUTs fail at import → net lands permanently red (guards nothing). Fix here for green baseline (Phase 1).
- Auth: plugin NUTs use `@salesforce/cli-plugins-testkit` `TestSession` `devhubAuthStrategy: 'AUTO'` + scratch orgs. AUTO honors `TESTKIT_AUTH_URL` (testkit readme: "Auth url that TestSession will use to auto-authenticate"). Repo secret `SFDX_AUTH_URL_E2E` = devhub auth url (used in other E2E to `--set-default-dev-hub`). Wire `TESTKIT_AUTH_URL: ${{ secrets.SFDX_AUTH_URL_E2E }}`.
- plugin-flow: dep on apex-node but ZERO deep imports (verified) → public-API only; softer signal. plugin-apex hits deep path.
- Standalone workflow — NOT wired into `e2e.yml` (that = post-build VSIX Playwright suites, unrelated trigger).
- DoD: new workflow triggers on `packages/salesforcedx-apex/**` change; plugin-apex + plugin-flow NUTs run against branch-built apex-node and pass; deep path resolves.

## Phases

### Phase 1 — ADR: record the deep-path exports decision (ADRs sequence first)
- Writes `packages/salesforcedx-apex/docs/adr/0001-deep-path-subpath-export.md` (create `docs/adr/` dir lazily; first ADR in this package → `0001`).
- Why an ADR (all three ADR-FORMAT.md gates hold): (1) **hard to reverse** — the `exports` map on a published npm package (`@salesforce/apex-node`) is public API; once external consumers rely on an exposed subpath, narrowing it later is a breaking change; (2) **surprising** — W-23051181's migration PR deliberately scoped `exports` down to `.` + `./lib/src/utils`, so re-widening it needs recorded rationale or the next engineer "fixes" it back; (3) **real trade-off** — genuine rejected alternatives exist (see below).
- Template: short title + 1-3 sentence context/decision/why, plus a **Considered Options** section (earned — rejected alternatives matter here):
  - **Chosen**: add the single explicit subpath entry `"./lib/src/tests/types.js"` mirroring the existing `./lib/src/utils` precedent.
  - **Rejected — full-subtree wildcard `"./lib/src/*"`**: exposes the entire `lib/src` tree (streaming, logs, reporter internals) to any npm consumer; over-broad, harder to narrow later.
  - **Rejected — drop the exports map (revert to `exports: null`)**: restores upstream any-deep-path behavior but discards the typed `.`/`/utils` intent the migration added; least reversible in the "public API" direction (everything becomes public again).
  - **Rejected — plugin-apex fixes its own import** (switch to public API): out of this repo's control; the deep import is real today and the NUT net must go green against the current consumer.
- Verify: markdown lint / `concise` style; file exists at expected path.
- Files: `packages/salesforcedx-apex/docs/adr/0001-deep-path-subpath-export.md`
- Commit: `docs(apex): ADR for lib/src/tests/types subpath export - W-23059455`

### Phase 2 — Restore deep-path subpath export (green-baseline enabler)
- `packages/salesforcedx-apex/package.json` `exports`: add the ONE concrete entry the evidence supports (per Phase 1 ADR), mirroring the `./lib/src/utils` precedent:
  `"./lib/src/tests/types.js": { "types": "./lib/src/tests/types.d.ts", "default": "./lib/src/tests/types.js" }`
- Narrower + more reversible than a wildcard; keeps explicit `.` + `./lib/src/utils`; exposes only the single path any known external consumer actually imports.
- Key must be the `.js` form verbatim — all known consumers (plugin-apex `jsonReporter.ts:17` + 3 NUT files) request `@salesforce/apex-node/lib/src/tests/types.js`; Node exports resolution matches the requested subpath string exactly.
- Verify: node repro — `import('@salesforce/apex-node/lib/src/tests/types.js')` resolves (no `ERR_PACKAGE_PATH_NOT_EXPORTED`); `npm run compile -w packages/salesforcedx-apex` green.
- Files: `packages/salesforcedx-apex/package.json`
- Commit: `fix(apex): expose lib/src/tests/types subpath export for deep-path consumers - W-23059455`

### Phase 3 — Consumer NUT workflow
- New `.github/workflows/apexConsumerNuts.yml`.
- Triggers: `push` `branches-ignore: [main, develop]` + `paths: ['packages/salesforcedx-apex/**']`; `workflow_dispatch`. Concurrency `ci-${{ github.ref }}-apexConsumerNuts` cancel-in-progress.
- Job `nuts`, matrix `plugin: [plugin-apex, plugin-flow]`, `fail-fast: false`, `timeout-minutes: 60`.
- Steps:
  1. checkout monorepo (`actions/checkout@v4`).
  2. `actions/setup-node@v4` node `lts/*` (match plugin test env), cache npm.
  3. `npm ci` (root) → `npm run compile -w packages/salesforcedx-apex` (wireit builds deps).
  4. `npm pack -w packages/salesforcedx-apex` → capture `salesforce-apex-node-*.tgz` abs path to `$GITHUB_ENV` (tarball ships prebuilt `lib/src`; no in-node_modules build needed).
  5. install CLI: `npm install -g @salesforce/cli@${{ vars.SF_CLI_VERSION || 'nightly' }}` via `salesforcecli/github-workflows/.github/actions/retry@main`.
  6. checkout consumer: `actions/checkout@v4` `repository: salesforcecli/${{ matrix.plugin }}` `path: consumer`.
  7. in `consumer/`: `yarn install --network-timeout 600000`; `yarn add file:$TGZ`; `npx yarn-deduplicate; yarn install` (dedup shared `@salesforce/core`); `yarn build`.
  8. NUTs via `salesforcecli/github-workflows/.github/actions/retry@main` (`max_attempts: 3`, `command: yarn test:nuts`, `retry_on: error`), `working-directory: consumer`, env `TESTKIT_AUTH_URL: ${{ secrets.SFDX_AUTH_URL_E2E }}`, `SF_DISABLE_TELEMETRY: true`.
- No e2e.yml wiring.
- Verify: YAML parses (actionlint if avail / `gh workflow list` post-push); push branch (or `workflow_dispatch`) → both matrix legs green; plugin-apex leg proves deep-path import (Phase 2) + public API; plugin-flow leg proves public API.
- Files: `.github/workflows/apexConsumerNuts.yml`
