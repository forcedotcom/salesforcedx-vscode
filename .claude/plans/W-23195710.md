# W-23195710 — coreE2E: background Playwright install (parallel-steps pilot)

## Context

Pilot GHA parallel/background steps (shipped 2026-06-25) in `.github/workflows/coreE2E.yml`.
Playwright-browser install independent of CLI→auth→project→scratch-org chain but runs sequentially after it on cache-miss. Background it → wall-clock = max, not sum.

Blocker: `@action-validator/core@0.6.0` (`check:actions`, `scripts/validateActions.ts`) rejects `background`/`wait`/`wait-all` — bundled schema predates schemastore PR #5845 (2026-06-25). No released/main validator supports keys. No runtime schema override.

Real-schema confirmation (verified against schemastore `master` `github-workflow.json`, def `step`, `oneOf` L485–504):
- `background`, `wait`, `wait-all` are declared step properties (L582–607).
- the step `oneOf` accepts `required:[uses] | [run] | [wait] | [wait-all] | [cancel] | [parallel]`.
- => a **wait-only step (no `run`/`uses`) is valid GitHub Actions YAML**. GitHub's real parser accepts it. Acceptance's "3 OS legs green" will NOT fail for a wait-step syntax reason. Do NOT add a no-op `run`/`uses` to the wait step (would execute a command / diverge from real syntax). Sole gap is the stale local validator.

Reproduced (this repo, `node repro-wait.mjs` against installed `@action-validator/core@0.6.0`, then deleted):
- validator wraps job-shape check in `one_of` (steps-based vs reusable-`uses` branch); step shape also `one_of` but stale schema's step branch only offers `uses`/`run` — no `wait`/`wait-all`.
- `background`/`wait` on a step → steps-branch leaf `{code:"properties", detail:"Additional property 'background'|'wait' is not allowed", path:/jobs/<j>/steps/N}`.
- **wait-only step (no run/uses)** additionally produces a *nested* `one_of` at `path:/jobs/<j>/steps/N` whose leaves are `{code:"required", path:.../steps/N/uses}` and `{code:"required", path:.../steps/N/run}` — orthogonal to the "Additional property" leaf. The plan's original `isSuppressibleLeaf` (properties/Additional-property only) does NOT cover these, so 7 leaves survive and `check:actions` still fails → blocks `precommit`→`check:actions` local commit (`package.json` `check:actions` globs `.github/workflows/*.{yml,yaml}`; `precommit` depends on it).
- a `background`-only step that keeps `uses` (Phase 2 Playwright step) has its inner `one_of` satisfied by `uses`; only the `background` property leaf appears — no nested run/uses one_of.
- whole outer `one_of` cascades; alt (`uses`) branch also errors (runs-on/steps not allowed, uses required) — noise.
- MIXED case: genuine step error sits alongside bg/wait leaves in same `states[0].errors`. Cannot blanket-suppress — must filter leaves, keep genuine ones.
- valid steps workflow (no bg/wait) → 0 errors.

Fix design (validator-only; ships real valid YAML): drop the stale-schema noise for adopters of the new keys, keep every genuine error.
1. suppressible "Additional property" leaves: `code==='properties'` && detail matches `background|wait|wait-all`. Record the step path prefix (e.g. `/jobs/j/steps/1`) of each suppressed `wait`/`wait-all` leaf.
2. suppressible run-or-uses leaves: a nested `one_of` whose only leaves are `required` `run`/`uses` at path `/…/steps/N/(run|uses)` where `/…/steps/N` matches a step path that had a suppressed `wait`/`wait-all` leaf. (Only wait-only steps hit this; `uses`/`run` steps satisfy the inner one_of and never emit it.)
3. for an outer `one_of`: filter each branch's leaves through (1)+(2); if any branch nets 0 leaves → satisfiable → drop whole `one_of`. Else keep remaining leaves.
Keeps all other rules validating on every workflow, incl. future bg/wait/wait-all adopters.

## Phases

### Phase 1 — validator: tolerate background/wait keys

Files: `scripts/validateActions.ts`

Two-pass leaf filtering (single step-tree walk):
- `isPropertyLeaf(e)`: `e.code === 'properties'` && `e.detail` matches `/Additional property '(background|wait|wait-all)' is not allowed/`. Extract the step path (`e.path`, e.g. `/jobs/j/steps/1`); collect the set of step paths that had a suppressed **`wait`/`wait-all`** property leaf (the wait-only steps). `background`-only steps never emit the run/uses one_of, so don't need path tracking, but harmless to include.
- `isRunOrUsesRequiredLeaf(e, waitStepPaths)`: `e.code === 'required'` && `e.path` matches `/(.*\/steps\/\d+)\/(run|uses)$/` && capture group 1 ∈ `waitStepPaths`. This drops the nested `run`/`uses` one_of leaves that the stale schema emits for a wait-only step.
- because run/uses suppression depends on knowing all suppressed wait paths first, gather property-leaf step paths in a first pass over the leaf tree, then filter in a second pass. Keep both passes pure (recurse the same tree twice, or collect `{path, waitPaths}` then filter) — no `let`.
- rework recursion for outer/nested `one_of`: map each state → collect+filter leaves through both predicates; if any filtered state has 0 leaves → `one_of` satisfiable → return `[]` (drop). Else keep remaining leaves. Applies to the outer job `one_of` and the inner step `one_of` alike (inner step one_of for a wait-only step nets 0 after run/uses suppression → dropped → its parent state can net 0).
- non-`one_of` errors: drop suppressible leaves too (defensive).
- warn: `Console.warn` once per file listing which new keys were tolerated (do NOT add to `failureCount`).
- `program`: `Stream.filter` must key off post-filter leaf count, not raw `result.errors.length` (else satisfied files slip to tap w/ empty output). Compute filtered leaves once, reuse for filter + tap.
- keep functional style (map/flatMap, const, no let), keep existing comments.
