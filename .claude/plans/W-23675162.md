# W-23675162: Remove unused org telemetry singleton

## Context

`packages/salesforcedx-vscode-services/src/core/defaultOrgRef.ts` defines `getTelemetryIdentitySnapshot`, a synchronous telemetry-specific view over the process-wide default-org reference. `packages/salesforcedx-vscode-services/src/index.ts` exposes it and its type through `SalesforceVSCodeServicesApi`, but no repository consumer uses that API. Remove this unused surface while retaining `getDefaultOrgRef`, identity seeding, and default-org behavior.

## Phases

1. **Remove the unused telemetry snapshot API**
   - Delete `TelemetryClassification`, `TelemetryIdentitySnapshot`, `GOV_POD_PATTERN`, and `getTelemetryIdentitySnapshot` from `packages/salesforcedx-vscode-services/src/core/defaultOrgRef.ts`.
   - Remove the related import, exported type, `SalesforceVSCodeServicesApi` member, and activation return member from `packages/salesforcedx-vscode-services/src/index.ts`.
   - Remove snapshot-only setup and assertions from `packages/salesforcedx-vscode-services/test/jest/observability/seedTelemetryIdentities.test.ts`; keep coverage of identity seeding into `defaultOrgRef` and global state.
   - Commit: `refactor: remove unused org telemetry singleton`

## Skills to apply

- `typescript`: preserve repository TypeScript conventions while deleting the API.
- `external-consumers`: account for the exported Services API removal.
- `services-extension-consumption`: keep the remaining Services API shape and activation wiring consistent.
- `verification`: run the repository-required checks for changed Services files.
