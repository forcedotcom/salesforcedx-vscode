# W-24221258 — Unify extension package.json schema onto Effect Schema in effect-ext-utils

## Context

- `packages/effect-ext-utils/src/extensionPackageJson.ts` already owns the exported Effect schema used for Salesforce extension manifests, but it lacks `publisher`.
- `packages/drivable-vscode/src/extensionService.ts` independently defines `name`, `publisher`, and `version` before reading extension manifests from disk.
- `packages/salesforcedx-vscode-core/src/metadataSupport/metadataXmlSupport.ts` independently defines the `version` shape for the Red Hat XML extension manifest.
- Centralize these fields in `@salesforce/effect-ext-utils`; consumers compose the validation strictness they need from that schema instead of repeating manifest fields.
- `packages/salesforcedx-lightning-lsp-common/src/types/packageJson.ts` remains separate: it models workspace package.json files, not VS Code extension manifests.

## Phases

### Phase 1 — Specify the shared extension manifest schema

Commit: `test(effect-ext-utils): specify extension package schema - W-24221258`

- Add `packages/effect-ext-utils/test/jest/extensionPackageJson.test.ts`.
- Cover decoding the shared fields used by consumers: `name`, `publisher`, `version`, `displayName`, `o11yUploadEndpoint`, and `otelConnectionString`.
- Cover rejection of invalid values for declared string fields.

### Phase 2 — Replace duplicate schemas with the shared schema

Commit: `refactor: unify extension package schemas - W-24221258`

- Update `packages/effect-ext-utils/src/extensionPackageJson.ts` to include `publisher` in the canonical Effect schema.
- Update `packages/drivable-vscode/src/extensionService.ts` to derive its required `name`/`publisher`/`version` decoder from `ExtensionPackageJsonSchema`; retain JSON parsing for the file contents.
- Update `packages/drivable-vscode/package.json` to depend on `@salesforce/effect-ext-utils` and compile it first.
- Update `packages/salesforcedx-vscode-core/src/metadataSupport/metadataXmlSupport.ts` to decode the Red Hat XML extension manifest with `ExtensionPackageJsonSchema`; remove `RedHatXmlPackageJsonSchema`.
- Update `package-lock.json` for the new drivable-vscode workspace dependency.
