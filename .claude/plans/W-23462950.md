# W-23462950 — Auto-merge doc-only PRs

## Context

Doc-glossary-only PRs → squash-merge to `develop` automatically, no human review.

Facts (verified on `develop`, 2026-07-23):
- Branch protection: `enforce_admins=false`, 1 required review (CODEOWNERS), required checks = `pr-validation`, `build-and-test/build-all`, `build-and-test/unit-tests` (linux+windows), `code-quality`.
- Only `validatePR.yml` runs on `pull_request`. `testCommitExceptMain.yml` + 16 E2E workflows run on `push` (feature branches), not PRs.
- **All required-check workflows carry `paths-ignore`** covering `.claude/**` + root `docs/**`. On a doc-only PR they don't fire → required checks never post → normal merge blocks forever. Only org-level SAST + Credential Scanning run on doc PRs (not in required list).
- ⇒ bot must **admin-merge** (bypasses absent required checks + review; `enforce_admins=false` lets repo-admin bot through). "Poll until required green" (WI gate 5) would deadlock — corrected below.
- `svc-idee-bot` = repo admin; org secret `IDEE_GH_TOKEN` present. Team `forcedotcom/ide-foundations` exists (id 13324432).
- 18 workflows share 1 identical `paths-ignore` block (not 19 — WI estimate off).

## Phases

### Phase 1 — add `.github/workflows/docOnlyAutoMerge.yml`
commit: `ci(workflows): auto-merge doc-only PRs via svc-idee-bot - W-23462950`

- trigger: `pull_request: [opened, reopened, synchronize]`, `branches: [develop]`. NO `paths` filter (job must see full file list to require ALL doc-only). `pull_request` not `pull_request_target` — team members push branches to origin, so secrets available; avoids fork-secret footgun.
- `concurrency: group doc-auto-merge-${{ github.event.pull_request.number }}, cancel-in-progress: false` — no double-merge on rapid synchronize.
- perms: `contents: write`, `pull-requests: write`, `checks: read`.
- single job, all steps use `GH_TOKEN=${{ secrets.IDEE_GH_TOKEN }}`:
  1. **doc-only gate** — `gh pr view --json files -q '.files[].path'` (paginates). Every path must match allowlist:
     - `CONTEXT.md` (root exact), `CONTEXT-MAP.md` (root exact)
     - `**/CONTEXT.md`
     - `docs/**/*.md` AND `**/docs/**/*.md` (root + `packages/*/docs`, `.md` only)
     - `.claude/**/*.md` (`.md` only — NOT `.claude/**/*.js`)
     - any non-match → `exit 0` neutral (no merge), log reason.
  2. **author gate** — `gh api orgs/forcedotcom/teams/ide-foundations/memberships/<author>` → state active; else neutral exit.
  3. **review gate** — `gh pr view --json reviewDecision`; `CHANGES_REQUESTED` → neutral exit.
  4. **mergeable gate** — `gh pr view --json mergeable`; not `MERGEABLE` → neutral exit.
  5. **checks-settled gate** — poll `statusCheckRollup` (bounded ~10min, ~15s interval). Absent required checks never appear as rows (only started ones do). **Race guard (adversary Q3):** empty rollup right after PR-open is NOT "settled" — org SAST + Credential Scanning haven't queued yet. Require the expected doc-PR contexts present as rows before settling: `SAST` AND `Credential Scanning Analysis` must each appear (by name). Until both present → keep polling. Once present: any settled row FAILURE/CANCELLED/TIMED_OUT → `exit 1` (never merge over a failing scan); any IN_PROGRESS/QUEUED → keep polling; all settled non-failing → proceed. Timeout w/o both expected rows → `exit 1` (fail safe, no merge).
  6. **merge** — `gh pr merge <num> --squash --admin` (admin bypass = absent required checks + review).
