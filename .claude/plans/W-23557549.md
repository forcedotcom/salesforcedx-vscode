# W-23557549: Show error tag in channel output

## Approach

Derive 1 optional channel-only prefix from the outer error returned by `Cause.squash`. If the outer error is a record with a string `_tag`, read it through `Reflect.get` and format `[<tag>] `; otherwise use no prefix. Apply it only to `appendToChannel` messages, preserving notifications, actions, and deploy/retrieve summary suppression.

## Phases

### Phase 1: Prefix channel output

- Update `packages/salesforcedx-vscode-services/src/vscode/errorHandlerService.ts`.
- After `Cause.squash`, use the existing `isRecord`, `_tag` property guard, `Reflect.get`, and `isString` narrowing to derive `[<tag>] ` or an empty string from the outer error only.
- Apply the prefix to both channel branches: before `Error: ...` when actions exist and before the base message when they do not.
- Leave `getBaseMessage`, nested action collection, `showErrorMessage` arguments, channel-show behavior, and `DeployCompletedWithErrorsError`/`RetrieveCompletedWithErrorsError` suppression unchanged.

### Phase 2: Cover tagged and untagged errors

- Update `packages/salesforcedx-vscode-services/test/jest/vscode/errorHandlerService.test.ts` separately from `/src` changes.
- Use `Schema.TaggedError` fixtures with a `message` field, following repository Effect error conventions.
- No actions: assert channel output is `[TestTaggedError] <message>` and `showErrorMessage` remains `<message>`.
- Actions: assert channel output is `[TestTaggedError] Error: <message>\n\n<actions>` and notification text/actions remain unprefixed.
- Keep native `Error`, string, and actions-bearing untagged assertions as no-prefix coverage.
- Keep deploy/retrieve completed-with-errors assertions proving tagged summary errors still skip `appendToChannel`.

### Phase 3: Cover the consumer output-panel path

- Add `packages/salesforcedx-vscode-metadata/test/playwright/specs/taggedErrorChannelOutput.headless.spec.ts`.

- Assert the notification is exactly the unprefixed message, then select `Salesforce Metadata` output and assert the exact `[ManifestSelectionRequiredError] <message>` line.
