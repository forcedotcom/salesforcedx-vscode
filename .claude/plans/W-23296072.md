# W-23296072 — Toggle filters: independent local/org visibility controls

## Context

- Package: `salesforcedx-vscode-org-browser`
- Replace cyclic viewMode with 2 independent toolbar toggles (show-local, show-org)
- Top-level types filtered at `getChildren(!element)` based on:
  - showLocal OFF → hide types with local files (show only org-only types)
  - showOrg OFF → hide org-only types (in describe, not in local ComponentSet)
- Filter state: `workspaceState` keys `orgBrowser.showLocal` / `orgBrowser.showOrg`
- Context keys: `sf:orgBrowser.showLocal`, `sf:orgBrowser.showOrg`, `sf:orgBrowser.hasOrgData`
- Org toggle disabled until first type expansion populates org data (hasOrgData = false initially)
- Auto-migrate legacy `orgBrowser.viewMode` → booleans on activation
- Icons: `resources/{dark,light}/cloud-on.svg` (toggle visual); use codicon `$(eye)`/`$(eye-closed)` for local toggle

## Filter semantics

The root `getChildren(!element)` path calls `describe()` to get all org metadata types and maps them to tree nodes. Types fall into two categories: those with local files ("local types") and those without ("org-only types"). Each toggle independently controls visibility of one category:

- **showLocal ON, showOrg ON** (default): all describe types (current behavior)
- **showLocal OFF**: hide types WITH local files (show only org-only types)
- **showOrg OFF**: hide types WITHOUT local files, i.e. org-only types (show only local types)
- **Both OFF**: intersection — types in describe AND local ComponentSet (empty in practice, since a type is either local or org-only)

Both filters need ComponentSet at root. describe → org types; ComponentSet → local types. Each toggle removes 1 source from visible set.
