# W-24179402 — Migrate unit tests from Jest to Vitest

## Context

Replace Jest as the repository's unit-test runner with Vitest. Preserve test behavior, coverage, JUnit output, VS Code mocks, and Wireit orchestration. Jest integration-test configuration remains because this work item only names unit tests.

## Phases

### 1. Add Vitest unit-test infrastructure

Commit: `chore: configure vitest for unit tests`

- Add `config/vitest.base.config.ts`, `scripts/setupVitest.ts`, and root `vitest.config.ts`, translating the current unit settings from `config/jest.base.config.js`, `scripts/setup-jest.ts`, and `jest.config.js`.
- Add package-local `vitest.config.ts` files corresponding to unit-only `packages/*/jest.config.js` files; preserve each package's aliases, environment, setup, exclusions, coverage, and transforms.
- Update root and affected `packages/*/package.json` test commands, Wireit inputs, Vitest dependencies, JUnit aggregation inputs, `package-lock.json`, `tsconfig.common.json`, and `eslint.config.mjs` for Vitest unit tests.
- Keep `config/jest.integration.config.js`, package `jest.integration.config.js` files, and their required Jest dependencies/configuration.

### 2. Convert unit-test APIs

Commit: `test: migrate unit tests to vitest APIs`

- Convert `scripts/**/*.test.ts` and `packages/**/test/{unit,jest}/**/*.{test,spec}.{ts,tsx}` from Jest globals, mocks, timers, spies, module mocking, and Jest-specific types to Vitest equivalents.
- Update unit snapshots and test-only helpers only where Vitest requires a format or API change; do not change production behavior.
- Keep integration tests on their existing Jest APIs.

### 3. Remove superseded Jest unit configuration

Commit: `chore: remove jest unit-test configuration`

- Delete root `jest.config.js`, `config/jest.base.config.js`, and package `jest.config.js` files replaced by Vitest.
- Remove Jest dependencies, ESLint configuration, setup code, and Wireit inputs used only by unit tests; retain everything referenced by integration tests.
- Update stale unit-test references in `.vscode/launch.json`, `.jscpd.json`, `knip.json`, and comments/configuration that point to the replaced Jest unit runner or files.

## Skills to apply

- `concise` — keep plan and migration notes compact.
- `packageJson` — preserve repository package and dependency conventions.
- `wireit` — update commands, dependencies, files, and outputs explicitly.
- `typescript` — keep converted tests and setup files within TypeScript standards.
- `verification` — run repository-required checks after the migration.

## Verification

1. Run `npm install` from the repository root.
2. Run `WIREIT_CACHE=none npm run compile`.
3. Run `WIREIT_CACHE=none npm run lint`.
4. Run `WIREIT_CACHE=none npm test` and confirm Vitest executes all migrated unit suites and emits the expected JUnit files.
5. Run the retained Jest integration-test scripts from affected package manifests and confirm they still pass.
6. Run `npm run check:knip` and `npm run check:dupes`.
7. Search unit-test files, unit-test commands, and Vitest configs for remaining Jest API/config references; allow only references required by retained integration tests or tested Jest-named product behavior.
