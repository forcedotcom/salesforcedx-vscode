# W-24293092

## Context

- Typed ESLint rule: nested ternaries that choose an Effect → `Match.value` / `Match.when` / `Match.orElse`.
- Why: 3+ Effect cases nest visually. Match keeps each case one flat line; same pipe continues into tap / ignore / run.
- Behavior source: `.claude/skills/effect-best-practices/references/composition-style.md` — "Match over nested ternaries for dispatch".
- `Match.orElse(() => Effect.void)` = no-op branch (trailing `: Effect.void`).
- Prerequisite guards stay early returns. Rule flags nested Effect dispatch ternaries only. Type-aware so non-Effect ternaries stay untouched.
