# W-23558126: Move alias list command to org extension

## Context

- Core currently owns `aliasListCommand`, exports it from `src/commands/index.ts`, and registers `sf.alias.list` during activation.
- The command reads aliases through the shared services `AliasService`, renders them with `createTable`, appends the table through `ChannelService`, and shows that channel.
- Core alone contributes the command and its palette entry, gated by `sf:project_opened && (!isWeb || (isWeb && sf:code_builder_enabled))`.
- Core alone contains `alias_list_text` in both package NLS files and both source-message files.
- Org already obtains `AliasService` and `ChannelService` from the services API, registers Effect commands with `AllServicesLayer`, and wires that layer's channel to the `Salesforce Org Management` output channel.
- Org has no dedicated alias-list Jest or Playwright coverage. Existing org desktop specs demonstrate command-palette and output-channel assertions.

## Approach

Move the existing command implementation and all command ownership metadata from core to org without changing the public command ID, title, Japanese translation, palette visibility condition, table columns, or shared services. Add focused regression coverage in separate test phases.

## Phases

1. **Transfer production command ownership**
   - Move `packages/salesforcedx-vscode-core/src/commands/aliasList.ts` to `packages/salesforcedx-vscode-org/src/commands/aliasList.ts` without changing its Effect/service/table behavior.
   - Remove the core command export, activation import, and `sf.alias.list` registration.
   - Export `aliasListCommand` from org's command index, import it into org activation, and register `sf.alias.list` with org's existing `registerCommandWithLayer(AllServicesLayer)` path.
   - Move the `sf.alias.list` command contribution and command-palette entry from core's `package.json` to org's `package.json`, preserving the title placeholder and exact `when` clause so only one installed extension contributes the ID.
   - Move `alias_list_text` with its existing English and Japanese values from core to org in `package.nls.json`, `package.nls.ja.json`, `src/messages/i18n.ts`, and `src/messages/i18n.ja.ts`.
   - Leave `AliasService`, `ChannelService`, and extension dependency declarations unchanged; org already consumes the services extension.

2. **Add focused unit coverage**
   - Add `packages/salesforcedx-vscode-org/test/jest/commands/aliasList.test.ts` using a provided `ExtensionProviderService` services API.
   - Assert aliases are read from `AliasService`, rendered as Alias/Username table rows, appended to `ChannelService`, and the channel is shown.
   - Keep this test-only phase separate from production edits per repository verification guidance.

3. **Add command ownership and output regression coverage**
   - Add one org desktop Playwright spec following the existing org command/output pattern.
   - Resolve the palette title from org's `package.nls.json`, verify the command appears after org activation, invoke it, select `Salesforce Org Management`, and assert the rendered alias table contains stable alias and username values from the fixture's authenticated org.
   - Keep the Playwright change in its own test-only phase and avoid new helpers where existing palette/output utilities suffice.

4. **Post-implementation verification**
   - Search both packages for `sf.alias.list`, `aliasListCommand`, and `alias_list_text`; confirm production ownership exists only in org and all 4 org label locations contain the transferred values.
   - Validate both manifests: org defines the command and preserved palette condition; core defines neither command nor menu reference.
   - Run the focused org Jest spec, then the org and core package unit suites from the repository root.
   - Run the focused org desktop Playwright spec with `WIREIT_CACHE=none` and `--retries 0`; no web run exists for org because the package exposes only `test:desktop`.
   - Run `npm run check:dupes` and inspect changed-code findings.
   - Run repository readiness hooks and require compile, lint, Effect LS diagnostics, unit tests, VS Code bundle, and knip to pass before implementation is reported complete.
   - Inspect the final diff for an unchanged command ID, title/translation values, palette condition, Alias/Username table shape, and absence of unrelated core/org changes.
