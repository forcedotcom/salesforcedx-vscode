## Phases

### Phase 1 — Web-bundle closure guard for apex web consumer (anti-regression)
- Deliverable: durable gate. Bundles already build clean; without a guard, a future apex src edit (new bare `require('child_process')`, ESM dynamic import, un-aliased builtin) leaks into web bundle undetected.
- Add `scripts/bundling/assert-web-safe.mjs`: reads a browser metafile path (arg), collects `external:true` import paths across `inputs`, fails (nonzero exit) on any node-builtin outside an allowlist.
  - Allowlist (documented benign): `vscode`, `scripts/bundling/*-global.js` injects, `vm` (asn1 try/catch fallback — cite chain above).
  - Node-builtin detection: `node:` prefix OR bare name in `module.builtinModules`.
- Wire into `salesforcedx-vscode-apex-testing/esbuild.config.mjs`: after `writeFile(dist/browser-metafile.json)`, call assert on that metafile; throw → nonzero → wireit `vscode:bundle` fails.
- Scope: apex-testing only (sole apex-node web consumer). Low blast radius — not a root gate, not other packages.
- Verify: (a) unalias `os` in web.mjs OR add bare node-only import in apex src → esbuild resolution fails at build (esbuild's own resolver, not the guard); revert → passes. (b) guard's own throw path only bites a try/catch-wrapped un-aliased builtin left external in the metafile; empty-polyfilled builtins never surface as externals (see assert-web-safe.mjs gap comment).
- Files: `scripts/bundling/assert-web-safe.mjs`, `packages/salesforcedx-vscode-apex-testing/esbuild.config.mjs`
- Commit: `build(apex): web-bundle closure guard for apex-testing (assert-web-safe) - W-23059502`
