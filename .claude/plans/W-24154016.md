# W-24154016

Add QueryService matching sf-effect query; replace extension `connection.query`.

## Context

Extensions call jsforce `connection.query`. No `QueryService` in `salesforcedx-vscode-services`.

Call sites:

- `packages/salesforcedx-vscode-soql/src/commands/dataQuery.ts` — REST + `connection.tooling.query`, `{ autoFetch: true, maxFetch, scanAll }`
- `packages/salesforcedx-apex/src/utils/traceFlags.ts` — `connection.query<IdRecord>(userQuery)`
- `packages/salesforcedx-apex/src/tests/utils.ts` — `connection.query` for `NamespacePrefix` (PackageLicense, Organization)
- `packages/salesforcedx-vscode-soql/src/editor/queryRunner.ts` — `conn.query(soql, { autoFetch: true, maxFetch: maxRows ?? 50_000, scanAll })`

Wire like `ConnectionService`: `servicesLayers.ts` (`ConnectionService.Default`), `src/index.ts` (import, services union, `services` object, type export).

1 path: `QueryService.query` only. Remove those `connection.query` calls. No second query API, no jsforce fallback.

## Phases

### 1. Add QueryService

`feat: add QueryService matching sf-effect query`

- Add `packages/salesforcedx-vscode-services/src/core/queryService.ts` — `Effect.Service`
- `query(connection, { soql, tooling?, scanAll?, maxFetch? }, schema)`
- Transport: the passed jsforce `Connection`. Web-safe. No `Session` import, no `@salesforce/sf-effect-sdk` dep (`"browser": "./dist/web/index.js"`)
- Collect the record stream into a `records` array. Keep `totalSize`
- `maxFetch` set → stop the stream at that count
- `maxFetch` omitted → first page only (apex `query` calls pass no options)
- Dynamic SOQL: `Schema.Unknown` or passthrough that keeps `attributes` and child relationships (a Struct strips fields the CSV/table path flattens)
- Totals-only envelope when `records` is absent (`SELECT COUNT()`; `.claude/skills/effect-best-practices/references/composition-style.md` reads `totalSize` only)
- Register `QueryService.Default` in `packages/salesforcedx-vscode-services/src/servicesLayers.ts`
- Export on `api.services` from `packages/salesforcedx-vscode-services/src/index.ts` (same slots as `ConnectionService`)

### 2. Unit test

### 3. Replace call sites

`refactor: replace extension connection.query with QueryService`

- Callers still see a `records` array plus `totalSize`
- `dataQuery`: REST and `connection.tooling.query` both call `query`. `scanAll` from `stripAllRows`. `maxFetch` from `salesforcedx-vscode-soql.maxQueryLimit` (default 50_000). Pass the `Connection` from `ConnectionService.getConnection()`
- `queryRunner.ts`: `scanAll` from `stripAllRows`. `maxFetch` from `maxRows ?? 50_000`. Pass the `conn` argument
- Apex: pass the `Connection` already held (`TraceFlags` constructor, `queryNamespaces(connection)`)
- `resolveInstalledNsRecords`: catch stays. Tooling fallback is `query({ tooling: true })` inside that catch, then `[]`
- `queryNamespaces`: `Promise.allSettled` stays. Effect failure is a rejected promise inside those `try` / `allSettled` blocks
