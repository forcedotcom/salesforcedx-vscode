# W-23358900 — Productionize VF web: ship `browser` field, drop spike gating

## Context

- Depends on WI 1 (spike W-23358899, merged `ef231c992`). Split already done:
  - `src/languageClient/{index,node,web,clientOptions}.ts` — platform branch via `ESBUILD_PLATFORM`; web uses `vscode-languageclient/browser` + `new Worker`, node keeps IPC.
  - `esbuild.config.mjs` — builds `dist/web/index.js` + `dist/web/visualforceServer.js` (IIFE worker); typescript regression guard.
- Spike gates shipping: `scripts/spike-browser-field.mjs` injects `browser` only when `VF_WEB_SPIKE=1` (run:web/test:web), restores after → shipped VSIX stays browser-less.
- WI 2 = "productionize": promote VF to a real web-enabled extension like `salesforcedx-vscode-lwc`.
- Ship model (LWC): permanent `"browser": "./dist/web/index.js"`, plain `run:web`/`test:web` (no injection), `.vscodeignore` ships `dist/web` (only excludes `dist/*-metafile.json`).
- eslint `vscodeignoreRequiredPatterns` activates once `browser` present; VF `.vscodeignore` already has all `REQUIRED_STATIC_ENTRIES`.
- e2e spec exists (`visualforceLsp.headless.spec.ts` on `playwright.config.web.ts`) but is NOT run in CI: `visualforceE2E.yml` has only `e2e-desktop` (runs `test:desktop`); nothing invokes `test:web`. Shipping `browser` with zero CI enforcement of the web path is a silent-regression risk — this WI must add the `e2e-web` job.
- Web spec needs no org (seeds `.page` via memfs Explorer "New File"), so mirror `lwcPlaywrightE2E.yml` `e2e-web` (ubuntu, no CLI/org/dev-hub setup), NOT `metadataE2E.yml` (org-dependent).
