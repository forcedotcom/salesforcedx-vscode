# W-24330048

Manual test plan section on PR open.

## Context

- On `pull_request` `opened` and `synchronize`, a GitHub Action writes one Manual test plan block into the PR body.
- Shape like changelog body (workflow + Effect script + judgment skill). New script. Do not copy `scripts/changelogBody/changelogBody.mts` (`packageSet`, section renderer, commit-range model stay there).
- Checkout PR head SHA, `fetch-depth: 0`. Script gathers facts. `Agent.prompt` with `tools: []`. Judgment skill from the base branch. Script validates JSON against facts, splices one marked block. Rest of the body stays.
- Missing `IDEE_CURSOR_API_KEY` skips the job. Cursor error, schema failure, checklist that does not bind to facts, or missing skill ref: log, exit 0, body unchanged. Not a merge gate.
- Body edit uses `github.token` (`pull-requests: write`). Not `secrets.IDEE_GH_TOKEN`. A PAT would re-fire `validatePR.yml` `edited` (`pr-validation`, `code-quality`, `check-effect-diagnostics` have no `action != 'edited'` guard). `GITHUB_TOKEN` does not ([Triggering a workflow from a workflow](https://docs.github.com/en/actions/using-workflows/triggering-a-workflow#triggering-a-workflow-from-a-workflow)).
- Draft-time `## Test plan` leaves `.claude/workflows/auto-build-wi.js` `draftPrPrompt`.

## Phases

### 1. `feat(ci): add manual test plan judgment skill`

`.cursor/skills/manual-test-plan-judgment/SKILL.md`

- Frontmatter like changelog-judgment. `disable-model-invocation: true`. Only caller: the manual test plan script.
- Reply: one JSON object, no fences.
- Schema the script accepts:
  - `{ "kind": "nothing" }` renders `Nothing worth manually testing.`
  - `{ "kind": "checklist", "items": [ ... ] }` with one or more items:
    - `{ "kind": "watch-video", "spec": string, "workflow": string, "job": string }`
    - `{ "kind": "manual", "step": string }`
- `job` is a job key that workflow file defines (`e2e-web`, `e2e-desktop`, `e2e-desktop-lsp`, `e2e-desktop-run-tests`, `e2e-desktop-debug-tests`, `e2e-conflicts-web`, `e2e-conflicts-desktop`, `code-builder-e2e`, …). Not the union `e2e-web | e2e-desktop`.
- Judgment traces what the change does for the end user, including a diff in services or a language server.
- `nothing` when there is no extension surface, or the behavior is already asserted. Language servers are on-screen.
- An assertion clears only what it asserts. Command-exists, UI-opened, and no-critical-errors do not clear a surface.
- Visual check (manual item) when e2e does not assert the surface, including refactors.
- Watch-video item names a spec path, a workflow `name`, and a job key from the facts. Spec may be a dependent package path. Artifact URL stays out.
- Checklist lines render as GitHub task items. Manual steps are the other checkbox.

### 2. `feat(ci): splice a manual test plan from PR facts`

New `scripts/manualTestPlan/` (not a fork of `changelogBody.mts`).

`package.json`: `name` `@salesforce/manual-test-plan`, `private: true`, `type: module`. No `files`. Deps pinned to the same versions as `scripts/changelogBody/package.json` (`effect`, `@effect/platform`, `@effect/platform-node`, `@cursor/sdk`). Commit `scripts/manualTestPlan/package-lock.json` so `npm ci` matches `changelog-body.yml`.

`manualTestPlan.mts` shares only this shape with changelog body: `Agent.prompt` (`tools: []`, `model: { id: 'auto' }`, temp `local.cwd`, `apiKey` from `CURSOR_API_KEY`) and `Schema.parseJson`. Leave `packageSet` and the section renderer in `changelogBody.mts`.

Facts JSON, one record per touched workspace package:

- PR diff.
- That package's `test/playwright` specs: path + text.
- Unit tests the diff itself changes (path + text). Plus the path mirror in the same package when the file exists: changed `src/<rel>.ts` → `test/jest/<rel>.test.ts` (`src/core/retrieveOnLoad.ts` → `test/jest/core/retrieveOnLoad.test.ts`). Not basename equality. Basename collides: `src/index.ts` and `src/messages/index.ts` vs nine `packages/*/test/jest/**/index.test.ts`.
- E2e workflow: leaf `.github/workflows/*E2E.yml` (not `e2e.yml`, `playwrightE2EFullSuite.yml`, `rerunPushE2E.yml`) whose jobs reference the package. Match when a `run` contains `-w <dir>` or `-w <package.json name>`, when a matrix value is that dir or name and the run uses it with `-w`, or when an `upload-artifact` path is under `packages/<dir>/` (`codeBuilderE2E.yml` → `salesforcedx-vscode-core`). Record workflow `name` and every job key that file defines. Several workflows → several records.

Dependents, separate from the touched-package record. Shape `{ package, workflow, jobs, spec paths, excerpt }`. Spec paths plus a short excerpt (not the file). No full consumer spec text. No package-name allowlist. Two relations, two finders (one importer walk cannot serve both):

- Services. Not "any importer of `salesforcedx-vscode-services`". Extensions call `getServicesApi` (`packages/effect-ext-utils/src/extensionProvider.ts`) and `api.services.*` with no import of that package (`salesforcedx-vscode-visualforce` `extension.ts`; `salesforcedx-vscode-core` type-only import plus `api.services.ConnectionService` / `TargetOrgRef`). When the edit is inside the shared layer (`prebuiltServicesLayer` / `buildAllServicesLayer` in `packages/salesforcedx-vscode-services/src/index.ts`), dependents are workspace packages whose `src` merges `prebuiltServicesLayer` or `buildAllServicesLayer`. Otherwise dependents are workspace packages whose `src` calls `api.services.<changed service>` via `getServicesApi`. Jest `Layer.succeed` mocks are not that surface.
- Language servers. Packages: `salesforcedx-aura-language-server` (`@salesforce/salesforcedx-aura-language-server`), `salesforcedx-lwc-language-server` (`@salesforce/salesforcedx-lwc-language-server`), `salesforcedx-visualforce-language-server` (`@salesforce/salesforcedx-visualforce-language-server`). Dependent: workspace package whose `package.json` depends on that name (`salesforcedx-vscode-lightning`, `salesforcedx-vscode-lwc`, `salesforcedx-vscode-visualforce`). Not an import walk of the touched file. `@salesforce/apex-node` is not a language server.

Skill text: `git show origin/<base>:.cursor/skills/manual-test-plan-judgment/SKILL.md`. Base ref is the PR base branch, after `git fetch origin <base>`. Missing ref (file not on base until this PR merges): same soft fail as Cursor error. Do not hard-fail the job.

`Agent.prompt`: skill + facts JSON.

Validate with `Schema.parseJson`, then bind to facts:

- `watch-video` kept only when `spec` is a spec path in the facts, `workflow` is a workflow `name` in the facts, and `job` is a job key of that workflow in the facts.
- `checklist` with empty `items`, or items that all drop out, is a schema failure.
- Hallucinated spec path does not render.

Render:

- markers `<!-- manual-test-plan -->` … `<!-- /manual-test-plan -->`
- heading `## Manual test plan`
- `nothing` → `Nothing worth manually testing.`
- watch-video → `- [ ] Watch video: \`<spec>\` in \`<workflow>\` (\`<job>\`)`
- manual → `- [ ] <step>`

Markers present: replace that block. Markers absent: append it. Every other byte of the body stays.

Write back with `gh pr edit` and `GH_TOKEN` from `github.token`. Re-read the body immediately before the edit.

Cursor error, JSON that fails the schema, checklist that does not bind, or missing skill ref: log, exit 0, do not edit the body.

### 3. `ci: write manual test plan on PR open and push`

`.github/workflows/manual-test-plan.yml`

- `on.pull_request.types`: `opened`, `synchronize`.
- `concurrency`: `group: manual-test-plan-${{ github.event.pull_request.number }}`, `cancel-in-progress: false` (same serialization as `docOnlyAutoMerge.yml`).
- Secret check job sets `has_key` from `secrets.IDEE_CURSOR_API_KEY`. Body job `if: has_key == 'true'` so a missing key skips that job.
- Body job: checkout `github.event.pull_request.head.sha`, `fetch-depth: 0`. Setup Node like changelog-body. `npm ci` in `scripts/manualTestPlan`. Run `node scripts/manualTestPlan/manualTestPlan.mts` with `CURSOR_API_KEY`, `GH_TOKEN: ${{ github.token }}`, PR number, base ref. No `IDEE_GH_TOKEN` on this job.
- `permissions`: `contents: read`, `pull-requests: write`.
- Workflow stays off required status checks.
