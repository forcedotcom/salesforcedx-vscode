# W-23290267 — Suppress `_OTELRESOURCE_` resource metric in Node trace exporter

## Context

- `@azure/monitor-opentelemetry-exporter` `AzureMonitorTraceExporter` emits `_OTELRESOURCE_` metric (server-renamed `_APPRESOURCEPREVIEW_`) once/span-export batch, sampleRate 100 (never sampled).
- App Insights: ~27.4M/24h, ~22% ingestion, counts vs 100GB cap. Pure noise for us.
- Source: `trace.js` ctor sets instance field `this.shouldCreateResourceMetric = shouldCreateResourceMetric()`; `export()` pushes `resourceMetricEnvelope` only when field true — gate at `node_modules/@azure/monitor-opentelemetry-exporter/dist/esm/export/trace.js:48` (`if (resourceMetricEnvelope && this.shouldCreateResourceMetric)`).
- Envelope identity: `data.baseData.metrics[0].name === '_OTELRESOURCE_'` (`node_modules/@azure/monitor-opentelemetry-exporter/dist/esm/utils/common.js:190`). Envelope is built by `createResourceMetricEnvelope(spans[0].resource, instrumentationKey)` and is **only non-undefined when the span resource has ≥1 non-SDK attribute** (common.js:187) — the test's fake span must carry a real resource attribute or the assertion is vacuous.
- `.d.ts:14` types it `private shouldCreateResourceMetric` (not readonly) — same shape as existing `sender` override (`private readonly sender`).
- No SDK config option. Env var `APPLICATIONINSIGHTS_OPENTELEMETRY_RESOURCE_METRIC_DISABLED` needs pre-ctor timing — reject.
- Node-only. Web path (`@vscode/extension-telemetry`) unaffected. customEvents path uses log exporter, not this trace exporter — unaffected.
- Target: `FilteredAzureMonitorTraceExporter` ctor, `packages/salesforcedx-vscode-services/src/observability/spansNode.ts:29`. Class is not currently exported.
- No existing unit test targets this class. Existing observability jest tests: `packages/salesforcedx-vscode-services/test/jest/observability/*.test.ts` (model `otlpFileLogExporterNode.test.ts`).

## Phases

### Phase 1 — disable resource metric in ctor + export class for test

- `spansNode.ts`: `export` the `FilteredAzureMonitorTraceExporter` class (needed so the jest test can construct it directly; class stays a module-internal concern otherwise).
- In the ctor, after `super(options)`, add:
  ```ts
  // @ts-expect-error -- `shouldCreateResourceMetric` is a private SDK field; suppresses the never-sampled _OTELRESOURCE_/_APPRESOURCEPREVIEW_ metric (~22% AI ingestion).
  this.shouldCreateResourceMetric = false;
  ```
- Place before `localIngestionEndpoint` block; unconditional (applies prod + local).
- Terse comment matching existing `sender`-override style (spansNode.ts:37).

### Phase 2 — jest unit test proving runtime suppression

New `packages/salesforcedx-vscode-services/test/jest/observability/spansNode.test.ts`:

- Import `FilteredAzureMonitorTraceExporter` from `../../../src/observability/spansNode`.
- `makeSpan`: fake `ReadableSpan` that (a) survives `isSpanValidForProductionTelemetry` — top-level (`parentSpanContext: undefined`), no `telemetryIgnore` — else `export()` filters it out and `spans.length` is 0, emitting nothing (false pass); (b) carries `resource: { attributes: { 'extension.name': 'x' } }` so `createResourceMetricEnvelope` returns a real envelope.
- Inject a fake sender matching `LocalEnvelopeSender` shape (`{ exportEnvelopes: jest.fn().mockResolvedValue({ code: ExportResultCode.SUCCESS }), shutdown: () => Promise.resolve() }`). Assign to the private `sender` after construction (`(exporter as unknown as { sender: LocalEnvelopeSender }).sender = fake`) — mirrors the existing `sender`-override mechanism in the ctor. Do not route through `localIngestionEndpoint` (that builds a real network sender).
- Construct with a valid connection string (`DEFAULT_AI_CONNECTION_STRING` from `./appInsights`) so `instrumentationKey` is set and the SDK actually builds envelopes.
- Test A (the fix): `await export([span], cb)`; assert `exportEnvelopes` called once and **no** envelope in the batch has `data.baseData.metrics?.[0]?.name === '_OTELRESOURCE_'`; assert ≥1 span envelope present (proves suppression didn't just drop everything).
- Test B (control, guards against a vacuous Test A): construct a plain `new AzureMonitorTraceExporter(...)` with the same fake sender + same span, `export`, assert an `_OTELRESOURCE_` envelope **is** present. Pins assertion to real SDK behavior — future SDK rename/removal fails Test B loudly, not a silent Test A pass.
- `shutdown()` test: resolves.
