# W-23530668: Modal destructive confirmations

## Context

Use VS Code modal confirmation for destructive delete-source and retrieve-overwrite decisions so the operation cannot proceed without an explicit confirmation. Org Browser retrieve overwrite already uses `PromptService.confirmOrThrow`; delete source still uses a non-modal information message with explicit confirm and cancel buttons.

## Phases

### 1. Route delete-source confirmation through the shared modal prompt

Commit: `fix: use modal confirmation for delete source`

- Update `packages/salesforcedx-vscode-metadata/src/commands/deleteSourcePath.ts` to call `PromptService.confirmOrThrow` with the existing delete warning and confirm label.
- Remove the explicit cancel label because VS Code supplies cancellation for modal messages.
- Remove the unused `cancel_delete_source_button_text` entries from:
  - `packages/salesforcedx-vscode-metadata/src/messages/i18n.ts`
  - `packages/salesforcedx-vscode-metadata/src/messages/i18n.ja.ts`
- Keep `packages/salesforcedx-vscode-org-browser/src/commands/retrieveMetadata.ts` on the existing `PromptService.confirmOrThrow` path; do not add a second modal implementation.

### 2. Exercise delete-source through the modal dialog

Commit: `test: confirm delete source through modal dialogs`

- Update modal selection and confirmation in:
  - `packages/salesforcedx-vscode-metadata/test/playwright/specs/deleteSource.headless.spec.ts`
  - `packages/salesforcedx-vscode-metadata/test/playwright/specs/deleteBundleSource.headless.spec.ts`
  - `packages/salesforcedx-vscode-metadata/test/playwright/specs/nonTrackingOrgDeployRetrieveOperations.headless.spec.ts`
- Assert the existing warning text is displayed in the VS Code modal and confirm with the existing `Delete Source` label.
