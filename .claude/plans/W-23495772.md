# W-23495772: Remove Lightning core extension dependency

## Context

- `packages/salesforcedx-vscode-lightning/package.json` declares both core and services in `extensionDependencies`.
- Lightning source has no core API import, core extension lookup, or core package dependency.
- Lightning source obtains its runtime API from the services extension through `ExtensionProviderService.getServicesApi`.
- Desktop Playwright fixtures explicitly install core for Aura and legacy telemetry coverage; the desktop Wireit target packages core for those fixtures rather than for Lightning activation.
- `package-lock.json` records no Lightning dependency on the core workspace package, so the manifest-only edit needs no lockfile update.
- The Apex precedent in `plans/W-23348778.md` retains services while removing core from `extensionDependencies`.

## Approach

Remove only the unused core extension dependency declaration. Retain the services dependency and explicit core test infrastructure; no source, test, Wireit, or lockfile changes are needed.

## Phases

1. **Manifest update**
   - Remove `salesforce.salesforcedx-vscode-core` from `packages/salesforcedx-vscode-lightning/package.json` `extensionDependencies`.
   - Keep `salesforce.salesforcedx-vscode-services` and all desktop-test references to core unchanged.

2. **Post-implementation verification**
   - Confirm Lightning's `extensionDependencies` contains only `salesforce.salesforcedx-vscode-services`.
   - Confirm `packages/salesforcedx-vscode-lightning/src/**` has no core API import, core extension lookup, or core package reference.
   - Confirm existing Playwright fixture and Wireit references to core remain unchanged because they support explicit Aura and telemetry test setup rather than production activation.
   - Run `npm run compile -w salesforcedx-vscode-lightning`, `npm run lint -w salesforcedx-vscode-lightning`, `npm test -w salesforcedx-vscode-lightning`, `npm run vscode:bundle -w salesforcedx-vscode-lightning`, and `npm run vscode:package:legacy -w salesforcedx-vscode-lightning` from the repository root.
   - Run and pass repository readiness hooks covering compile, lint, Effect diagnostics, unit tests, VS Code bundle, and knip after implementation.
   - Do not add a separate Playwright run: Lightning is outside the verification skill's required Playwright package list, and the manifest edit leaves its explicit desktop-test installation of core intact.

## Skills

- `concise`: keep the tracked plan focused on executable work.
- `packageJson`: preserve repository extension-manifest conventions.
- `core-extension-api`: distinguish runtime core API consumption from a stale manifest declaration.
- `services-extension-consumption`: confirm the services extension remains Lightning's runtime API provider and dependency.
- `wireit`: preserve core packaging as explicit desktop-test setup rather than removing it with the production dependency.
- `verification`: use the repository readiness suite and package-specific verification rules.
