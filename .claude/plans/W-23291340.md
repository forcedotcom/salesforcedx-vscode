# W-23291340 — isCliInstalled to TerminalService, migrate debugger, drop core isCLIInstalled

## Context

- Consolidate CLI-installed check into services ext.
- Today: `isCLIInstalled` in `packages/salesforcedx-vscode-core/src/util/cliConfiguration.ts` runs `sfdx --version` via `execSync`. Exposed on core API (`src/index.ts` 58, 211), re-exported `util/index.ts`.
- Sole caller: apex-debugger `src/index.ts:266` — `salesforceCoreExtension.exports.isCLIInstalled()`.
- Behavior change `sfdx`→`sf` (intentional). No external consumers (verified org:forcedotcom + org:salesforcecli).
- Debugger already: depends on `salesforcedx-vscode-services`, `buildAllServicesLayer`, runs `activateEffect` via `getRuntime()` (`ManagedRuntime.make(AllServicesLayer)`). `TerminalService` in `prebuiltServicesDependencies` → available in that runtime.
- Access in-Effect: `(yield* ExtensionProviderService).getServicesApi` → `api.services.TerminalService`.
- `TerminalService` is defined `accessors: false` (`terminalService.ts:30`) — the Tag has NO method accessors. Every consumer resolves the instance first (`const terminalService = yield* api.services.TerminalService;` then `terminalService.simpleExec(...)`, e.g. orgOpen.ts:80, orgDelete.ts:56/95, orgCreate.ts:157). Migration must follow that pattern; `yield* api.services.TerminalService.isCliInstalled` would not compile.
