# W-23291340 — move sf-CLI check to apex-debugger, drop core isCLIInstalled

## Context

- Move the CLI-installed check out of core; the sole consumer (apex-debugger) composes it inline against services `TerminalService`.
- Was: `isCLIInstalled` in `packages/salesforcedx-vscode-core/src/util/cliConfiguration.ts` ran `sfdx --version` via `execSync`. Exposed on core API (`src/index.ts` 58, 211), re-exported `util/index.ts`.
- Sole caller: apex-debugger `src/index.ts:266` — `salesforceCoreExtension.exports.isCLIInstalled()`.
- Behavior change `sfdx`→`sf` (intentional). No external consumers (verified org:forcedotcom + org:salesforcecli).
- Debugger already: depends on `salesforcedx-vscode-services`, `buildAllServicesLayer`, runs `activateEffect` via `getRuntime()`. `TerminalService` available in that runtime.
- Access in-Effect: `(yield* ExtensionProviderService).getServicesApi` → `api.services.TerminalService`.
- `TerminalService` is `accessors: false` — resolve the instance first (`const terminalService = yield* api.services.TerminalService;` then `terminalService.simpleExec(...)`, e.g. orgOpen.ts:80, orgDelete.ts:56/95).

## Design decision — inline in debugger, NOT a TerminalService method

- An earlier revision added `isCliInstalled` to `TerminalService`. Reverted: single consumer + the catch-to-`false` semantics are the debugger's policy (CLI-absent → skip ISV setup), not a shared-terminal truth. `parse: () => true` also discards stdout — a presumptuous abstraction to bake into the shared seam.
- Final: `simpleExec` stays the only shared primitive. Debugger composes `simpleExec({ command: 'sf --version', parse: () => true }).pipe(catchTag('TerminalServiceError', () => false))` at the call site, where the policy lives.

## Phases

### Phase 1 — inline the check in apex-debugger (+ finish Effect migration of the touched block)

- `packages/salesforcedx-vscode-apex-debugger/src/index.ts`:
  - import `ExtensionProviderService` from `@salesforce/effect-ext-utils`.
  - in `activateEffect`:
    ```ts
    const api = yield* (yield* ExtensionProviderService).getServicesApi;
    const terminalService = yield* api.services.TerminalService;
    const isCliInstalled = yield* terminalService
      .simpleExec({ command: 'sf --version', parse: () => true })
      .pipe(Effect.catchTag('TerminalServiceError', () => Effect.succeed(false)));
    if (isCliInstalled) { ... }
    ```
  - bring the rest of the block to Effect idiom:
    - `console.log('Setting up ISV Debugger environment variables')` → `yield* Effect.log(...)`.
    - the bare `Effect.promise(async () => { try {...} catch { console.error; showWarningMessage } })` → `Effect.tryPromise` with `catch: e => new IsvAuthSetupError({ message: ... })` (new `Schema.TaggedError` in local `errors.ts`), then `Effect.catchTag('IsvAuthSetupError', e => Effect.log(e.message).pipe(Effect.zipRight(Effect.sync(() => vscode.window.showWarningMessage(nls.localize('isv_debug_config_environment_error'))))))` — non-fatal ISV setup failure → warn + log, don't fail the fiber.
    - `registerIsvAuthWatcher` / `setupGlobalDefaultUserIsvAuth` stay imperative; only the wrapping Effect changes.
  - drop `getActiveSalesforceCoreExtension` import/usage (was only for isCLIInstalled).

### E2E: scoped out

- apex-debugger has NO e2e infra (only `test/jest`; no CI workflow references it). First-ever playwright suite + ISV-configured scratch org for 1 boolean gate — disproportionate.
- User-visible surface is narrow/deterministic: the gate flips `sf:isv_debug_project` + logs during ISV setup. `sf`→`sfdx` only changes *which* binary answers "CLI present"; both ship together, so the boolean is unchanged on any supported install.
- Manual-QA checklist (run before merge, record in PR):
  - install built VSIXs; open a project with `isvDebuggerSid`/`isvDebuggerUrl` config → "Setting up ISV Debugger environment variables" logs and `sf:isv_debug_project` becomes true.

  - temporarily rename `sf` off PATH → gate goes false (setup skipped), no crash.
