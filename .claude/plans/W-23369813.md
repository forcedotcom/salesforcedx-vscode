# W-23369813 — Route doc-output phases (ADR/CONTEXT) through doc-format rules

## Context

- auto-build-wi treats every WI as code-shaped. Docs WI (e.g. ADR) → code planner specs doc prose into plan → builder transcribes verbatim → bloated ADR (call-site line#s, allowlist internals, downstream constraints). Ref PR #7694.
- Root cause: routing per-WI, but doc-format obligation is per-artifact. Any output under `docs/adr/**` (incl. `packages/*/docs/adr/**`) or matching `**/CONTEXT.md` / `**/CONTEXT-MAP.md` must obey ADR-FORMAT.md / CONTEXT-FORMAT.md, independent of code in same WI.
- Format files: `.claude/skills/grill-me/ADR-FORMAT.md` (1-3 sentences core, optional sections only when earned), `.claude/skills/grill-me/CONTEXT-FORMAT.md`.
- Seams:
  - Authoring: `planPrompt` + `buildPrompt` in `.claude/workflows/auto-build-wi.js`. Mirror existing concise-skill injection (planPrompt line ~888).
  - Review: `.claude/workflows/review-diff.js` (doc content altitude), `.claude/workflows/review-plan.js` (plan pre-specs doc prose). Keep auto-build-wi.js orchestration-only — no doc-detection there beyond prompt text.
- Precedent (binding): sibling WI W-23278637 added the ADR-consistency / ADR-violation checks by **appending instructions to the existing `adversaryPlanReviewPrompt` and `thermoPrompt` strings** — no new agent, no new schema, no `parallel()` reshaping. W-23278637.md:35 — "Prefer appending to `thermoPrompt` over a new agent (keeps fan-out count, reuses verify pass)." This WI extends those same two operators with a doc-altitude check, gated in-prompt by doc-glob detection, exactly as the ADR checks are gated in-prompt by "packages the diff/plan touches". No new sibling agent, no new schema, no parallel-array widening.
- Out of scope: refactor format files out of grill-me; grill-me itself; fixing merged ADRs.

## Phases

### Phase 1 — Authoring seam in auto-build-wi.js

`chore(auto-build-wi): route doc-output phases through doc-format rules - W-23369813`

- `planPrompt`: add rule (near step 2, mirror concise injection) — for any phase whose output path matches `docs/adr/**` / `packages/*/docs/adr/**` / `**/CONTEXT.md` / `**/CONTEXT-MAP.md`: plan phase states intent + target path + format-file ref only. Do NOT pre-spec doc prose into the plan.
- `buildPrompt`: add rule — before writing any doc-glob output, Read matching format file (`.claude/skills/grill-me/ADR-FORMAT.md` or `CONTEXT-FORMAT.md`) and obey it (1-3 sentences core; sections only when earned; downstream-WI detail belongs in downstream WIs).
- Prompt text only — no code/orchestration change.
- Files: `.claude/workflows/auto-build-wi.js`

### Phase 2 — Doc-altitude check appended to `thermoPrompt` (review-diff.js)

`feat(review-diff): flag over-altitude ADR/CONTEXT doc output - W-23369813`

- **Append** a doc-altitude paragraph to the existing `thermoPrompt` string (review-diff.js:245-249), directly after the ADR-violation check — same in-prompt structure the W-23278637 ADR check used. No new agent, no new schema, no `parallel()` change.
- Text: for any diff file matching `docs/adr/` / `packages/*/docs/adr/` / `CONTEXT.md` / `CONTEXT-MAP.md`, Read the matching format file (`ADR-FORMAT.md` / `CONTEXT-FORMAT.md`) and flag doc hunks that exceed the format's altitude — over-detailed core, downstream-WI material, sections filled without a real trade-off. If the diff touches no doc-glob file, this check produces nothing (in-prompt no-op — the agent simply finds no matching files, exactly like the ADR check when no ADRs are touched).
- Findings are `THERMO_SCHEMA`-shaped like every other thermo finding; the `evidence` MUST embed a `file:line` citation into the over-altitude doc hunk (mirrors thermo's existing file:line rule) so it is checkable in the verify pass.
- Verifier (`verifyFindingPrompt`): **no change.** Altitude is a style/architecture judgment; the verifier already keeps style/architecture findings by default ("it's only style or architecture" is never a drop → KEEP). A doc-altitude finding with a valid file:line citation is confirmed unless its premise is factually disproven (cited hunk doesn't exist / doesn't say what the finding claims) under the existing generic "Premise false" rule. No doc-specific drop rule is needed or wanted (adding one would only create a new way to silence the finding).
- Findings flow through the unchanged `rawFindings` → verify → fix pipeline.
- Files: `.claude/workflows/review-diff.js`
