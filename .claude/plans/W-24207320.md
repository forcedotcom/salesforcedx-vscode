# W-24207320

1.1 Add SettingsService.inspect and migrate remaining inspect callers

## Context

`SettingsService` (`packages/salesforcedx-vscode-services/src/vscode/settingsService.ts`) wraps `WorkspaceConfiguration.get` / `update` (`getValue`, `setValue`) in `Effect.fn` + `Effect.try` → `SettingsError`. No `inspect`.

Remaining `WorkspaceConfiguration.inspect` callers:

- `packages/salesforcedx-vscode-services/src/vscode/notificationModeService.ts` — `getInternalMode` (`:93` command section, `:99` extension section). Global fallback (`:106`) is `.get`, not inspect.
- `packages/salesforcedx-vscode-core/src/metadataSupport/metadataXmlSupport.ts` — local `inspectXmlConfiguration` (`:137-146`) on section `xml`. Same function already uses `api.services.SettingsService` `getValue` / `setValue`. Failures are `XmlConfigurationInspectError`; `MissingSettingsError` is already in `catchTags` (`:180`).

## Phases

### 1. `feat: add SettingsService.inspect`

`packages/salesforcedx-vscode-services/src/vscode/settingsService.ts`

- `inspect<T>(section, key)` beside `getValue`. `Effect.fn('SettingsService.inspect')`. `Effect.try` → `vscode.workspace.getConfiguration(section).inspect<T>(key)`.
- `SettingsError` same fields as `getValue` (`cause`, `section`, `key`, `message`). Return type = `ReturnType<vscode.WorkspaceConfiguration['inspect']>` (object or `undefined`). No default arg.
- Export on the service object. Class already on the services API (`src/index.ts` `SettingsService: typeof SettingsService`). No index change.

`packages/salesforcedx-vscode-services/test/jest/vscode/settingsService.test.ts`

- Success: mock `getConfiguration` `inspect`, `Effect.provide(SettingsService.Default)`, assert returned scopes.
- Throw from `inspect` → `SettingsError` (`MissingSettingsError`).

### 2. `refactor: read configuration inspect through SettingsService`

`metadataXmlSupport.ts`

- Replace `inspectXmlConfiguration` with `settingsService.inspect`.
- Delete `XmlConfigurationInspectError` and its `catchTags` arm. Inspect failures are `SettingsError`; existing `MissingSettingsError: reportSetupFailure` covers them.
- Keep `shouldSetSchemaDocumentationTypeToNone` / `ensureMinXmlHeap` and the `getValue` / `setValue` calls.

`packages/salesforcedx-vscode-core/test/jest/metadataSupport/metadataXmlSupport.test.ts`

- Stub is `new SettingsService({ getValue, setValue })` (`:86`). Add `inspect` returning `Effect.succeed` of the objects `makeXmlConfig` builds today.
- Drop the `vscode.workspace.getConfiguration` spy (`:70-73`) once nothing reads it.

`notificationModeService.ts`

- `getInternalMode` → `Effect.fn` that `yield*` `SettingsService.inspect` for the 2 inspect reads. Precedence unchanged: folder → workspace → global, then extension, then existing global `.get`.
- `showSuccessNotification` / `getProgressLocation` `yield*` that effect.
- `dependencies: [SettingsService.Default]` on `NotificationModeService`.

`packages/salesforcedx-vscode-services/test/jest/notificationModeService.test.ts`

- `getInternalMode` cases: `Effect.runPromise` + `Effect.provide(SettingsService.Default)`. Existing `getConfiguration` mocks stay (Default calls `vscode.workspace`).
- `NotificationModeService` cases: same, so `Default` can build with `SettingsService.Default`.
