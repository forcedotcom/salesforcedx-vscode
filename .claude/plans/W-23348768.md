# W-23348768: Migrate Apex telemetry to Effect spans; drop core TelemetryService

## Context

- Per ADR-0002 (`packages/salesforcedx-vscode-apex/docs/adr/0002-telemetry-to-effect-spans.md`) + root ADR-0012 (spans-only).
- Retire core `TelemetryService` event API in `salesforcedx-vscode-apex`; emit Effect spans instead.
- Prior closed PR #7727 = full reference impl (branch abandoned). Reimplement on this branch.
- Production telemetry = span attrs only (top-level/command spans export). `Effect.logDebug` = local-debug, NOT event replacement.
- Call sites (all in `salesforcedx-vscode-apex/src`):
  - `index.ts:61` `TelemetryService.getInstance` fetch + `initializeService` + `setTelemetryService`
  - `index.ts:117` deactivation `sendExtensionDeactivationEvent`
  - `languageServer.ts:105` `sendEventData('apexLSPSettings',...)`
  - `languageServer.ts:134` `sendException(LSP_ERR,...)`
  - `languageServer.ts:156` `sendEventData('apexLSPLog',...)` (high-volume, allowlist-gated)
  - `languageUtils/index.ts:20,23` `apexTestDiscoveryStart/End`
  - `languageUtils/languageClientManager.ts:149` `apexLSPRestart`; `:325` `apexLSPStartup`
  - `telemetry/telemetry.ts` holder (`get/setTelemetryService`) — delete
- Event→span map:
  - `apexLSPSettings` → `apex.lsp.settings` (fireSpan, attr `maxHeapSize`)
  - `LSP_ERR` → root span `LSP_ERR`, `Effect.fail` for ERROR status + `error` attr
  - `apexLSPLog` → attrs onto single long-lived `apex.lsp.client` root span (NOT N spans; allowlist stays at `onTelemetry` boundary)
  - `apexTestDiscoveryStart/End` → 1 root span `apex.test.discovery` (attrs source/numClasses/numMethods/durationMs)
  - `apexLSPRestart` → `apex.lsp.restart` (fireSpan)
  - `apexLSPStartup` → `apex.lsp.startup` (fireSpan)
  - deactivation event → `apex.deactivation` root span

## Phases

### Phase 1: fireSpan helper + runtime dispose
- New `src/services/fireSpan.ts`: `fireSpan(name, attributes)` → `getRuntime().runFork(Effect.void.pipe(Effect.withSpan(name,{attributes,root:true})))`.
- `src/services/runtime.ts`: add `disposeRuntime()` — `await _apexRuntime?.dispose(); _apexRuntime=undefined`. `ManagedRuntime.dispose` closes the runtime's internal scope, which runs the NodeSdk finalizer (`forceFlush().then(shutdown)`, verified `node_modules/@effect/opentelemetry/dist/esm/NodeSdk.js:21`) so ended spans export instead of being lost to the BatchSpanProcessor UNREF'd timer when the window reloads.
- Why apex needs this (repo-wide gap, NOT apex-unique): every Effect extension holding a `ManagedRuntime`+NodeSdk layer that never disposes (apex-log `deactivate` closes only the extension scope — `src/index.ts:53`; org-browser/metadata/apex-oas same) can drop un-flushed spans on deactivate/reload. Apex fixes it here because its deactivation span + long-lived `apex.lsp.client` span (Phase 2) must flush on reload/restart to be observable. Filing the equivalent fix for the other extensions is out of scope for this WI — call it out as a follow-up, not a silent partial patch. (No other `index.ts` in the repo has a bespoke `disposeRuntime` today; this is the first.)
- Files: `src/services/fireSpan.ts`, `src/services/runtime.ts`
- Commit: `refactor(apex): add fireSpan helper + runtime dispose for span export - W-23348768`

### Phase 2: languageServer.ts span conversions
- Drop `getTelemetryService` import + `const telemetryService=` in `createServer`/`createLanguageServer`.
- `apexLSPSettings` → `fireSpan('apex.lsp.settings',{maxHeapSize: jvmMaxHeap ?? 0})`.
- `LSP_ERR` catch → `getRuntime().runFork(Effect.annotateCurrentSpan('error',String(err?.error??err)).pipe(Effect.zipRight(Effect.fail(err)),Effect.withSpan(LSP_ERR,{root:true})))` (fail ⇒ ERROR status/severity 17); keep `showErrorMessage`+`throw`.
- `apexLSPLog` → single long-lived `apex.lsp.client` root span per client lifetime, state held in a module-level `Ref<Option<{scope; span}>>` (NOT a bare `let` — use the Effect primitive for mutable shared state per anti-patterns.md "FORBIDDEN: Mutable State Without Ref"):
  - `src/languageServer.ts` module scope: `const clientSpanRef = Effect.runSync(Ref.make(Option.none<{ scope: Scope.CloseableScope; span: Tracer.Span }>()))`. This mirrors the sanctioned singleton idiom already in the codebase (`apex-log/src/services/apexLogState.ts:37-41` — `??= Effect.runSync(Ref.make(...))`). No module `let`, so the `functional/no-let` question is moot (and it's off for this pkg regardless — see Verification).
  - New `Effect.fn('apex.lsp.client.rotate')` run via `getRuntime().runPromise` in `createLanguageServer`: read `clientSpanRef`; if `Some`, `Scope.close(prev.scope, Exit.void)` (ends+flushes prior span on restart); `Scope.fork(yield* getExtensionScope(), ExecutionStrategy.sequential)` → child scope; `span = yield* Effect.makeSpanScoped('apex.lsp.client',{root:true}).pipe(Scope.extend(child))`; `Ref.set(clientSpanRef, Option.some({scope: child, span}))`.
  - `onTelemetry` (allowlist gate unchanged): run an `Effect.fn` that reads `clientSpanRef` and `Option.match` — `onSome: ({span}) => Effect.sync(() => Object.entries({...properties,...measures}).forEach(([k,v]) => span.attribute(k,v)))`, `onNone: Effect.void`. Avoids the raw closure-captured mutable var; the span is fetched from the Ref inside the effect.
  - Note: `makeSpanScoped`/`Scope.fork` long-lived-span pattern is new to this repo (grep confirms no prior use) — cover it in Phase 5 jest (recording tracer asserts exactly one `apex.lsp.client` span, attrs land) AND Phase 6 e2e (restart → prior client span flushed with status/attrs, exactly 1 live).
- Imports: add `getExtensionScope` from effect-ext-utils; `ExecutionStrategy`, `Exit`, `Option`, `Ref`, `Scope`, `Tracer` from `effect/*`; `fireSpan`.
- Files: `src/languageServer.ts`
- Commit: `refactor(apex): convert languageServer telemetry to spans - W-23348768`

### Phase 3: languageUtils span conversions
- `languageUtils/index.ts`: replace `fetchFromLs` telemetry w/ `discoverFromLs = Effect.fn('apex.test.discovery',{root:true})` — `Clock.currentTimeMillis` timing, `Effect.tryPromise` getApexTests, `annotateCurrentSpan({source:'ls',...buildMeasuresFromTests})`; `fetchFromLs = async () => getRuntime().runPromise(discoverFromLs())`. Drop telemetry import.
- e2e reachability of `apex.test.discovery` (why it's jest-only, Phase 5, not e2e): the LS discovery path (`fetchFromLs`→`languageClientManager.getApexTests`) has NO reachable trigger in-repo — grep confirms zero callers of the apex extension's exported `getApexTests` LS API (`packages/*/src`), no command wired to it, and the ls/api discovery-source setting from #6653 is no longer contributed (only orphan i18n strings remain in apex-testing/messages/i18n.ts:52-54). apex-testing's Test Explorer drives its OWN API-based discovery (`ApexTestDiscoveryService`, span `apex-test-discovery`, separate extension+runtime) — it does not route through the apex extension. So the advocate's assumption that testExplorer.headless.spec triggers `apex.test.discovery` is incorrect; there is no e2e path to assert. Unit coverage (recording tracer) is the correct and sufficient tier here.
- `languageClientManager.ts`: `sendRestartTelemetry` → `fireSpan('apex.lsp.restart',{...})`; startup → `fireSpan('apex.lsp.startup',{activationTime:startTime})`. Drop telemetry import + `const telemetryService=`. Add `fireSpan` import.
- Files: `src/languageUtils/index.ts`, `src/languageUtils/languageClientManager.ts`
- Commit: `refactor(apex): convert languageUtils telemetry to spans - W-23348768`

### Phase 4: drop TelemetryService fetch + deactivation span; delete holder
- `index.ts`: remove telemetry block (`getInstance`, `initializeService`, `setTelemetryService`, `TelemetryUnavailableError`, `Schema`/`ExtensionPackageJson*` imports).
- `deactivate`: `deactivation = Effect.fn('apex.deactivation',{root:true})` — `Effect.tryPromise(()=>getClientInstance()?.stop(30_000)??Promise.resolve()).pipe(Effect.ensuring(disposeOutputChannel then closeExtensionScope()),Effect.ignore)`; then `await getRuntime().runPromise(deactivation()); await disposeRuntime()`.
  - Ordering is correct and load-bearing: `runPromise(deactivation())` fully awaits — including `closeExtensionScope()` (which ends the `apex.lsp.client` span via its parent extension scope) and the `apex.deactivation` root span ending — BEFORE `disposeRuntime()` tears down the same runtime. `disposeRuntime` closes the runtime scope, firing the NodeSdk finalizer (forceFlush→shutdown) that exports every span ended above. Closing the extension scope must happen inside the still-live runtime (it does, via `runPromise`), so no use-after-dispose.
- Delete `src/telemetry/telemetry.ts`.
- Import `disposeRuntime`.
- Files: `src/index.ts`, delete `src/telemetry/telemetry.ts`
- Commit: `refactor(apex): drop core TelemetryService, span deactivation - W-23348768`
