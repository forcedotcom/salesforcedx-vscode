# W-24293101

## Context

- Typed ESLint rule: methods of an `Effect.Service` must not return `Promise`.
- Why: `.claude/skills/effect-best-practices/references/service-patterns.md` — "Services should return `Effect` types, never `Promise`" (`async (): Promise<…>` is the banned shape; `Effect.fn` is the allowed shape).
- Service methods in this repo are the functions on the object returned from the `effect` callback. Example: `WorkspaceService` returns `{ getWorkspaceInfo, getWorkspaceInfoOrThrow }` from `Effect.gen` inside `class WorkspaceService extends Effect.Service<WorkspaceService>()(…)`.
- Type-aware (`getParserServices`, same as `noNestedEffectTernary`): flag when the checker return type is `Promise`, including `async` and inferred `Promise`. `Effect` / `Effect.fn` returns stay clean.
- Class detection: `extends Effect.Service<…>()(…)`, same `Effect.Service` call shape as `isEffectServiceCall` in `packages/eslint-local-rules/src/noEffectServiceAccessorCalls.ts`.
