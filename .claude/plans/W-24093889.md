# W-24093889: Spike undeclared dependencies and `INIT_CWD` under pnpm

## Context

- The repository is an npm workspace with `package-lock.json`, npm-oriented root scripts, and npm settings in `.npmrc`.
- `scripts/require-root-install.js` permits installation only when npm's `INIT_CWD` equals the repository root.
- Evaluate pnpm directly: use its default strict dependency resolution to expose package imports missing from the consuming package's manifest, and use observed pnpm lifecycle values to preserve the root-only install guard.
- One approach: convert the checkout to a standard pnpm workspace, fix only dependency declarations and root-install behavior proven incompatible by install/build verification, and keep pnpm's strict resolution. No hoisting compatibility mode.

## Phases

### 1. Establish the pnpm workspace

**Commit:** `build: configure pnpm workspace`

- Add `pnpm-workspace.yaml` for `packages/*`.
- Update root `package.json` package-manager metadata and npm-specific workspace commands to pnpm equivalents without changing their intent.
- Update `.npmrc` only where an existing npm setting needs a pnpm equivalent.
- Generate `pnpm-lock.yaml`; remove `package-lock.json` after a successful root install.

### 2. Declare dependencies required by each workspace

**Commit:** `fix: declare dependencies exposed by pnpm`

- Run the existing compile, lint, test, Knip, and packaging paths with pnpm's default dependency isolation.
- Declare each dependency in the `packages/*/package.json` that imports or executes it.
- Adapt package build, test, and packaging configuration only where a failing pnpm verification path proves pnpm's virtual-store layout or lifecycle behavior requires it. This includes Jest transform exclusions, esbuild module resolution, and legacy package lifecycle commands.
- Regenerate `pnpm-lock.yaml` from those manifest changes.

### 3. Preserve root-only installation under pnpm

**Commit:** `fix: enforce root installs under pnpm`

- Update `scripts/require-root-install.js` from pnpm's observed lifecycle environment so a root invocation succeeds and an invocation from a package directory fails.
- Update the root `package.json` lifecycle wiring only if the pnpm probe shows it is required.
- Keep the error specific to the supported root-level pnpm command.

### 4. Cut CI and release automation over to pnpm

**Commit:** `build: run repository automation with pnpm`

- Set up pnpm and pnpm-store caching before repository installs in shared GitHub actions and workflows; install with `pnpm install --frozen-lockfile`.
- Translate repository scripts and workspace-targeted commands to `pnpm` and `pnpm --filter` while leaving external consumers' package-manager commands unchanged.
- Update release/version scripts and workflows to regenerate and stage `pnpm-lock.yaml`, never `package-lock.json`.
- Update worktree setup to install from `pnpm-lock.yaml`.

## Skills to apply

- `packageJson`: package-manager metadata, scripts, workspace manifests, dependency placement.
- `wireit`: preserve existing task graph behavior while changing command invocations.
- `verification`: install and run repository checks before claiming pnpm compatibility.

## Verification

- Clean checkout: `pnpm install` at the repository root succeeds and reproduces an unchanged `pnpm-lock.yaml`.
- Package directory: `pnpm install` fails through `scripts/require-root-install.js` with the root-install instruction.
- `pnpm compile`
- `pnpm lint`
- `pnpm test`
- `pnpm check:knip`
- `pnpm vscode:package`
- Search build output for module-resolution failures; every fix maps to a dependency declaration in the consuming workspace's `package.json`.
- Confirm no npm lockfile remains and no pnpm hoisting option was added.
- Validate GitHub Actions syntax and representative Linux, Windows, E2E, stable-release, patch-release, and npm-package-publish workflows.
