# W-23506239: Use `Effect.filterOrFail` for org-delete guards

## Scope

- `packages/salesforcedx-vscode-org/src/commands/orgDelete.ts` only
- Existing Jest coverage in `packages/salesforcedx-vscode-org/test/jest/commands/orgDelete.test.ts` already exercises both rejected guards and their ordering; no test edit planned
- Preserve existing errors, messages, confirmation order, command selection, cancellation, channel output, sequential deletion, and state refresh
- No `orgDisplay.ts` work; its former guards no longer exist

## Skills

- `effect-best-practices`: compose both validations with `Effect.filterOrFail`; retain typed `Schema.TaggedError` failures
- `typescript`: keep the refactor minimal, immutable, and type-driven
- `verification`: rely on repository readiness hooks, then run focused package checks not covered by them
- `playwright-e2e`: run the required org desktop suite without retries

## Phases

### 1. Default-org validation

- Pipe `SubscriptionRef.get(TargetOrgRef)` through `Effect.filterOrFail` and yield the validated snapshot.
- Accept snapshots where `isScratch === true || isSandbox === true`.
- Lazily construct the existing `OrgNotDeletableError` with `org_delete_default_not_deletable` on rejection.
- Keep confirmation before snapshot validation and leave subcommand selection, target-org flag construction, execution, output, and refresh unchanged.

### 2. Aggregate delete validation

- After partition output, channel writes, channel display, and unconditional `updateConfigAndStateAggregators`, lift `failed` into the Effect pipeline and apply `Effect.filterOrFail(failures => failures.length === 0, ...)`.
- Lazily construct the existing `OrgDeleteFailedError` for a non-empty collection using `org_delete_failed_summary` and the rejected collection's same comma-separated username list.
- Keep `Effect.partition(..., { concurrency: 1 })` and the whole-loop cancellable progress wrapper unchanged so typed delete failures accumulate while interruption still aborts.
