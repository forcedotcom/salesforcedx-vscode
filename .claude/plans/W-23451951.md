# W-23451951: Rebuild Core WorkspaceContext as Services Facade

## Contract

- Preserve `WorkspaceContext.getInstance(forceNew?)`, `initialize(context)`, `getConnection()`, `onOrgChange`, `username`, `alias`, and `orgId` signatures.
- Preserve synchronous getter reads through a module-level Effect `MutableRef`; no bare mutable variables.
- Treat `TargetOrgRef.changes` element 0 as cache initialization, not an org change. Fire `onOrgChange` and refresh telemetry only for later distinct `{ username, alias, orgId }` snapshots.
- Preserve legacy missing values as `undefined`. A services connection failure does not create the util's historical `orgId: ''` sentinel because `TargetOrgRef` retains no failed identity; cover this intentional normalization in tests.
- Preserve `workspaceContextUtils.getOrgShape` until external consumers, including the shipping Einstein branch, migrate. This work removes only Core's shape-change handler and its util writes; deleting the public wrapper is separate contract work.

## Phase 1: Target-Org Adapter

- In `packages/salesforcedx-vscode-core/src/context/workspaceContext.ts`, define the cached identity shape from the services `DefaultOrgInfoSchema` fields and initialize a module-level `MutableRef` with absent identity values.
- Replace `WorkspaceContextUtil` construction/initialization with one extension-scoped `TargetOrgRef.changes` subscription started by `initialize` after Core's services runtime exists; close Core's extension scope from `deactivate` so the watcher cannot survive extension shutdown.
- In that subscription, map each snapshot to legacy identity: `username`, configured `alias`, and `orgId`; update the `MutableRef` for every distinct identity, including element 0.
- Preserve configured-alias semantics by having the services connection refresh compare `ConfigService.getTargetOrg()` with the resolved username and write `TargetOrgRef.alias` only when the configured value differs; do not infer the legacy getter/event alias from arbitrary `aliases` order.
- From the same subscription, drop element 0 before firing a private `vscode.EventEmitter<OrgUserInfo>` and invoking `refreshAllExtensionReporters`. Register the emitter with the initializing extension context and fork the stream into `getExtensionScope()` for lifecycle cleanup.
- Keep initialization idempotent and retain Core-context gating for telemetry. Let stream/setup failures reject initialization rather than creating a second watcher or fallback path.

## Phase 2: Pure Facade Cleanup

- Make `username`, `alias`, and `orgId` read synchronously from the `MutableRef`.
- Keep `getConnection()` delegated unchanged through `ConnectionService` and the Core runtime.
- Remove `handleOrgShapeChange`, `getDevHubId`, and all Core reads/writes of `WorkspaceContextUtil`.
- Remove the now-dead internal shape handler tests. Keep `workspaceOrgShape.ts`, its tests, `context/index.ts`, and `workspaceContextUtils.getOrgShape` because that top-level API has a known external consumer.
- Add focused Jest coverage for initial cache seeding without an event, one event per distinct switched identity, duplicate suppression, getter updates before listener notification, configured-alias parity, no-org values, idempotent initialization, telemetry refresh on post-initial changes only, and unchanged connection delegation.

## Phase 3: Desktop Contract Test

- Add `packages/salesforcedx-vscode-core/test/playwright/specs/workspaceContextOrgSwitch.desktop.spec.ts` using the Core desktop fixture and minimal org. Extend the fixture/package test dependencies to load and build `salesforcedx-vscode-org`, which owns `sf.set.default.org` and the org-picker UI.
- Add the smallest development-only VS Code command seam needed to subscribe to Core's exported `WorkspaceContext`, capture event payload/count plus synchronous getters, and write that state to a workspace JSON artifact Playwright can poll. Register it only when `extensionContext.extensionMode === vscode.ExtensionMode.Development`; keep it out of the returned API and production VSIX behavior, and use a targeted lint suppression with rationale if the repository command-registration rule requires a contributed command.
- Switch `target-org` from the initial alias to the authenticated username, then back to the alias through the existing org-picker UI so `ConfigService.setTargetOrg` and `ConnectionService.getConnection` drive the real `TargetOrgRef` path.
- Assert no activation event, exactly 1 event for each switch, event `{ username, alias }` parity, and synchronous `username`/`alias`/`orgId` parity after each switch. Use status-bar/state polling rather than timeouts or swallowed rejections.
