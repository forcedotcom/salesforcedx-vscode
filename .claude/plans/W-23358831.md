# W-23358831 — Adopt Predicate.isString across effect packages

## Context

- Replace `typeof x === 'string'` w/ effect `Predicate.isString` in pkgs already importing `effect`.
- Also negations `typeof x !== 'string'` → `!isString(x)` in same pkgs.
- Convert typed guards `(id): id is string => typeof id === 'string' && id.length > 0` → `isString(id) && id.length > 0` (isString is a `x is string` refinement; `&&` narrows, keep explicit annotation where TS needs it).
- Repo import convention = named subpath import, e.g. `import { isString } from 'effect/Predicate'` (matches existing `import { isError } from 'effect/Predicate'`). NOT namespace `Predicate.isString`. Call site: `isString(x)`.
- Scope = 15 effect pkgs, ~44 positive hits + relevant negations. Non-effect pkgs (salesforcedx-apex-debugger, i18n, eslint-local-rules) out of scope.
- One PR, multi commit (per pkg group).

Hit counts (positive `=== 'string'`, non-test src):
- services 23 (fsService 9, spanTransformProcessor 3, fileSystemProvider 2, connectionService 2, +7 singles)
- core 6, apex-testing 6, lwc 4, lightning-lsp-common 4
- metadata 3, apex 3, org-browser 2, apex-oas 2, utils-vscode 2
- soql/apex-replay-debugger/apex-log/apex-debugger/effect-ext-utils 1 each

Feeds `validIds`; the empty-check `if (validIds.length === 0) return new Map()`, `cacheKey`, and PACKAGE2_MEMBER batching all depend on it. Dropping `length > 0` would admit `''`/non-string apexClassIds into cache lookup + query.

Dropping `length > 0` would emit empty `''` into the SOQL IN clause.
  - Post-swap: diff each line individually, confirm both retain the `&& id.length > 0` conjunct — not just that the file type-checks (a dropped conjunct on the plain filter still compiles).
