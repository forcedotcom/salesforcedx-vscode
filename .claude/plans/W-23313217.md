# W-23313217 — Promote effect ESM esbuild override to shared bundling config

## Context

- WI 2-15 done: all 15 node consumers opt into `effectEsmConditions` (`conditions: ['import','module','default']`) via per-package `...effectEsmConditions` spread.
- Override lives in shared opt-in constant `scripts/bundling/effect.mjs`, imported per-package.
- **Node** promotion criterion (ADR 0021) met: ≥3 opt-ins (all 15 opted in) + full bundle green → fold into `nodeConfig`, no behavior change (pure move).
- **Browser** side NOT covered by ADR 0021 criterion (node-builds-only scope). Only 1 browser build opted in: `org-browser` (`commonConfigBrowser`). Other 5 effect-in-graph packages (apex-log, apex-testing, lwc, metadata, services, soql) condition only node builds — browser builds never validated.
- Folding into `commonConfigBrowser` applies `conditions` to 6 browser bundles at 1/6 prior-validation — below node's ≥3 gate. `conditions` alters resolution for every dep — real blast radius (web/Web-Console-shipping, hard to reverse), not a pure move.
- Decision: record a **browser-specific promotion criterion** in ADR 0021 first (Phase 1, sequenced before any config change per work-item-sequencing), then fold only after the named per-package web e2e specs are green. Do not silently reuse node's node-scoped criterion for browser.
- Consumers (all `packages/*/esbuild.config.mjs`): apex, apex-debugger, apex-log, apex-oas, apex-replay-debugger, apex-testing, core, lightning, lwc, metadata, org, org-browser, services, soql, visualforce.
- visualforce LS build (`visualforceServer.js`) has literal `conditions` (no effect in graph, W-19480954) — becomes redundant once `nodeConfig` defaults it (LS build spreads `nodeConfig`).

## Phases

### Phase 1 — ADR: add browser-specific promotion criterion (docs-only, sequenced first)

- `docs/adr/0021-*.md`: add a **browser** promotion criterion distinct from the node one. State: browser side had 1 opt-in (`org-browser`); `conditions` alters resolution for every dep in each browser bundle (ships to web/Web-Console, hard to reverse). Criterion: fold into `commonConfigBrowser` only after the per-package web e2e specs (Phase 3 list) run green on branch for each newly-conditioned browser build. Records the trade-off (validation cost vs shipping velocity) per grill-me ADR-FORMAT.
- No config change in this phase.

commit: `docs(adr): browser promotion criterion for effect ESM conditions - W-23313217`

### Phase 2 — Promote node conditions, remove per-package node overrides

- `scripts/bundling/node.mjs`: add `conditions: ['import', 'module', 'default']` to `nodeConfig`.
- each `packages/*/esbuild.config.mjs` (15): drop `import { effectEsmConditions }` line + every node-build `...effectEsmConditions,` spread. org-browser: drop only the **node**-build spread (line 15); keep the browser-build spread (line 25) until Phase 3.
- `visualforce/esbuild.config.mjs`: drop import + node spread; remove now-redundant literal `conditions` from LS build (inherited via `nodeConfig`); update comment.
- `scripts/bundling/effect.mjs`: keep for now (org-browser browser build still spreads it).
- Node builds: pure move, no behavior change.

commit: `refactor(bundling): promote effect ESM node conditions to nodeConfig - W-23313217`

### Phase 3 — Promote browser conditions after per-package web e2e green

- Precondition: run the newly-conditioned browser specs (Verification list) green on branch.
- `scripts/bundling/web.mjs`: add `conditions: ['import', 'module', 'default']` to `commonConfigBrowser`.
- `org-browser/esbuild.config.mjs`: drop the remaining browser-build `...effectEsmConditions` spread + import.
- delete `scripts/bundling/effect.mjs` (no refs remain).
- `docs/adr/0021-*.md`: record browser fold complete; opt-in constant removed.

commit: `refactor(bundling): promote effect ESM browser conditions to commonConfigBrowser - W-23313217`
