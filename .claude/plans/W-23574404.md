# W-23574404 — Adopt Effect HashMap

## Context

The org metadata catalog stores immutable state in native `ReadonlyMap` values, then repeatedly clones maps for updates or converts them to arrays for Effect pipelines and persistence. Replace those internal maps with Effect `HashMap` so updates and collection transforms use Effect's immutable APIs. Preserve existing catalog behavior, ordering, persisted snapshot arrays, and external return shapes.

## Phases

### 1. Convert org catalog map state and transforms

- Change internal map types and empty values to `HashMap.HashMap` and `HashMap.empty`.
- Replace clone-and-mutate updates with `HashMap.set`, `HashMap.remove`, `HashMap.union`, and immutable reductions.
- Replace map-to-array spreads and temporary native maps with Effect `HashMap` collection operations.
- Convert to ordered arrays only at boundaries that require arrays, retaining existing sorts.
- Update helpers, consumers, fixtures, and assertions for `HashMap.get` returning `Option`.
- Add or adjust focused tests for hydration, persistence, invalidation, deduplication, and catalog projection where the representation changes.

Commit: `refactor(services): adopt Effect HashMap in org catalog`
