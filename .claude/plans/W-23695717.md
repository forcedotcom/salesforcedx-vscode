# W-23695717

## Context

- Subject: optimize local commit + pre-push hook performance
- `package.json` `husky.hooks`: `pre-commit` → `npm run precommit`; `pre-push` → `npm run prepush`. `commit-msg` stays `commitlint`
- `wireit.precommit` deps: `check:branch`, `compile`, `lint`, `check:format:staged`, `check:peer-deps`, `check:package-lock`, `check:lock-sync`, `check:actions`, `check:knip`, `check:effect-diagnostics`
- `check:knip` + `check:effect-diagnostics` depend on `compile`. `files` include `packages/*/src/**/*.ts`. Any TS edit cache-misses both, so they sit on the commit critical path after compile
- `wireit.prepush`: `command` `npm run test`, `env.WIREIT_PARALLEL` `"1"`, deps `precommit` + `vscode:bundle`. Wireit runs `command` after deps
- Wireit 0.14.12: `env` applies to that script's `command` only (not deps). `WIREIT_PARALLEL=1` runs 1 script at a time; default is 2× logical CPUs. https://github.com/google/wireit/blob/v0.14.12/README.md
- So local push runs the test graph serially, and only after precommit + `vscode:bundle`
- CI unit-test workflows set `WIREIT_PARALLEL: 1` in workflow `env`. Leave them. `docs/Build.md` sequential note is legacy `vscode:package` chdir

## Phases

### 1. Hook graph

- File: `package.json`

- Commit keeps incremental `compile` / `lint` / lock + format + branch checks. The two repo-wide post-compile analyses run on push, in the same wireit graph as `test` + `vscode:bundle`, at default parallelism
