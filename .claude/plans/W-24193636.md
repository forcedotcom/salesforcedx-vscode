# W-24193636 — Ban `salesforcedx-vscode-services` runtime dependencies

## Context

Extension packages currently declare `salesforcedx-vscode-services` under `dependencies`. Repository convention permits it only as an `extensionDependency` and, when needed for compilation, a `devDependency`. Enforce that boundary in package manifests and migrate existing violations so later changes cannot restore the runtime package dependency.

## Phases

### Phase 1 — Enforce and satisfy the package dependency rule

- Add `packages/eslint-local-rules/src/packageJsonNoServicesDependency.ts` to report `salesforcedx-vscode-services` entries under `dependencies` in `packages/*/package.json`.
- Add focused valid/invalid cases in `packages/eslint-local-rules/test/packageJsonNoServicesDependency.test.ts`.
- Export the rule from `packages/eslint-local-rules/src/index.ts` and enable it for package JSON files in `eslint.config.mjs`.
- Move each existing `salesforcedx-vscode-services` entry from `dependencies` to `devDependencies`; preserve existing `extensionDependencies` entries.
- Commit: `chore: ban services runtime dependencies - W-24193636`

## Skills to apply

- `packageJson` — enforce the repository dependency convention.
- `typescript` — implement the JSON AST rule and tests.
- `concise` — keep rule scope and documentation narrow.
- `verification` — verify the rule and affected manifests.

From the repository root:

1. Run `npm install`.

3. Run `npm run lint -w @salesforce/eslint-plugin-vscode-extensions`.
