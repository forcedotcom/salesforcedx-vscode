# W-23354585 — Enforce consistent-type-imports (inline-type-imports)

## Context
- Add `@typescript-eslint/consistent-type-imports` to root `eslint.config.mjs`.
- Config: `['error', { prefer: 'type-imports', fixStyle: 'inline-type-imports' }]`.
- Rule goes in TS `rules:` block (`files: ['**/*.ts']`, line 104), near other `@typescript-eslint/*` entries.
- inline style = `import { type Foo, bar } from 'x'` — single import stmt. Avoids collision w/ `no-duplicate-imports` (line 489, no `allowSeparateTypeImports`). separate-type-imports would emit 2nd `import type` line → violation.
- `eslint-plugin-import`/import-x present; not a factor for inline.
- Lint per-pkg via wireit `eslint --color --cache .`; root `npm run lint` fans out across ~30 workspaces.
- ~1557 src `.ts` files in scope. `import type` currently unused → wide fixable diff expected.

### Not autofixable: `import()` type annotations (must fix by hand)
- Rule default `disallowTypeAnnotations: true` bans inline `import('mod').Type` / `typeof import('mod')` type-position usages. `eslint --fix` does NOT rewrite these — they survive as hard errors.
- Verified empirically: 29 such occurrences across 9 files survive `--fix`. In `/src` (ships in build, highest priority):
  - `packages/salesforcedx-vscode-i18n/src/hover/tsPlugin.ts:13` — `typeof import('typescript/lib/tsserverlibrary')`
  - `packages/salesforcedx-utils-vscode/src/telemetry/reporters/appInsights.ts:19` — `typeof import('applicationinsights')`
  - `packages/salesforcedx-utils-vscode/src/telemetry/reporters/appInsights.ts:30` — `import('applicationinsights').TelemetryClient`
  - `packages/salesforcedx-apex-replay-debugger/src/adapter/types.ts:19` — `import('@salesforce/salesforcedx-utils').LineBreakpointInfo[]`
- Remaining ~6 files are test files (lwc-language-server, vscode-apex, vscode-org, vscode-services, vscode-soql, vscode-lightning) using `as typeof import('mod')`, `as unknown as import('mod').Type`, or `page: import('@playwright/test').Page` param annotations.
- Do NOT touch dynamic runtime imports (`import('o11y_schema/sf_pdp').then(...)` in o11yReporter.ts / o11ySpanExporter.ts) — those are value expressions, not type annotations, and are not flagged.
- Manual conversion per case:
  - `typeof import('mod')` used as a type → add top-level `import type * as Mod from 'mod'` and reference `typeof Mod` / `Mod` (or `import type { X } from 'mod'` when a named member is used). tsserverlibrary: hoist to `import type * as tsserverlibrary from 'typescript/lib/tsserverlibrary'`, annotate `typescript: typeof tsserverlibrary`.
  - `import('mod').Type` → top-level `import type { Type } from 'mod'`, reference `Type`.
  - Playwright `page: import('@playwright/test').Page` → top-level `import type { Page } from '@playwright/test'`.
  - `require('mod') as typeof import('mod')` (test mock casts) → add top-level `import type * as Mod from 'mod'`, cast `as typeof Mod`.

### Memory / OOM guidance
- Repo-root `npx eslint --fix .` OOMs on default Node heap (`FatalProcessOutOfMemory` across 1557 files / ~30 workspaces w/ typed linting).
- Run either:
  - per-workspace: `npm run lint -w <pkg> -- --fix` (uses the wireit per-package lint), OR
  - repo-root with heap bump: `NODE_OPTIONS=--max-old-space-size=8192 npx eslint --fix .`.
