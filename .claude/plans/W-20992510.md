# W-20992510 — Route WorkspaceContextUtil.getConnection reauth through ConnectionService

## Context

- Move expired-access-token reauth flow out of `WorkspaceContextUtil.getConnection` (salesforcedx-utils-vscode/src/context/workspaceContextUtil.ts:92-172) into `ConnectionService` (salesforcedx-vscode-services/src/core/connectionService.ts:203-274). Per ADR 0005 (services = contract), ADR 0006 (core API sunset).
- Current getConnection: caches Connection per username (`sessionConnections` Map); if `isAccessTokenFlow()`, revalidates via `connection.identity()` ≤ every 5min; on failure logs to Org Management channel (`getSalesforceVSCodeOrgExtension`), shows modal, `sf.org.login.web(instanceUrl, alias ?? username)`; dedupes modal cross-extension via `sharedAuthState`.
- `sharedAuthState` + the `isKnownBadConnection` Set + the `lastTokenValidationTimestamp` throttle exist ONLY because each ext bundles its own `WorkspaceContextUtil` singleton with a hand-rolled Map. One shared `ConnectionService` (via `getServicesApi`) needs NONE of them: an Exit-TTL keyed `Cache` replaces all three (see Phase 1).
- Callers: workspaceContext.ts:77 (in-repo, already uses ConnectionService @17-20), o11yReporter.ts:25 (facade), ui-preview previewUtils.ts:62 (EXTERNAL, private repo — facade signature frozen).
- ConnectionService.getConnection already caches (connectionCache, connectionService.ts:165-174) → drop utils Map + timestamp cache.
- Facade delegate pattern: telemetry.ts:49-66 (`fetchIdentityFromServices`), workspaceContext.ts:17-20 (`getConnectionEffect`). `@salesforce/effect-ext-utils` already dep of utils package.json:14.
- Exit-TTL Cache idiom: `connectionCache` (connectionService.ts:165-174) `Cache.makeWith` keyed by username, `timeToLive: Exit.match({ onSuccess: () => Duration.minutes(30), onFailure: () => Duration.zero })`. Effect's `Cache` dedupes concurrent same-key lookups into ONE in-flight run — this is exactly the reauth coordination shape (one modal per Connection, retry-clean after failure), so no separate semaphore/Set/timestamp AND no hand-rolled username→conn Map.
- Cache key = the live `Connection` object itself, NOT a username string. Effect's `Hash`/`Equal` give any plain object identity-based hashing/equality for free (Hash.ts randomHashCache WeakMap; Equal.ts `self === that` reference fast-path), so `Cache.makeWith({ lookup: (conn: Connection) => … })` + `reauthCache.get(conn)` dedupes per Connection instance with zero side-channel state. This is the key correction: do NOT key on username and smuggle the per-call `conn` in via a module-scoped closure/Map — that reintroduces exactly the hand-rolled-Map anti-pattern the Cache is meant to eliminate (anti-patterns.md "FORBIDDEN: Mutable State Without Ref"). Keying on the Connection reference also fixes staleness: a Connection recreated after invalidation is a fresh key that revalidates, whereas a username key would collide with the stale entry.
- Services ChannelService: vscode/channelService.ts, `appendToChannel` (best-effort) + `showChannel`. Default channel name is `Salesforce Services` (constants.ts:17). DECISION for plan: route reauth logging to the services-owned `Salesforce Services` channel (the `ChannelService.Default` destination), NOT `Salesforce Org Management`. Rationale: `salesforcedx-vscode-services` is a *dependency* of `salesforcedx-vscode-org`, so creating a `ChannelServiceLayer('Salesforce Org Management')` here would call `vscode.window.createOutputChannel('Salesforce Org Management')` from a second, distinct JS bundle (channelService.ts:65-70) — producing a SECOND output channel with the same display name as the one the org extension already owns (`salesforcedx-vscode-org/src/channels/index.ts:11-13` via utils' `ChannelService.getInstance`). That duplicate-channel trap is the exact anti-pattern the deleted code called out and avoided (`orgExtensionUtils.ts` comment "Do not fall back to ChannelService here: a second copy of utils can create a duplicate Org Management channel"; deleted `appendAccessTokenErrorToOrgManagement` reached UP into the org ext's `.exports.channelService` rather than create its own). Services must NOT reach up into the org extension's exports (dependency inversion) and must NOT re-create the org channel name. So: emit to `Salesforce Services` and explicitly DOCUMENT the user-visible channel-destination change in the PR body.
- Messages `error_access_token_expired*` live in utils i18n.ts:30-33 only (no ja) — need copy into services i18n.ts.

## Phases

### 1. Add reauth Effect to ConnectionService via Exit-TTL Cache (no semaphore/Set/throttle)
Files: `packages/salesforcedx-vscode-services/src/core/connectionService.ts`, `packages/salesforcedx-vscode-services/src/messages/i18n.ts`, new `packages/salesforcedx-vscode-services/test/jest/core/connectionService.test.ts`
- New exported service method `validateAccessTokenOrPromptReauth`: input Connection. If NOT `getAuthInfo().isAccessTokenFlow()` → `Effect.void` (skip). Else run through a module-level `reauthCache` keyed by the `Connection` object. getConnection stays fast/pure — do NOT inline the validation.
- Coordination = ONE `Cache.makeWith` whose LOOKUP TAKES THE LIVE `Connection` as its key (`lookup: (conn: Connection) => …`, `reauthCache.get(conn)`), NOT a username string + a side-channel `connByUsername` Map, and NOT a Set + semaphore + timestamp:
  - `lookup(conn)` = derive `username = conn.getUsername() ?? conn.getAuthInfoFields().username`; run `conn.identity()`; on success succeed `void`, on failure append reauth error to channel + `showChannel` + show the modal + (if button) dispatch `sf.org.login.web(conn.instanceUrl, alias ?? username)`, then `Effect.fail(new AccessTokenExpiredError(...))`.
  - Key on the Connection reference: Effect's `Hash`/`Equal` give plain objects identity-based hash/equality for free (Hash.ts randomHashCache WeakMap; Equal.ts `self === that`), so the Cache dedupes per Connection instance with ZERO module-level Map. Keying on username instead would force smuggling the per-call `conn` through a closure/Map — the hand-rolled-mutable-state anti-pattern this Cache exists to kill (anti-patterns.md "FORBIDDEN: Mutable State Without Ref"). Reference-keying also self-heals staleness: a Connection recreated after invalidation is a fresh key that revalidates; the old bad Connection's entry just expires.
  - `timeToLive: Exit.match({ onSuccess: () => Duration.minutes(30), onFailure: () => Duration.zero })`. Success TTL replaces the 5-min `lastTokenValidationTimestamp` throttle (revalidation window preserved). `Duration.zero` on failure replaces the manual `isKnownBadConnection` add/clear — the entry is not retained, so the next `getConnection` retries cleanly.
  - Cache's built-in concurrent-same-key dedup gives show-once: N concurrent callers sharing ONE cached Connection collapse to a SINGLE in-flight `lookup`, hence one modal — no `Effect.makeSemaphore(1)` and no `Set`.
- New `AccessTokenExpiredError extends Schema.TaggedError` (message field), EXPORTED (cross-package `catchTag`) — replaces the bare `throw new Error('Unable to refresh...')`.
- Channel destination: emit to the services-owned `Salesforce Services` channel via the default `ChannelService` (constants.ts:17). Do NOT provide `ChannelServiceLayer('Salesforce Org Management')` here: services is a *dependency* of the org extension, so that call would `createOutputChannel('Salesforce Org Management')` from a second bundle → a DUPLICATE channel with the same display name as the org extension's own (org/src/channels/index.ts:11-13). That is the exact trap the deleted code avoided (orgExtensionUtils.ts comment). Reaching UP into the org ext's `.exports.channelService` (the deleted code's approach) is dependency inversion and is disallowed from services. Net user-visible change: reauth errors now log to `Salesforce Services` instead of `Salesforce Org Management` — DOCUMENT this in the PR body and update Phase 5's channel assertion accordingly. `AliasService` already in `dependencies` for alias lookup (username via `conn.getUsername()`).
- Copy `error_access_token_expired`, `_detail`, `_login_button` into services i18n.ts.
- Jest (coverage of record for the relocated logic — desktop e2e deferred per Phase 5): identity success (no modal, cached ~30min so second call with the SAME Connection object skips identity), identity fail (modal shown ONCE across N concurrent `Effect.all` callers sharing ONE Connection instance via Cache dedup — assert executeCommand `sf.org.login.web` called with `[instanceUrl, alias ?? username]`, channel appended + shown, error tagged `AccessTokenExpiredError`), post-failure retry (failure TTL zero → next call re-runs identity), fresh Connection object = fresh key (a re-created Connection revalidates, not served stale), non-access-token flow skips. Mock `conn.identity`, `conn.getAuthInfo().isAccessTokenFlow`, `vscode.window.showErrorMessage`, `vscode.commands.executeCommand`. Follow templateService.test.ts `Effect.provide(layer)` style.
- Commit: `feat(services): add access-token reauth Effect to ConnectionService - W-20992510`
