# W-20992510 — Route WorkspaceContextUtil.getConnection reauth through ConnectionService

## Context

- Move expired-access-token reauth flow out of `WorkspaceContextUtil.getConnection` (salesforcedx-utils-vscode/src/context/workspaceContextUtil.ts:92-172) into `ConnectionService` (salesforcedx-vscode-services/src/core/connectionService.ts:203-274). Per ADR 0005 (services = contract), ADR 0006 (core API sunset).
- Current getConnection: caches Connection per username (`sessionConnections` Map); if `isAccessTokenFlow()`, revalidates via `connection.identity()` ≤ every 5min; on failure logs to Org Management channel (`getSalesforceVSCodeOrgExtension`), shows modal, `sf.org.login.web(instanceUrl, alias ?? username)`; dedupes modal cross-extension via `sharedAuthState`.
- `sharedAuthState` + the `isKnownBadConnection` Set + the `lastTokenValidationTimestamp` throttle exist ONLY because each ext bundles its own `WorkspaceContextUtil` singleton with a hand-rolled Map. One shared `ConnectionService` (via `getServicesApi`) needs NONE of them: an Exit-TTL keyed `Cache` replaces all three (see Phase 1).
- Callers: workspaceContext.ts:77 (in-repo, already uses ConnectionService @17-20), o11yReporter.ts:25 (facade), ui-preview previewUtils.ts:62 (EXTERNAL, private repo — facade signature frozen).
- ConnectionService.getConnection already caches (connectionCache, connectionService.ts:165-174) → drop utils Map + timestamp cache.
- Facade delegate pattern: telemetry.ts:49-66 (`fetchIdentityFromServices`), workspaceContext.ts:17-20 (`getConnectionEffect`). `@salesforce/effect-ext-utils` already dep of utils package.json:14.
- Exit-TTL Cache idiom: `connectionCache` (connectionService.ts:165-174) `Cache.makeWith` keyed by username, `timeToLive: Exit.match({ onSuccess: () => Duration.minutes(30), onFailure: () => Duration.zero })`. Effect's `Cache` dedupes concurrent same-key lookups into ONE in-flight run — this is exactly the reauth coordination shape (one modal per username, retry-clean after failure), so no separate semaphore/Set/timestamp.
- Services ChannelService: vscode/channelService.ts, `appendToChannel` (best-effort) + `showChannel`. Default channel name is `Salesforce Services` (constants.ts:17), NOT `Salesforce Org Management`. Preserving the current Org Management destination requires providing `ChannelServiceLayer('Salesforce Org Management')` at the reauth call site (channelService.ts:41). DECISION for plan: keep reauth logging to `Salesforce Org Management` to match today's user-visible behavior; note channel-destination change explicitly if we accept `Salesforce Services` instead.
- Messages `error_access_token_expired*` live in utils i18n.ts:30-33 only (no ja) — need copy into services i18n.ts.

## Phases

### 1. Add reauth Effect to ConnectionService via Exit-TTL Cache (no semaphore/Set/throttle)
Files: `packages/salesforcedx-vscode-services/src/core/connectionService.ts`, `packages/salesforcedx-vscode-services/src/messages/i18n.ts`, new `packages/salesforcedx-vscode-services/test/jest/core/connectionService.test.ts`
- New exported service method `validateAccessTokenOrPromptReauth`: input Connection. If NOT `getAuthInfo().isAccessTokenFlow()` → `Effect.void` (skip). Else run through a module-level `reauthCache` keyed by username. getConnection stays fast/pure — do NOT inline the validation.
- Coordination = ONE keyed `Cache.makeWith<username, void, AccessTokenExpiredError>` (mirror connectionCache:165-174), NOT a Set + semaphore + timestamp:
  - `lookup(username)` = run `conn.identity()`; on success succeed `void`, on failure append reauth error to channel + `showChannel` + show the modal + (if button) dispatch `sf.org.login.web(conn.instanceUrl, alias ?? username)`, then `Effect.fail(new AccessTokenExpiredError(...))`.
  - `timeToLive: Exit.match({ onSuccess: () => Duration.minutes(30), onFailure: () => Duration.zero })`. Success TTL replaces the 5-min `lastTokenValidationTimestamp` throttle (revalidation window preserved). `Duration.zero` on failure replaces the manual `isKnownBadConnection` add/clear — the entry is not retained, so the next `getConnection` retries cleanly.
  - Cache's built-in concurrent-same-key dedup gives show-once: N concurrent callers for one username collapse to a SINGLE in-flight `lookup`, hence one modal — no `Effect.makeSemaphore(1)` and no `Set<username>`.
  - `conn` is per-call runtime data. Since the Cache key is `username` but the lookup needs the live `conn`, thread `conn` in via a small module-scoped closure map OR make the method run the `identity()` directly and use `Cache.get(username)` only for dedup/TTL of the boolean outcome — pick the pattern that keeps `conn` out of the cache key. Prefer: lookup closes over the `conn` from the triggering call, keyed by username (same as connectionCache keys by username while the lookup builds a fresh Connection).
- New `AccessTokenExpiredError extends Schema.TaggedError` (message field) — replaces the bare `throw new Error('Unable to refresh...')`.
- Channel destination: log to `Salesforce Org Management` (match current behavior) by providing `ChannelServiceLayer('Salesforce Org Management')` where the reauth Effect runs; do NOT add the default `ChannelService.Default` (that channel is `Salesforce Services`). `AliasService` already in `dependencies` for alias lookup (username via `conn.getUsername()`).
- Copy `error_access_token_expired`, `_detail`, `_login_button` into services i18n.ts.
- Jest (unit-level dedup + branch coverage — real modal/CLI is Phase 5 e2e): identity success (no modal, cached ~30min so second call skips identity), identity fail (modal shown ONCE across N concurrent `Effect.all` callers via Cache dedup — assert executeCommand `sf.org.login.web` called with `[instanceUrl, alias ?? username]`, channel appended + shown, error tagged `AccessTokenExpiredError`), post-failure retry (failure TTL zero → next call re-runs identity), non-access-token flow skips. Mock `conn.identity`, `conn.getAuthInfo().isAccessTokenFlow`, `vscode.window.showErrorMessage`, `vscode.commands.executeCommand`. Follow templateService.test.ts `Effect.provide(layer)` style.
- Commit: `feat(services): add access-token reauth Effect to ConnectionService - W-20992510`

### 5. e2e: access-token-expired → modal → login.web (NEW spec — deliverable, not a note)
Files: new `packages/salesforcedx-vscode-org/test/playwright/specs/reauthExpiredToken.desktop.spec.ts` (or `-services` if the getConnection-triggering command lives there)
- No existing spec covers this path. orgLoginWeb.desktop.spec.ts:53-62 drives the palette WITHOUT instanceUrl (org-type QuickPick + alias-input path); orgLoginAccessToken.desktop.spec.ts:21-26 only covers initial session-ID prompt+cancel ("Real session-ID auth can't run in e2e"). Neither touches the programmatic reauth call (instanceUrl+alias args that SKIP the QuickPick per authParamsGatherer.ts:124 `skipAlias`), the moved modal copy, the channel destination, or the Cache dedupe. - Setup: authorize an org via the access-token flow with a DELIBERATELY INVALID token so `isAccessTokenFlow()` is true and `identity()` fails offline (no live OAuth needed). Mechanism: `sf org login access-token --instance-url <url> --no-prompt` with `SF_ACCESS_TOKEN=<bogus>` in env, set as default. Confirm the CLI accepts a bogus token without a round-trip (verify against the `sf` version pinned in the e2e image before relying on it; fall back to writing an access-token auth file directly into the test org dir if `--no-prompt` validates).
- Drive: invoke a command that calls `WorkspaceContextUtil.getConnection()` (e.g. any org-dependent command / the config-change handler that runs on activation with a default org). Assert: (1) the reauth modal appears with `error_access_token_expired` text + `_detail` + `_login_button`; (2) accepting the button dispatches `sf.org.login.web` with the org's instanceUrl (observable via the org-type QuickPick being SKIPPED — programmatic instanceUrl path — reaching straight to the web-login/port-1717 behavior, reusing orgLoginWeb.desktop.spec.ts's port-hold trick to make it deterministic offline); (3) the reauth error is appended to the `Salesforce Org Management` channel (`selectOutputChannel(page, 'Salesforce Org Management')`).
- If, after spiking, a live-CLI-free invalid-access-token org proves impossible in the e2e image, downgrade to: keep the modal-copy + login.web-dispatch + channel assertions jest-only (Phase 1 tests already assert executeCommand args + channel), and STRIKE the e2e-covered claim with an explicit written justification here — do not leave a false claim.
