# W-23506238: Use `Effect.filterOrFail` for metadata guards

## Scope

- Refactor the specified live guards in `salesforcedx-vscode-metadata`; no behavior changes.
- Preserve localized messages, error payloads, successful values, and operation order.
- Production source only; repository policy avoids simultaneous `/src` and `/test` edits. Existing tests exercise related conflict, diff, package-install, and delete flows; no focused unit tests cover these guard branches.

## Skills

- `concise`: compact tracked plan
- `effect-best-practices`: `Effect.filterOrFail`, predicates, typed failures, Effect diagnostics
- `typescript`: narrowing, minimal cleanup, unused imports
- `verification`: package checks, Effect review, Playwright requirements
- `playwright-e2e`: metadata package web/desktop test execution

## Implementation

1. Missing default org
   - In `packages/salesforcedx-vscode-metadata/src/conflict/resultStorage.ts`, pipe the `SubscriptionRef.get` result through `Effect.map` to select `orgId`, then `Effect.filterOrFail` with the predicate matching its declared optional type.
   - Construct the existing `MissingDefaultOrgError` lazily with `nls.localize('missing_default_org')`; keep the validated org ID as the successful value used in the storage URI.
   - Apply the same shape in `packages/salesforcedx-vscode-metadata/src/shared/diff/diffHelpers.ts`, preserving concurrent workspace/default-org lookup and cache URI construction.

2. Package installation guards
   - In `packages/salesforcedx-vscode-metadata/src/commands/packageInstall.ts`, filter the availability query result for a non-empty `records` array and fail with the existing localized `PackageInstallFailedError`; map success back to the input package ID.
   - Normalize the tooling create response as today, then filter for a successful create result before selecting its `id`; preserve the current serialized-errors failure message.
   - Replace the `Arr.head`/`Option.match` missing-record branch in `fetchInstallStatus` with `Effect.filterOrFail` after the existing query retry, preserving `Request ${requestId} not found` and returning the first record.
   - Remove imports made unused by these compositions without changing polling, prompts, progress, cancellation, or notification ordering.

3. Delete deploy result
   - In `packages/salesforcedx-vscode-metadata/src/shared/delete/deleteComponentSet.ts`, pipe the deploy effect through `Effect.filterOrFail`, accepting only results whose file responses contain no `isSDRFailure`.
   - Build `DeleteSourceFailedError` from the rejected deploy result, preserving the localized cause and rejected result payload.
   - Keep local-file deletion and formatted channel output after validation, so neither runs for a failed deploy.
   - Delete the now-unreachable duplicate post-success failure notification and remove its unused `vscode` import.
