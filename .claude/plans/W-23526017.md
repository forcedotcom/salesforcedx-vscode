# W-23526017: Convert MetadataXmlSupport singleton class to Effects consuming services

## Context

`packages/salesforcedx-vscode-core/src/metadataSupport/metadataXmlSupport.ts` currently keeps a process-global `MetadataXmlSupport` instance, returns Promises, receives `ExtensionContext`, and reaches the legacy core channel wrapper directly. Core activation already runs inside the extension's managed Effect runtime with Salesforce services available. Replace the singleton with one Effect workflow that consumes the existing extension context, channel, and settings services while preserving Red Hat XML version checks, schema registration, user-setting detection, heap adjustment, and localized channel output.

## Phases

### 1. Replace the singleton and update its callers/tests

Commit: `refactor(core): convert metadata XML support to Effect`

- `packages/salesforcedx-vscode-core/src/metadataSupport/metadataXmlSupport.ts`
  - Replace `MetadataXmlSupport` and `getInstance()` with exported `Effect.fn` functions.
  - Obtain the services API through `ExtensionProviderService`; consume `ExtensionContextService`, `ChannelService`, and `SettingsService` instead of receiving context or calling `getCoreChannelService`.
  - Keep Red Hat extension discovery through VS Code and configuration `inspect` calls required to distinguish explicitly configured scopes.
  - Use `vscode-uri` for resource URI construction; preserve current catalog/file-association values and all existing branches/messages.
  - Keep `ensureMinXmlHeap` as the tested pure helper.
- `packages/salesforcedx-vscode-core/src/index.ts`
  - Make project initialization an Effect workflow.
  - Run metadata XML setup and hover-provider initialization concurrently inside the managed runtime; remove the singleton call.
- `packages/salesforcedx-vscode-core/test/jest/metadataSupport/metadataXmlSupport.test.ts`
  - Run the exported Effect with test layers for the extension provider and consumed services.
  - Remove singleton resets and legacy channel mocks.
  - Preserve coverage for setting suppression and heap calculations; assert service writes/channel messages where behavior crosses a service boundary.
- `packages/salesforcedx-vscode-core/test/playwright/specs/coreOutputChannel.headless.spec.ts`
  - Update stale test wording that attributes metadata output to `getCoreChannelService`; keep the single-channel and no-Red-Hat output assertions.
