# W-24182965 — Convert Apex LSP client setup to Effect

## Context

The Apex extension currently builds and starts its language client through Promise-based setup in:

- `packages/salesforcedx-vscode-apex/src/languageServer.ts`
- `packages/salesforcedx-vscode-apex/src/languageUtils/languageClientManager.ts`
- `packages/salesforcedx-vscode-apex/src/languageUtils/index.ts`
- `packages/salesforcedx-vscode-apex/src/index.ts`

Convert that setup path to Effect so creation, startup, and failure propagation use one typed composition. Preserve existing Apex language-client options, status updates, restart behavior, and extension lifecycle boundaries. `effect` is already a package dependency.

## Phases

### 1. Specify the Effect setup boundary

**Commit:** `test: specify Effect-based Apex LSP client setup`

- Update `packages/salesforcedx-vscode-apex/test/jest/languageServer.test.ts` for the Effect-returning client construction/options path.
- Update `packages/salesforcedx-vscode-apex/test/jest/languageUtils/languageClientManager.test.ts` for Effect-based creation and startup while retaining current observable status and restart behavior.
- Keep tests focused on setup behavior; do not duplicate type-system or library behavior.

### 2. Convert Apex LSP client setup to Effect

**Commit:** `refactor: convert Apex LSP client setup to Effect`

- Refactor `packages/salesforcedx-vscode-apex/src/languageServer.ts` so server options, client options, and `ApexLanguageClient` construction compose as Effect functions.
- Refactor `packages/salesforcedx-vscode-apex/src/languageUtils/languageClientManager.ts` to compose client creation and startup in Effect instead of Promise orchestration, preserving current status, notification, restart, and cleanup behavior.
- Update `packages/salesforcedx-vscode-apex/src/languageUtils/index.ts` to expose the Effect setup operation.
- Update `packages/salesforcedx-vscode-apex/src/index.ts` to compose setup directly into the existing activation Effect and keep Effect execution at the extension lifecycle boundary.
- Use named `Effect.fn` functions and specific typed errors for setup failures; retain existing user-facing messages and telemetry data.
