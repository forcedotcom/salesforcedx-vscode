# W-23451946 — o11yReporter uses cached identity + services connection

Depends on WI 3 (already merged: `3aa2d1f74` appInsights/telemetryFile read cached org identity; `503e0d30b` widened services identity bridge). Cached-identity plumbing (`orgIdentity` prop, `updateReporters` setting it on O11yReporter) already in place.

## Context

o11yReporter is last util-vscode reporter reading org fields inline via `WorkspaceContextUtil.getInstance()`. 2 problems:
- Send sites read 4 org fields off util at call time (o11yReporter.ts:122-125, :164-167) instead of WI-1 cached `this.orgIdentity`.
- Module thunk `getConnection` (o11yReporter.ts:25) calls `WorkspaceContextUtil.getInstance().getConnection()`; captured once at `initialize()` (:66), invoked lazily on upload.

`this.orgIdentity: OrgIdentity` already declared (:32), set per-reporter by `telemetry.ts updateReporters` (:278). Sibling AppInsights already reads `this.orgIdentity`.

DESIGN CONSTRAINT: keep `getConnection` a module thunk hitting `getServicesApi` per call → resolves CURRENT org. Do NOT capture a resolved `Connection` at init (stale/cold-start hole).

Prop-shape note: existing send sites emit `orgShape`/`devHubId` even when `''` (only `orgEdition` gated). Preserve via `?? ''` reads off `this.orgIdentity`; do NOT swap to `getOrgIdentityProps` (it omits empties → changes shape, breaks tests). Acceptance = same prop shape.

Services bridge pattern to mirror: `workspaceContextUtil.ts:33-37` (`getServicesApi` → `api.services.ConnectionService.getConnection().pipe(Effect.provide(Layer.succeedContext(api.services.prebuiltServicesDependencies)))`). Same `getServicesApi` `fetchIdentityFromServices` uses (`telemetry.ts:57`).

`O11yService.initialize(name, endpoint, getConnection?: () => Promise<Connection>, options?)` — signature unchanged (`o11y-reporter/dist/index.bundle.d.ts:73`). Keep passing thunk.
