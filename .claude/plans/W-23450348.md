# W-23450348 — Skip non-required lint jobs on PR `edited` event

## Context
- `.github/workflows/validatePR.yml` triggers on `pull_request` types [opened, reopened, edited, synchronize].
- Goal: don't rerun code-only checks on title/body-only edits.
- Fix: job-level `if: github.event.action != 'edited'` (no per-job `types` filter in GHA).

### Critical constraint — required vs non-required checks
- `develop` branch protection `required_status_checks.contexts` = `pr-validation / pr-validation`, `build-and-test / build-all / build-all`, windows/linux unit-tests, **`code-quality`**. (verified: `gh api repos/forcedotcom/salesforcedx-vscode/branches/develop/protection`)
- **`code-quality` IS required. `check-knip` and `validate-actions` are NOT.**
- Skipped job reports Success, doesn't block merge (GitHub docs). GitHub evaluates only the latest status per (SHA, context).
- Merge-bypass risk: `synchronize` pushes bad code → `code-quality` fails on SHA X → author edits PR title/body (no code change) → `edited` fires on same SHA X → guarded `code-quality` skipped → posts fresh Success for `code-quality` on SHA X, superseding the earlier Failure → PR mergeable despite unfixed lint.
- Therefore: **do NOT guard `code-quality`.** Only guard the two non-required checks (`check-knip`, `validate-actions`) — skip-on-edit can't bypass a required gate.
- Leave `pr-validation` untouched — validates PR title/body GUS ref, needs `edited`.
- Leave `check-effect-diagnostics` untouched — not in WI scope.
- Out of scope (WI-noted): merging check-knip + code-quality to share compile.

## Phases
### 1. Add `if` guard to the 2 non-required lint jobs
- File: `.github/workflows/validatePR.yml`
- Add `if: github.event.action != 'edited'` to `validate-actions` and `check-knip` only (job level, alongside `runs-on`).
- Do NOT add the guard to `code-quality` (required check — skipping masks failures).
- Commit: `ci: skip non-required lint jobs on PR edited event - W-23450348`
