# W-24289597

Fail fast on other side closed and split Apex E2E timeouts.

Ref: actions/runs/35918228992 (macos class-scoped).

## Context

Class-scoped Apex Testing desktop E2E polls for `=== Test Summary` for `TEST_RUN_TIMEOUT` (600s) after the run already failed. `codeCoverageColorizer.headless.spec.ts` attempt 2: channel `Ended SFDX: Run Apex Tests[UnknownException] other side closed`. Span `sf.apex.test.run` 425.9s, status 2, `trigger` quickPick. Cause chain: `UnknownException` → `TypeError: fetch failed` → `SocketError: other side closed` at `TLSSocket.onHttpSocketEnd`.

`runApexTests` (`packages/salesforcedx-vscode-apex-testing/src/commands/apexTestRunUtils.ts`) wraps `runTestAsynchronous` in `Effect.tryPromise` with no `catch`. Span message becomes `An unknown error occurred in Effect.tryPromise`.

`waitForOutputChannelText` (`packages/playwright-vscode-ext/src/pages/outputChannel.ts`) forwards the caller timeout into `waitForOutputContent`, which only checks `.view-lines` length > 1. Callers pass `timeout: TEST_RUN_TIMEOUT`, so an empty buffer burns 600s before `waitForOutputChannelTextCommon` looks for the string. Code-lens attempt 1: `Output channel did not have content within 600000ms` after `runApexTests` spans had already ended OK (175.7s, 39.9s, 23.2s) and `onResultFileCreate` had fired.

`test.setTimeout(TEST_RUN_TIMEOUT)` starts at the beginning of the test, including auth and deploy. Toast-gone `toPass` is also 600s, so the test clock expires first. Suite attempt 1: `runApexTests` ended OK at 349s (`writeAndOpenTestReport`); failure was `Test timeout of 600000ms exceeded` inside `waitForRunApexTestsProgressNotificationGone` with Cancel-toast count still 1.

Keep toast appear, toast gone, and output lines. Do not replace them with a `test-result-*.json` poll.

## Phases

### 1. `fix: record socket error on the apex test run span`

`packages/salesforcedx-vscode-apex-testing/src/commands/apexTestRunUtils.ts` — `runApexTests`, `Effect.tryPromise` around `testService.runTestAsynchronous` (~105).

- `Effect.tryPromise({ try, catch })`. `catch` gets the raw rejection, not `UnknownException`.
- Do not copy `fsService.readFile` / `unknownToErrorCause`. That sets `message` from the outer `Error` only (`packages/salesforcedx-vscode-services/src/core/shared.ts`). `@effect/opentelemetry` sets `status.message` to `firstError.message` (`packages/salesforcedx-vscode-services/node_modules/@effect/opentelemetry/src/internal/tracer.ts`). Nested `.cause` is the exception stack only. `TypeError: fetch failed` with `cause` `SocketError: other side closed` records `fetch failed`.
- Caught error's own `.message` joins every `Error.message` on the rejection and its `.cause` chain (`fetch failed`, `other side closed`). That string is `sf.apex.test.run` `status.message`.
- `.cause` stays the original rejection. Exception stack and `ErrorHandlerService.getBaseMessage` still reach `other side closed` (phase 3 channel match). `api.services.getErrorMessage` returns that innermost string.
- `unknownToErrorCause` is not on `SalesforceVSCodeServicesApi`. Do not call it.
- Do not swallow. Keep `Effect.onInterrupt` (`tokenSource.cancel`) and `Effect.ensuring` (`tokenSource.dispose`).
- No new fallback path. Plain `Error` in this file, not a `Schema.TaggedError` from another module.
