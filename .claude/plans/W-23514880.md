# W-23514880: Harden O11yReporter telemetry sends

## Goal

Prevent failures from `@salesforce/o11y-reporter` event sends and final flushes from escaping `O11yReporter`, without changing successful telemetry or batching behavior.

## Scope

- Production change: `packages/salesforcedx-utils-vscode/src/telemetry/reporters/o11yReporter.ts`
- Test coverage: `packages/salesforcedx-utils-vscode/test/jest/telemetry/reporters/o11yReporter.test.ts`
- No dependency, batching, App Insights, navigator shim, or other telemetry changes

## Applicable Skills

- `concise`: keep this tracked plan compact and implementation-focused.
- `typescript`: preserve TypeScript style and comments; module-level `const` arrow helper.
- `verification`: focused regression checks followed by repository readiness hooks.

## Phase 1: Contain O11y Failures

1. Add module-level `guard(label, op)` after imports: catch synchronous errors, log `O11yReporter <label> failed:`, return normally.
2. Guard standard-event `logEvent` with label `logEvent`.
3. Attach a rejection handler to asynchronous command PFT delivery; log `O11yReporter sendPftEvent failed:`. Covers schema-load rejection and `logEventWithSchema` throws converted to rejection by the async method.
4. Guard exception-event `logEvent` with label `logEvent(exception)`.
5. Await `forceFlush()` with a rejection handler; log `O11yReporter forceFlush failed:` and let `dispose()` resolve.
6. Preserve batching setup, shutdown-hook behavior, payloads, and batching comments.

## Phase 2: Prove Failure Containment

1. Extend the existing Jest suite through its mocked `O11yService`.
2. Throw from `logEvent`; assert `sendTelemetryEvent()` does not throw.
3. Throw from `logEvent`; assert `sendExceptionEvent()` does not throw.
4. Reject `forceFlush`; assert `dispose()` resolves.
5. Spy on `console.error`; suppress expected output and assert operation-specific diagnostics.
6. Retain happy-path assertions as transparent-guard regression coverage.

## Verification

1. Run the focused `o11yReporter.test.ts` Jest suite.
2. Run `npm run test -w @salesforce/salesforcedx-utils-vscode`.
3. Let repository readiness hooks run compile, lint, tests, bundle, Effect checks, and knip.
4. Resolve failures attributable to this change; report readiness only after hooks pass.
