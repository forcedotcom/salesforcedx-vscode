# W-23429454 — Fix + enforce unknownInEffectCatch

## Context

- Effect LS rule `unknownInEffectCatch`: `catch` handler leaves `unknown` in failure channel (no typed error).
- Ratchet: `config/effect-diagnostics.json` `enforcedRules` (script `scripts/effect-diagnostics.mjs`, wireit `check:effect-diagnostics`, CI `validatePR.yml`). Enforce = append rule name.
- 2 sites, both in `packages/salesforcedx-vscode-lwc/src/index.ts`, both `catch: e => e`:
  - :88-90 `Effect.tryPromise({ try: () => createLanguageClient(...), catch: e => e })`
  - :114 `Effect.tryPromise({ try: () => client.start(), catch: e => e })`
- Each `.pipe(Effect.tapError(err => channelSvc.appendToChannel(nls.localize(<key>, isError(err) ? err.message : String(err)))))`. Failure NOT otherwise caught → propagates to `runPromise` (activation). Behavior: log + reject.
- OVERLAP: no custom eslint rule/skill; built-in LS rule + JSON ratchet (confirmed).

### Fix strategy (adversary:high)
- Repo pattern for typed catch = `catch: e => new XError({ message: isError(e) ? e.message : String(e) })` where `X extends Schema.TaggedError<X>()('X', { message: Schema.String })` (e.g. `packages/salesforcedx-vscode-metadata/src/commands/packageInstall.ts:30`, `packages/salesforcedx-vscode-apex-debugger/src/errors.ts:12`). `Schema.String` import: `import * as Schema from 'effect/Schema'`.
- Do NOT use single-arg `Effect.tryPromise(() => ...)`: yields `UnknownException` w/ generic message "An unknown error occurred in Effect.tryPromise" (`node_modules/effect/dist/esm/internal/core-effect.js:579`) → LEAVES rule findings unchanged AND drops real error text from the logged `tapError`, so must supply a typed `catch`.
- `Schema.TaggedError` extends `Error` (`node_modules/effect/dist/dts/Cause.d.ts:281` YieldableError extends Error) → `isError(err)` stays true, `err.message` stays populated → existing `tapError` localize calls unchanged, distinct keys (`lwc_language_server_start_failed`, `lwc_language_server_client_start_failed`) preserved.
- 1 shared tagged error `LwcLanguageServerError` (both = "server failed to start/launch"); distinct log keys already differentiate. Inline in `index.ts` (lwc has no `errors.ts`; 2 sites, don't add a file).
- No behavior change: same log text, same rejection/propagation. Only the failure-channel type narrows `unknown`→`LwcLanguageServerError`.
