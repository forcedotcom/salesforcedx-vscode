### Phase 3 — apexTestExecutionService loops (16)

File: views/apexTestExecutionService.ts. Loops only; try-statements are #7818's and already Effect-ified.

**Actual post-#7818 shape** (verified, not the pre-#7818 try/catch): `debugTests` is `Effect.fn('ApexTestExecutionService.debugTests')(function* (...))` (line 299). It contains:
- An `Effect.sync` at 308 wrapping `for (const test of orgOnlyTests)` (line 309) — pure `run.errored` side-effects, no await.
- A `yield* Effect.promise(async () => {...})` at 320 containing 3 native for-loops that `await vscode.commands.executeCommand(...)` and recover per-item via `.catch()`:
  - Loop A (line 324, `for (const test of testsToDebug)`): builds `classIdsToDebug` Set + `methodsToDebug` Map via a local `async debugItem()` closure; className-less methods dispatch `sf.test.view.debugSingleTest`; suites call `run.errored` (not-supported msg). Recovery: `await debugItem().catch(error => run.errored(test, new vscode.TestMessage(nls.localize('apex_test_debug_failed_message', toUserFriendlyApexTestError(error)))))` (lines 342-346).
  - Loop B (line 349, `for (const className of classIdsToDebug)`): `await Promise.resolve(vscode.commands.executeCommand('sf.test.view.debugTests', { name: className })).catch(error => { for (const test of testsToDebug) {...run.errored...} })`. Note the nested `for` at 353.
  - Loop C (line 368, `for (const [className, methods] of methodsToDebug)`): skips `classIdsToDebug.has(className)` (continue, 371), inner `for (const methodName of methods)` (373) dispatches `sf.test.view.debugSingleTest`; `.catch` recovers with a nested `for (const test of testsToDebug)` at 378.

**Correct rewrite.** The `Effect.promise(async () => {...})` wrapper is a Promise-in-Effect boundary; converting it to `Effect.gen` + `Effect.forEach` routes dispatch through the Effect runtime and eliminates all 6 loops. Idiom mirrors packageResolution.ts:141-146 (`Effect.forEach(collection, fn, { concurrency })`). Requirements:

1. Convert `yield* Effect.promise(async () => {...})` to inline `Effect.gen` body under the outer `Effect.fn` (or a nested `yield* Effect.gen`). Accumulators `classIdsToDebug`/`methodsToDebug` stay `const` mutable collections in gen scope — sequential concurrency (below) makes mutation safe, and no-let is already satisfied.

2. `concurrency: 1` is MANDATORY on every `Effect.forEach` — preserves the existing sequential debug-dispatch ordering (the replay debugger services one session at a time; parallel dispatch would change observable behavior and is not covered by any spec).

3. **Tagged error, not `catch: e => e`.** Each `vscode.commands.executeCommand` await becomes `Effect.tryPromise` whose `catch` maps to a `Schema.TaggedError` — never the raw caught value. `catch: e => e` puts `unknown`/`Error` on the E channel and trips the build-enforced `globalErrorInEffectCatch` LS diagnostic (config/effect-diagnostics.json `enforcedRules`; anti-patterns.md "Global Error in Effect Failure Channel / Catch Handler"). Add a module-local tagged error alongside the existing ones in utils/apexTestExecutionErrors.ts (peers: TestExecutionError etc.):
   ```ts
   export class DebugDispatchError extends Schema.TaggedError<DebugDispatchError>()('DebugDispatchError', {
     message: Schema.String
   }) {}
   ```
   Precedent for the exact catch→tagged-error+message shape: apexTestExecutionService.ts:225 (`catch: e => new TestExecutionError({ message: toUserFriendlyApexTestError(e) })`) and packageResolution.ts:55/141. Then route via `catchTag('DebugDispatchError', ...)` — NOT `catchAll`. Because `Effect.tryPromise`'s error channel is now exactly `DebugDispatchError`, `catchTag` fully discharges it and the recovery `Effect.sync(...run.errored...)` returns to the A channel.

   Per-dispatch pattern:
   ```ts
   Effect.tryPromise({
     try: () => vscode.commands.executeCommand('sf.test.view.debugSingleTest', { name }),
     catch: error => new DebugDispatchError({ message: toUserFriendlyApexTestError(error) })
   }).pipe(
     Effect.catchTag('DebugDispatchError', err =>
       Effect.sync(() => run.errored(test, new vscode.TestMessage(nls.localize('apex_test_debug_failed_message', err.message))))
     )
   )
   ```
   (`err.message` is already user-friendly — mapping happens in `catch`, matching the :225 precedent, so recovery does not re-map.)

4. Per-loop conversions:
   - Loop A → `Effect.forEach(testsToDebug, test => <per-item Effect>, { concurrency: 1 })`. The per-item Effect: `Effect.sync` for the Set/Map-mutation and suite-`run.errored` branches; the className-less dispatch branch uses the tryPromise+catchTag pattern above. (Replaces the `async debugItem()` closure — the branch logic moves into the Effect, the `.catch` becomes `catchTag`.)
   - Loop B → `Effect.forEach(Array.fromIterable(classIdsToDebug), className => <tryPromise dispatch>.pipe(Effect.catchTag('DebugDispatchError', err => Effect.sync(() => { /* same testsToDebug filter as lines 353-364, mark matching tests errored with err.message */ }))), { concurrency: 1 })`. The inner recovery `for` (353) becomes `testsToDebug.filter(...).forEach(...)` inside the `Effect.sync`.
   - Loop C → `Effect.forEach(Array.fromIterable(methodsToDebug), ([className, methods]) => classIdsToDebug.has(className) ? Effect.void : Effect.forEach(Array.fromIterable(methods), methodName => <tryPromise dispatch>.pipe(Effect.catchTag(...same-filter recovery...)), { concurrency: 1 }), { concurrency: 1 })`. Inner recovery `for` (378) → `.filter().forEach()` in `Effect.sync`.

5. Preserve exactly: `run.errored` side-effects and message keys (`apex_test_debug_failed_message`, `apex_test_suite_debug_not_supported_message`, `apex_test_debug_org_only_warning_message`), the skip-if-`classIdsToDebug.has(className)` semantics, the recovery filters (class-name / method-name matching), sequential ordering, `toUserFriendlyApexTestError` mapping, and "no channel sentinel on debug path".

**Remaining loops** — the orgOnly `for (const test of orgOnlyTests)` inside the `Effect.sync` at 308-314 → `orgOnlyTests.forEach(...)` inside that same `Effect.sync` (no await, no error routing). Plus any other pure side-effect for-loops in the file → `.forEach` in place.
