### Phase 3 — apexTestExecutionService debug-dispatch loops (+ remaining side-effect loops)

File: views/apexTestExecutionService.ts. Loops only — try-statements are #7818's and already Effect-ified.

**Debug-dispatch (`debugTests`):** post-#7818 this is `Effect.promise(async () => {...})` containing 3 native for-loops that `await vscode.commands.executeCommand(...)` and recover per-item via `.catch()`. Leaving them inside one `Effect.promise(async)` and swapping to `.forEach` is FORBIDDEN — it re-creates the Promise-in-Effect-boundary / async-callback pattern (`.claude/skills/effect-best-practices/references/anti-patterns.md` — "FORBIDDEN: Promise in Service Signatures"), and `.forEach` can't `yield*` so the catch can't route through Effect's error channel.

Correct rewrite — convert the `Effect.promise(async)` wrapper to `Effect.gen`, and each of the 3 loops to `Effect.forEach(..., { concurrency: 1 })` mirroring packageResolution.ts:141-146. `concurrency: 1` is mandatory to preserve the existing sequential debug-dispatch ordering (debugger can service one session at a time).

- Loop 1 (partition `testsToDebug` → build `classIdsToDebug` Set + `methodsToDebug` Map, dispatch className-less methods): `Effect.forEach(testsToDebug, test => <per-item effect>, { concurrency: 1 })`. Per-item effect: `Effect.sync` for the Set/Map mutation and `run.errored` (suite) branches; the className-less `debugSingleTest` dispatch branch → `Effect.tryPromise({ try: () => vscode.commands.executeCommand('sf.test.view.debugSingleTest', { name }), catch: e => e }).pipe(Effect.catchAll(error => Effect.sync(() => run.errored(test, new vscode.TestMessage(nls.localize('apex_test_debug_failed_message', toUserFriendlyApexTestError(error)))))))`. Accumulators stay `const` mutable collections in the gen scope (no-let already satisfied; sequential concurrency makes mutation safe).
- Loop 2 (`classIdsToDebug`): `Effect.forEach(Array.fromIterable(classIdsToDebug), className => Effect.tryPromise({ try: () => vscode.commands.executeCommand('sf.test.view.debugTests', { name: className }), catch: e => e }).pipe(Effect.catchAll(error => Effect.sync(() => { /* mark matching tests errored, same filter as today */ }))), { concurrency: 1 })`.
- Loop 3 (`methodsToDebug` entries, skip class-selected): `Effect.forEach(Array.fromIterable(methodsToDebug), ([className, methods]) => classIdsToDebug.has(className) ? Effect.void : Effect.forEach(Array.fromIterable(methods), methodName => Effect.tryPromise({ try: () => vscode.commands.executeCommand('sf.test.view.debugSingleTest', { name: methodName }), catch: e => e }).pipe(Effect.catchAll(error => Effect.sync(() => { /* mark matching tests errored */ }))), { concurrency: 1 }), { concurrency: 1 })`.
- Preserve exactly: `run.errored` side-effects, suite-not-supported message, skip-if-`classIdsToDebug.has(className)` semantics, toUserFriendlyApexTestError mapping.

**Remaining loops** (orgOnly-errored loop inside `Effect.sync`, and the pure side-effect loops): `.forEach` inside their existing `Effect.sync` blocks — no `await`, no error routing needed.

Commit: `refactor(apex-testing): apexTestExecutionService loops -> functional - W-23354498`
