# W-23596410: Replace input predicates with Schema decoders

## Approach

Define reusable string schemas and replace each hand-rolled boolean validator with a precomputed schema validator: `Schema.is(...)` for type-preserving string filters and `Schema.decodeUnknownOption(...)` plus `Option.isSome` for transforming schemas. Export the shared identifier schemas from `salesforcedx-vscode-services`; keep command-specific package IDs, expiration days, org aliases, and URLs beside their consumers. Preserve trimming, empty-value handling, localized validation keys, and the exact shell-safety character restrictions. The expiration-days schema intentionally uses `NumberFromString` semantics and accepts numeric forms such as `1e1`, padded whitespace, and a leading plus when their decoded integer is between 1 and 30.

## Phases

### Phase 1: Add shared identifier schemas

- Add a focused schema module under `packages/salesforcedx-vscode-services/src/core/schemas/` containing the common identifier schema (`Schema.String` plus `/^[A-Za-z][A-Za-z0-9_]*$/`) and its lowercase-first variant (`/^[a-z][A-Za-z0-9_]*$/`).
- Export both schema values explicitly from `packages/salesforcedx-vscode-services/src/index.ts`; do not add them to the activated `services` object because validation is synchronous and requires no service instance.
- Add a separate services Jest suite covering first-character constraints, underscores/alphanumerics, empty strings, whitespace, punctuation, and the lowercase-only distinction. Keep this test-only phase separate from the source phase.

### Phase 2: Adopt shared identifier decoders

- Import the shared schemas and define module-level `Schema.is(...)` predicates in the 6 consumers: Apex anonymous script, Apex type name, Aura name, LWC name, manifest name, and SOQL file name.
- Replace only the duplicated regex tests. Preserve each caller's current normalization order, empty/reserved/max-length/duplicate/collision checks, output trimming, and existing `nls.localize` key.
- Use the lowercase-first schema only for LWC; use the common schema for the other 5 sites.

### Phase 3: Replace local numeric, package, alias, and URL predicates

- In `orgCreate.ts`, replace `isInteger` and `isIntegerInRange` with one module-level `Schema.decodeUnknownOption(...)` decoder for `Schema.NumberFromString.pipe(Schema.int(), Schema.between(1, 30))`; validate with `Option.isSome`. Keep `error_invalid_expiration_days`; do not prepend a digits-only pattern, so the approved `Number()` forms remain accepted.
- In `packageInstall.ts`, replace `PKG_ID_PREFIX` and `isValidPackageId` with a local pattern schema that accepts exactly an alphanumeric `04t` ID of length 15 or 18, then use its `Schema.is(...)` decoder. Preserve empty input as valid and `package_install_id_validation` for invalid non-empty input.
- In `orgAlias.ts`, model the existing alphanumeric/underscore/space and hyphen-enabled alias regexes as branded string schemas, derive both exported predicates with `Schema.is(...)`, and retain `validateAliasInput` behavior. Keep the regexes unchanged so all current shell metacharacters remain rejected.
- In `authParamsGatherer.ts`, apply the existing HTTP(S) safe-character pattern to `Schema.String`, compose that input schema into `Schema.URL`, and precompute a `Schema.decodeUnknownOption(...)` decoder checked with `Option.isSome` in `validateUrl`. This retains the current protocol and metacharacter restrictions while adding URL decoding; keep `auth_invalid_url` unchanged.
- Preserve current comments, updating only statements made obsolete by `NumberFromString` acceptance.

### Phase 4: Add focused regression coverage

- Extend `orgCreate.test.ts` through the captured expiration `validateInput` callback: accept 1 and 30, reject out-of-range/non-integer/non-numeric values, and record accepted `NumberFromString` forms (`1e1`, padded whitespace, leading plus).
- Retain and extend `orgAlias.test.ts` and `authParamsGatherer.test.ts` with boundary cases needed to prove the branded schemas and composed URL schema preserve existing injection defenses.
- Add focused package-install validation coverage at the prompt callback for valid 15/18-character `04t` IDs, wrong prefixes/lengths, non-alphanumeric characters, and empty input. Keep source and test changes in separate phases except imports required by test organization.
