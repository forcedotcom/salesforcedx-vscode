# W-23195719 — publish workflows: background npm install during release download

## Context

Publish jobs: `npmInstallWithRetries` independent of `downloadExtensionsFromRelease` but runs after it (sequential). Background npm install so it overlaps the slow release download; `wait` before publish (needs `node_modules`).

GHA `background: true` overlaps only *subsequent* steps (pilot: `coreE2E.yml` L113 Playwright bg step precedes the generate-project/scratch-org steps it overlaps, then wait @L136). => npm-install step must move **before** `downloadExtensionsFromRelease` to run during the download. WI's "add background to the npm-install step" satisfied by relocating it above download.

Blocker W-23195710 shipped (commit 5a8b23195): `validateActions.ts` tolerates `background`/`wait`/`wait-all`; `check:actions` won't reject new keys.

Files:
- `.github/workflows/publishVSCode.yml` — publish job L72-99
- `.github/workflows/publishOpenVSX.yml` — publish job L51-70

## Phases

### Phase 1 — background npm install in both publish workflows

**publishVSCode.yml** (publish job):
- move `- uses: .../npmInstallWithRetries@main` (L93) up to right after `setup-node` (L78-80); add `id: npm-install` + `background: true`.
- resulting order: checkout → setup-node → npm-install(bg) → download → display → collect-names → **wait** → validate-vsix → publish.
- new wait-only step **before `Validate VSIX OPC Part URIs` (L94)**, i.e. right after `collect-extensions` (L92): `wait: npm-install`. NO `run`/`uses` (valid real GHA syntax; validator handles stale-schema noise).
- **why wait before validate-vsix, not just before publish:** `validate-vsix-opc.mjs` imports `glob`/`jszip` (L9-10) → MODULE_NOT_FOUND w/o node_modules. collect-extensions (`parse-extension-names.js`, fs/path only, no deps) safe before wait → keep it there for max overlap; wait after collect-extensions gates validate-vsix + publish in one step. download→display→collect→validate chain keeps internal order; only wait boundary shifts left.

**publishOpenVSX.yml** (publish job):
- move `- uses: .../npmInstallWithRetries@main` (L66) up to right after `setup-node` (L57-59); add `id: npm-install` + `background: true`.
- resulting order: checkout → setup-node → npm-install(bg) → download → display → wait → publish.
- new wait-only step before the `retry@main` ovsx publish step (L67): `wait: npm-install`. No intermediate node-dependent step here (no validate-vsix in this workflow) → placement before publish is correct.

Both: npm-install needs only checkout (`package.json`) + node; download uses `gh` (no node) → truly independent.
