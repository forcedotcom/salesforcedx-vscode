# W-23233936 — Add OrgInfoService to services; drop @salesforce/core from util/orgDisplay

## Context

- Goal: eliminate direct `@salesforce/core` import from `packages/salesforcedx-vscode-org/src/util/orgDisplay.ts`.
- Today `orgDisplay.ts` imports `AuthInfo/Connection/Org/AuthFields` + `OrgInfo` type from org pkg; derives `OrgInfo` via direct `AuthInfo.create`/`Connection.create`/`Org.create`.
- Follow-up to PR 7626 (services migration pattern).
- Consumers of `OrgInfo` type: `commands/orgDisplay.ts` (`formatOrgInfoAsTable`, `writeOrgInfoToChannel`), `util/orgDisplay.ts`. Type def: `types/orgInfo.ts`.
- Org pkg reaches services only via `ExtensionProviderService.getServicesApi` → `api.services.*` (no direct import of service impls).
- `ConnectionService.getConnection()` resolves DEFAULT org only — no per-username accessor. `connectionCache` (module-private) desktop lookup = `createDesktopConnection(username)`; private helpers `createAuthInfoFromUsername`, `createConnection`.
- `shared.getOrgFromConnection(conn)` already exists → reuse for `Org.create`.
- `ConfigService.getTargetOrg()` exists (configService.ts:95-97, returns target-org value or `undefined`). Reuse it — do NOT reimplement the TARGET_ORG lookup.
- `ConnectionService.getConnection` still INLINES the TARGET_ORG lookup + alias resolution (connectionService.ts:221-233: `agg.getPropertyValue(TARGET_ORG)` + `aliasService.getUsernameFromAlias`). Phase 2 must refactor `getConnection` to call `ConfigService.getTargetOrg()` so the lookup lives in 1 place (shared by `getConnection` and `OrgInfoService.getOrgInfoForUsername`), not 3 copies.
- `getConnection`'s desktop branch throws `NoTargetOrgConfiguredError` when target-org unset; after the refactor that branch = `getTargetOrg()` → `filterOrFail(!= null)` → alias-resolve → `connectionCache.get(username)`.
- CRITICAL side effect: `getConnection` unconditionally forks `maybeUpdateDefaultOrgRef(conn)` (connectionService.ts:236-241) to update the SubscriptionRef backing telemetry/context. Any per-username accessor modeled on `getConnection`'s body would corrupt the tracked default-org identity when inspecting a NON-default org. The new accessor MUST NOT invoke `maybeUpdateDefaultOrgRef`.
- `getConnectionStatusFromError`/`shouldRemoveOrg` live in `util/orgUtil.ts` (org pkg); also used by org-list-clean flows there. Service can't import org pkg → needs own copy in services.
- Web caveat:
  - `connectionCache.lookup` chosen once at module load = `ESBUILD_PLATFORM === 'web' ? createWebConnection : createDesktopConnection` (connectionService.ts:165-174).
  - on web, `connectionCache.get(username)` → `createWebConnection` → `fromKey(username)` expects `instanceUrl###accessToken###apiVersion` (connectionService.ts:140-157); bare username silently mis-parses.
  - services pkg ships a web bundle (esbuild.config.mjs sets `ESBUILD_PLATFORM='web'`) → per-username accessor NOT web-safe as-is.
  - decision (below): guard with a typed `UsernameConnectionNotSupportedOnWebError`.
- Schema convention: `services/src/core/schemas/*.ts` (`Schema.Struct`, e.g. `defaultOrgInfo.ts`).
- Service pattern: `Effect.Service<T>()('Name',{accessors:true,dependencies:[...],effect})`; wired in `index.ts` (prebuilt-deps union, API accessor field, `globalLayers`, return obj, type export).

## Phases

### Phase 1 — OrgInfo schema in services
- new `services/src/core/schemas/orgInfo.ts`: `OrgInfoStruct = Schema.Struct({...})` mirroring `types/orgInfo.ts` fields (`status` + `password`/`namespace` optional); `export type OrgInfo = typeof OrgInfoStruct.Type`.
- `index.ts`: `export { OrgInfoStruct, type OrgInfo } from './core/schemas/orgInfo'`.
- commit: `feat(services): add OrgInfo schema`

### Phase 2 — OrgInfoService (+ ConnectionService per-username connection)
- `connectionService.ts` refactor (do FIRST, own commit if it clarifies): change `getConnection`'s desktop branch to call `configService.getTargetOrg()` instead of the inlined `agg.getPropertyValue(TARGET_ORG)` (connectionService.ts:222-228). `filterOrFail` on the result for `NoTargetOrgConfiguredError`, then alias-resolve + `connectionCache.get`. This is the single source of the target-org lookup.
- `connectionService.ts`: add `getConnectionForUsername(username: string)` accessor. Requirements:
  - alias-resolve `username` via `aliasService.getUsernameFromAlias` (arg may be an alias), then `connectionCache.get(resolvedUsername)`; returns `Connection`.
  - MUST NOT call `maybeUpdateDefaultOrgRef` — reuse only the conn-resolution path, never the ref-update side effect. `getConnection` keeps the fork; `getConnectionForUsername` returns the raw connection with no ref mutation. (Factor the shared `connectionCache.get` step so the 2 accessors clearly diverge on the side effect.)
  - Web: guard at the top — `process.env.ESBUILD_PLATFORM === 'web'` → `Effect.fail(new UsernameConnectionNotSupportedOnWebError({...}))`. Rationale: `connectionCache.lookup` is `createWebConnection` on web, which parses the arg as `instanceUrl###accessToken###apiVersion`, not a username. Add `UsernameConnectionNotSupportedOnWebError` (Schema.TaggedError, `@ExportTaggedError`) to connectionService.ts. Desktop path only past the guard.
  - Add to returned obj.
- new `services/src/core/orgInfoService.ts`:
  - `OrgInfoService` (deps: `ConnectionService`, `AliasService`, `ConfigService`).
  - `getOrgInfoForUsername(username?: string)`:
    - resolve username: arg ?? `ConfigService.getTargetOrg()` (configService.ts:95) else `NoUsernameError`; alias-resolve via AliasService.
    - → `ConnectionService.getConnectionForUsername` → derive `OrgInfo`.
    - connection/query failure → typed `OrgInfoConnectionError` → graceful degraded `OrgInfo`.
    - web: `getConnectionForUsername` fails `UsernameConnectionNotSupportedOnWebError` → map into the same degraded builder as `OrgInfoConnectionError`, so org-display still renders.
  - `getOrgInfoFromConnection(conn)`: default-org path — derive `OrgInfo` from established `Connection`.
  - port helpers from `util/orgDisplay.ts`: `createOrgInfo`, `getOrgInfoFromConnection` core, `queryScratchOrg` (`getOrgFromConnection` from shared, no direct `Org.create`), `getConnectionStatus` (`conn.identity()`), `getAllAliases` (AliasService), degraded builder.
  - port `getConnectionStatusFromError`/`shouldRemoveOrg` (copy) into services (own module or inline) for error→status mapping.
  - tagged errors `NoUsernameError`, `OrgInfoConnectionError` (Schema.TaggedError) — `@ExportTaggedError`, follow ts4023 export rules.
- `index.ts`: add `OrgInfoService` to prebuilt-deps union, API accessor field, `globalLayers` mergeAll, return obj, `export type { OrgInfoService, NoUsernameError, OrgInfoConnectionError }`.
- commit: `feat(services): add OrgInfoService for org metadata by username`

### Phase 3 — Delegate org pkg to OrgInfoService; drop @salesforce/core from util/orgDisplay.ts
- `util/orgDisplay.ts`: gut to thin delegator — `getOrgInfoEffect(username?)` = `api.services.OrgInfoService.getOrgInfoForUsername(username)`. Remove all `@salesforce/core` imports + ported helpers + local errors. Move `orgInfoFromConnection` usage to service (default path).
- `commands/orgDisplay.ts`: default path calls `api.services.OrgInfoService.getOrgInfoFromConnection(conn)`; import `OrgInfo` type from `@salesforce/vscode-services` (drop `../types/orgInfo`).
- delete `types/orgInfo.ts` (verify no other importers).
- if `util/orgDisplay.ts` becomes empty re-exports only, fold into command + delete file.
- commit: `refactor(org): delegate orgDisplay to OrgInfoService, drop @salesforce/core`

### Phase 4 — Tests
- new `services/test/jest/core/orgInfoService.test.ts`: port cases from org `util/orgDisplay.test.ts` (username resolution, scratch vs non-scratch, degraded/connection-error, alias supplement).
  - REQUIRED regression: assert `defaultOrgRef` (SubscriptionRef) is UNCHANGED after `getConnectionForUsername`/`getOrgInfoForUsername` for a NON-default username. Snapshot the ref before, invoke, assert `SubscriptionRef.get` equals the snapshot (no `maybeUpdateDefaultOrgRef` side effect). Contrast with a `getConnection()` test that DOES update the ref, to prove the divergence.
  - REQUIRED web case: with `ESBUILD_PLATFORM='web'`, `getConnectionForUsername` fails `UsernameConnectionNotSupportedOnWebError` and `getOrgInfoForUsername` degrades gracefully (returns degraded `OrgInfo`, no `fromKey` mis-parse).
- update/relocate `org/test/jest/util/orgDisplay.test.ts` (now delegator — mock service via ExtensionProviderService) + `commands/orgDisplay.test.ts` (default path uses service).
- commit: `test(services): OrgInfoService; update org orgDisplay tests`
