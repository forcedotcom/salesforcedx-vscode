# W-23348768 — Migrate Apex telemetry to Effect spans/logs; drop core TelemetryService

## Context

- Implements ADR-0002 (`packages/salesforcedx-vscode-apex/docs/adr/0002-telemetry-to-effect-spans.md`), which implements repo ADR-0012 (spans-only).
- Retire legacy core event API in `salesforcedx-vscode-apex`: `sendEventData`, `sendException`, `sendExtensionDeactivationEvent`.
- Delete holder `src/telemetry/telemetry.ts` (`TelemetryServiceInterface` + `get/setTelemetryService`) and the `vscodeCoreExtension.exports.services.TelemetryService.getInstance` fetch at `src/index.ts:62-67`.
- Holder consumers (all must migrate before delete):
  - `src/languageServer.ts` — `apexLSPSettings` (L105), `apexLSPError`/LSP_ERR (L134), `apexLSPLog` (L156)
  - `src/index.ts` — deactivation event (L121)
  - `src/languageUtils/languageClientManager.ts` — `apexLSPStartup` (L325), `apexLSPRestart` (L149)
  - `src/languageUtils/index.ts` — `apexTestDiscoveryStart`/`apexTestDiscoveryEnd` (L20/L23)
- Export rules (services observability README): only top-level + command spans reach App Insights/O11y. Nested-fiber data → `annotateRootSpan` (`@salesforce/effect-ext-utils`). `Effect.logDebug/logError` = local-debug only, not event replacement.
- `apexLSPLog` = high-volume, allowlist-gated at `client.onTelemetry`. ADR: do NOT make each event a top-level span (reinstates suppressed volume). Write attrs onto 1 long-lived language-client root span (held Span reference); keep allowlist gate at boundary.
- CRITICAL — the client span must be a genuine trace ROOT (`root: true`), not parented to activation. `annotateRootSpan` walks `Span.parent` to the trace's ultimate root (`annotateRootSpan.ts:13-18`), so annotating "via `withParentSpan(clientSpan)`" when clientSpan is nested under the activation span writes attrs onto the activation span, not clientSpan. Also the activation span closes when `activateEffect` returns (`index.ts:52-101`, `Effect.fn`), and Jorje emits `apexLSPLog` for the whole session afterward — writes to an ended span are silent no-ops (`@opentelemetry/sdk-trace-base` `Span.setAttribute` returns early once ended). Fix: create the client span as a scoped root and write attrs to the held `Span` reference directly (see Phase 1).
- Runtime: `getRuntime()` (`src/services/runtime.ts`) → `ManagedRuntime`. Emit standalone one-shot spans via `getRuntime().runFork(...)` with `root: true` (matches `registerCommand.ts:36-37` — root ensures top-level export, not an orphaned child of activation). Precedent: `languageServerOrphanHandler.ts` (annotateRootSpan, withSpan, Effect.fn).
- Allowlist (`apexLspTelemetryAllowlist.ts`) + its test stay.

## Phases

### Phase 1 — languageServer.ts events → spans/logs
- `apexLSPSettings` (L105): standalone low-volume top-level span via `getRuntime().runFork` — `Effect.withSpan('apex.lsp.settings', { attributes: { maxHeapSize }, root: true })`.
- `apexLSPError`/LSP_ERR (L134): span carrying error (`root: true`, one-shot) + `Effect.logError`; keep `showErrorMessage`.
- `apexLSPLog` (L154-158) — 1 long-lived client span, attrs written to the held Span reference (NOT annotateRootSpan, NOT withParentSpan):
  - In `createLanguageServer`, before `client.onTelemetry`, create a scoped ROOT span and keep its `Span` handle:
    `const clientSpan = getRuntime().runSync(Effect.makeSpanScoped('apex.lsp.client', { root: true }).pipe(Scope.extend(getExtensionScope())))` — `makeSpanScoped` returns the `Tracer.Span`; `root: true` makes `findRoot`/`onStart` treat it as top-level so it exports; extending the extension scope keeps it unended (so `setAttribute` keeps working) until `closeExtensionScope()` on deactivate/restart, at which point it ends and the file/App Insights exporter ships it.
  - In `onTelemetry`, keep the `isApexLspTelemetryAllowed(data.properties)` gate at the boundary, then write directly: `Object.entries({ ...data.properties, ...data.measures }).forEach(([k, v]) => clientSpan.attribute(k, v))`. No fork, no annotateRootSpan — `Span.attribute` mutates the held span in place. 1 span, not N (attrs last-write-wins, per ADR).
  - Rationale: `annotateRootSpan` walks to the trace root and would either no-op (no current span in the `onTelemetry` callback) or land on the wrong span; writing to the held `root: true` Span reference is the only path that (a) targets exactly that span and (b) keeps it exportable as top-level.
- Confirm `Scope.extend` + `makeSpanScoped` shape against `effect-best-practices`; if `Scope.extend` piping proves awkward, equivalently `getRuntime().runFork(getExtensionScope().pipe(Effect.flatMap(scope => Effect.makeSpan('apex.lsp.client', { root: true }) ... )))` — the invariant is: span is `root: true`, held by reference, ended only at scope close.
- Drop `getTelemetryService` import + both `const telemetryService = getTelemetryService()` (L76, L145).
- Holder still present (index.ts consumers remain) → compiles.
- Commit: `refactor(apex): emit languageServer telemetry as Effect spans - W-23348768`
