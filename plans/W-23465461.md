## Phases

### Phase 1 — channels/index.ts becomes an Effect-backed fire-and-forget bridge

commitMessage: `refactor(apex-replay-debugger): route debugger output through services ChannelService - W-23465461`

Files: `packages/salesforcedx-vscode-apex-replay-debugger/src/channels/index.ts`, `packages/salesforcedx-vscode-apex-replay-debugger/src/index.ts`

- Rewrite `channels/index.ts`: drop `vscode.window.createOutputChannel`, `nls`, utils-vscode `ChannelService`. Export one sync `void` fn (e.g. `appendAndShowChannelOutput(message: string): void`), modeled on `packages/salesforcedx-vscode-lwc/src/channel/index.ts:28-45`:
  - inner effect via `Effect.fn('channels.appendAndShowChannelOutput')`: `const api = yield* (yield* ExtensionProviderService).getServicesApi` → `const channelService = yield* api.services.ChannelService` → `yield* channelService.appendToChannel(message)` then `yield* channelService.showChannel` (`showChannel` is an Effect property, not a fn — `packages/salesforcedx-vscode-services/src/vscode/channelService.ts:46`).
  - failures swallowed (`Effect.ignoreLogged`): `getServicesApi` can fail `ServicesExtensionNotFoundError | InvalidServicesApiError`; channel writes stay best-effort as today.
  - run with `getRuntime().runFork(...)` — never `Effect.provide(AllServicesLayer)` at a call site. `try`/`catch` around the fork so a not-yet-set `AllServicesLayer` (pre-activation, unit tests) cannot throw into callers — same guard + rationale as the LWC bridge.
  - ordering: `getServicesApi` is `Effect.sync` once the services extension is active (`packages/effect-ext-utils/src/extensionProvider.ts:32-43`) and the channel cache lookup is `Effect.sync` — no async boundary, so append→show and successive calls keep source order.
- `src/index.ts`: swap the `channelService` import for the new fn; replace lines 266-267 with the single call. Rest of `writeToDebuggerOutputWindow` (window-message switch) untouched.
- Keeps `src/index.ts` down to 3 changed lines (import + 2 body lines) to minimize conflict with WI 1, which also edits `src/index.ts`.
