# W-23451863 — Convert apex-debugger debuggerStop/isvDebugBootstrap off SfCommandlet to Effect

## Context

- Depends on prereq WI "1 Move SfCommandlet into apex-debugger" (already done: `SfCommandlet` local at `packages/salesforcedx-vscode-apex-debugger/src/utils/sfCommandlet.ts`).
- Goal: rewrite 2 commands to Effect + services API (per ADR 0005); kill all commandlet-pattern code in monorepo.
- Pattern refs: `packages/salesforcedx-vscode-org/src/commands/orgCreate.ts`, `.../auth/orgLoginWeb.ts` (`ExtensionProviderService` → `api.services.*`).
- Data ops via `Connection`, not CLI:
  - `ConnectionService.getConnection()` yields jsforce `Connection` (ex: `packages/salesforcedx-vscode-metadata/src/commands/packageInstall.ts:79-83` `conn.tooling.query` wrapped in `Effect.tryPromise` w/ tagged error; `packages/salesforcedx-apex/src/utils/traceFlags.ts:86` `conn.tooling.update`).

Current state:
- `commands/debuggerStop.ts`: `StopActiveDebuggerSessionExecutor` shells `sf data query` (ApexDebuggerSession Status='Active'); `DebuggerSessionDetachExecutor` shells `sf data update record` Status="Detach". Both via `SfCommandlet` + `getSfCommandletExecutorClass()`. Note the current `catch {}` at debuggerStop.ts:119 silently swallows query/parse failures — do NOT port this.
- `commands/isvdebugging/bootstrapCmd.ts`: `IsvDebugBootstrapExecutor extends getSfCommandletExecutorClass()`; multiple `CliCommandExecutor` calls (project:generate, config:set, data:query namespace, project:retrieve:start, package:installed:list). ISV session auth via `org-isv-debugger-sid` config → NOT a normal username, so its data:query stays CLI.
- Cross-ext indirection `utils/coreExtensionUtils.ts`: `getChannelService`, `getTelemetryService`, `getSfCommandletExecutorClass`.
- Core: `commands/util/sfCommandletExecutor.ts` exported via `commands/util/index.ts` + `core/src/index.ts` (`SalesforceVSCodeCoreApi.SfCommandletExecutor`). Only external runtime consumer = apex-debugger. `orgCreate.ts` reference = comment only.

Decisions:
- debuggerStop query+update → `conn.tooling.query` / `conn.tooling.sobject('ApexDebuggerSession').update(...)`.
- bootstrap CLI project ops → `TerminalService.simpleExec` (`sf ...` auto-injects SF_JSON_TO_STDOUT/FORCE_COLOR); namespace query stays CLI (ISV session, not username-resolvable via ConnectionService).
- Channel/notifications → `api.services.ChannelService` + `vscode.window.*` (parity w/ orgCreate).
- Telemetry: `registerCommandWithLayer` gives span tracing; drop per-cmd `sendCommandEvent` (parity w/ migrated org cmds). `getTelemetryService` kept — still used by index.ts activation/deactivation + metric handler.

### Adversarial decisions (must resolve before/inside implementation)

- **cwd (Phase 0 blocker).** bootstrap is a cwd-dependent multi-step flow that no migrated command demonstrates: `project:generate` outputs to `projectParentPath` (bootstrapCmd.ts:245), then `config:set` (writes project-local `.sf/config.json` for `org-isv-debugger-sid`/`org-isv-debugger-url`/`org-instance-url`, keyed to cwd), `data:query`, `project:retrieve:start` (`--manifest this.relativeApexPackageXmlPath` = RELATIVE, only resolvable at cwd=projectPath, bootstrapCmd.ts:184), and `package:installed:list` all run at `{ cwd: projectPath }` (bootstrapCmd.ts:253,261,304,312,327). `simpleExec` has NO cwd param (terminalService.ts:40-50); `ChildProcess.exec`/`resolveExecOptions` accept only timeout/signal/env (childProcess.ts:11-21). Decision: **extend the service with `cwd`** (Phase 0) rather than absolute-path workarounds — config:set project-scoping is inherently cwd-bound, so absolute paths alone cannot achieve parity.
- **NODE_EXTRA_CA_CERTS / CLI env.** `setNodeExtraCaCerts` writes only into `GlobalCliEnvironment.environmentVariables` (a Map), never `process.env` (core/src/util/cliConfiguration.ts:11-16). The old `CliCommandExecutor.patchEnv` injects that Map into every spawned child (salesforcedx-apex-debugger/src/core/cliCommandExecutor.ts:12-23). `ChildProcess`/`simpleExec` only spread `process.env` + explicit `env` (childProcess.ts:16-21) → migrating drops NODE_EXTRA_CA_CERTS (corp proxy / custom CA) plus SF_LOG_LEVEL / SF_DISABLE_TELEMETRY for every bootstrap CLI call. Decision: **thread `GlobalCliEnvironment.environmentVariables` (Map→Record) into `simpleExec`'s `env` for the bootstrap calls** (parity, no regression). Note: the old executor constructs `CliCommandExecutor(command, options, false)` (bootstrapCmd.ts:408) with `inheritGlobalEnvironmentVariables=false`, yet patchEnv still merges the GlobalCliEnvironment Map — the `false` only suppresses `process.env` inheritance, not the CA-cert Map — so threading the Map is exact parity.

## Phases

### Phase 0 — add `cwd` to TerminalService.simpleExec + ChildProcess
- `childProcess.ts`: add `cwd?: string` to `ExecOptions`; thread it in `resolveExecOptions` (node exec `cwd` option). Keep the pure-fn shape so the merge stays unit-testable.
- `terminalService.ts`: add `cwd?: string` to the `simpleExec` param type; pass into `childProcess.exec({ ..., cwd })`. Doc it in the jsdoc.
- Tests: extend `resolveExecOptions` unit test (childProcess test) — cwd passed through when set, omitted when undefined; extend TerminalService test to assert `simpleExec({ cwd })` forwards cwd to the injected ChildProcess seam.
- Commit: `feat(services): thread cwd through TerminalService.simpleExec + ChildProcess`

### Phase 1 — debuggerStop.ts → Effect + Connection
- Rewrite as `Effect.fn('debuggerStop')`: get `api`; `conn = yield* api.services.ConnectionService.getConnection()`.
- Query: `conn.tooling.query<{Id:string}>("SELECT Id FROM ApexDebuggerSession WHERE Status = 'Active' LIMIT 1")` wrapped in `Effect.tryPromise` w/ tagged error (`IsvDebuggerQueryError` or `DebuggerSessionQueryError`) — do NOT reproduce the current `catch {}` (debuggerStop.ts:119) that swallows failures; let the tagged error flow to `ErrorHandlerService`.
- Branch on `result.records`: exactly 1 record whose `Id.startsWith('07a')` → `conn.tooling.sobject('ApexDebuggerSession').update({ Id, Status: 'Detach' })` (wrap in `Effect.tryPromise` w/ tagged error); else (0 records, or 1 non-'07a' Id) → NO update, `vscode.window.showInformationMessage(nls.localize('debugger_stop_none_found_text'))`.
- Channel output via `api.services.ChannelService` (append + show) for parity.
- Drop `SfCommandlet`/`SfCommandBuilder`/`CliCommandExecutor`/`IdGatherer`/`getSfCommandletExecutorClass`/`ProgressNotification`/`CommandOutput` imports.
- Add `@ExportTaggedError` class(es) for query/update failure (Schema.TaggedError) → ErrorHandlerService renders (parity w/ `OrgCreateParseError`, orgCreate.ts:41-43).
- index.ts: register via `api.services.registerCommandWithLayer(AllServicesLayer)('sf.debugger.stop', debuggerStop)` inside `activateEffect`; drop `vscode.commands.registerCommand('sf.debugger.stop', ...)`.
- Commit: `refactor(apex-debugger): rewrite debuggerStop to Effect + Connection tooling API`

### Phase 2 — bootstrapCmd.ts → Effect
- Rewrite `isvDebugBootstrap` as `Effect.fn`; gather (forceide URL / project name / folder) via `vscode.window.*` + `PromptService.considerUndefinedAsCancellation` (parity w/ orgCreate gatherers, orgCreate.ts:93-124) or keep plain-async gatherers called from Effect. Keep the existing `PathExistsChecker` overwrite-prompt semantics.
- Replace `IsvDebugBootstrapExecutor extends getSfCommandletExecutorClass()` + `CliCommandExecutor` calls w/ `TerminalService.simpleExec` for `sf project generate`, `sf config set`, `sf data query` (namespace), `sf project retrieve start`, `sf package installed list`; build command strings (double-quote path/arg values that can contain spaces).
- **cwd threading:** pass `{ cwd: projectParentPath }` to `project generate`; `{ cwd: projectPath }` to config set / data query / project retrieve start / package installed list (mirrors bootstrapCmd.ts:245,253,261,304,312,327). Depends on Phase 0. `--manifest` may then stay relative (`relativeApexPackageXmlPath`) as today, since cwd=projectPath.
- **CLI env threading:** build `env` from `GlobalCliEnvironment.environmentVariables` (Map→Record via `Object.fromEntries`) and pass to every bootstrap `simpleExec` call so NODE_EXTRA_CA_CERTS / SF_LOG_LEVEL / SF_DISABLE_TELEMETRY survive (parity w/ old patchEnv). simpleExec merges this over `process.env`; the auto-injected SF_JSON_TO_STDOUT/FORCE_COLOR still apply.
- **Error handling — do NOT port the five swallow-and-return catch blocks** (bootstrapCmd.ts:270-275 sfdx-project.json namespace write, 278-299 package.xml creation, 337-347 installed-package.json write loop, 351-358 temp cleanup, 361-393 launch.json write). Each currently does `catch (error) { console.error; channelService.appendLine; notificationService.showErrorMessage; return; }` — logs then silently truncates the rest of the bootstrap. Instead wrap each fs op in `Effect.tryPromise` with a dedicated `@ExportTaggedError` (e.g. `IsvBootstrapProjectConfigError`, `IsvBootstrapPackageXmlError`, `IsvBootstrapInstalledPackageWriteError`, `IsvBootstrapCleanupError`, `IsvBootstrapLaunchJsonError`), `Effect.fail` on error (not return), and let `ErrorHandlerService` render (parity w/ `OrgCreateParseError`). This is an effect-best-practices `must`: no `catchAll`/swallow-to-be-safe; fail with an improved error.
- Channel/notifications for the normal progress lines (`isv_debug_bootstrap_processing_package`, `..._generate_launchjson`, `..._open_project`) → `api.services.ChannelService` + `vscode.window.*`.
- Keep pure helpers `parseOrgNamespaceQueryResultJson` / `parsePackageInstalledListJson` + exported consts (`ISVDEBUGGER`/`INSTALLED_PACKAGES`/`PACKAGE_XML`) — test-referenced.
- Drop `SfCommandlet`/`CompositeParametersGatherer`/`SfCommandBuilder`/`CommandOutput`/`CliCommandExecutor`/`getChannelService`/`getSfCommandletExecutorClass`/`ProgressNotification` imports.
- index.ts: register `'sf.debug.isv.bootstrap'` via `registerCommandWithLayer`; drop plain `registerCommand`.
- Update `test/jest/commands/isvdebugging/bootstrapCmd.test.ts`: drop `SfCommandletExecutor` extension mock; test exported pure helpers + consts (drop class-instance/build-method assertions).
- Commit: `refactor(apex-debugger): rewrite isvDebugBootstrap to Effect + services API`
