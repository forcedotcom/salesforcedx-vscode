## Context

Kill `packages/salesforcedx-utils-vscode/src/helpers/paths.ts` (+ `test/jest/helpers/paths.test.ts`) and its
`fileExtensionsMatch, projectPaths` re-export from utils-vscode `src/index.ts:18`.

Current file contents (already trimmed by prior WIs — the WI's "delete as dead" list of
`metadataFolder`/`apexLanguageServerDatabase`/`lwcTestResultsFolder`/`testResultsFolder` and consts
`ORGS`/`METADATA`/`APEX_DB`/`LWC` **no longer exist**; nothing to do there):

- `fileExtensionsMatch` — **already dead**; its one consumer (`launchApexReplayDebuggerWithCurrentFile.ts:49-51`) was
  converted to `Utils.extname` by W-23465459. Only paths.test.ts + the index re-export remain.
- `projectPaths.stateFolder` / `.debugLogsFolder` / `.apexTestResultsFolder` — consumer = apex-replay-debugger only
  (`getDialogStartingPath.ts:30,35`, `quickLaunch.ts:57,77,78`, `anonApexDebug.ts:30`), all already inside Effect +
  `api.services.*`
- `projectPaths.salesforceProjectConfig` — 2 consumers: utils-vscode `workspaceContextUtil.ts:60` (FileSystemWatcher),
  apex-debugger `isvContext.ts:31` (watcher for the dead `sf:isv_debug_project` key)
- private `toolsFolder` — feeds debugLogs/apexTestResults

services already owns this: `projectService.ts:210` `getToolsFolder` = `Utils.joinPath(uri, Global.SFDX_STATE_FOLDER, 'tools')`
off `WorkspaceService.getWorkspaceInfoOrThrow()`. New accessors go alongside (ADR 0005: services API is the contract).
services cannot be a dep of utils-vscode -> consumer A inlines locally.

While rewriting those replay-debugger call sites, the utils-vscode async fs helpers used in the same functions
(`fileOrFolderExists`, `readFile`, `createDirectory`/`writeFile`, each currently `Effect.promise`-wrapped) switch to
their Effect-native `FsService` equivalents (`fsService.ts:33` `readFile`, `:50` `safeWriteFile`, `:88`
`fileOrFolderExists`) off the same `api.services.*` object — no new Promise wrappers in Effect code.
Out of scope: `debugConfigurationProvider.ts:9` also imports utils-vscode `readFile`, but it is not a paths.ts
consumer and is not otherwise touched by this WI -> left alone, so the package keeps its utils-vscode dep.

Confirmed dead: `sf:isv_debug_project` set at `isvContext.ts:22`, zero readers repo-wide (no `when:` clause in any
package.json, no other `.ts`/`.json` reference). `registerIsvAuthWatcher` + `setupGlobalDefaultUserIsvAuth` exist only
to set it + `console.log`; deleting them makes the whole `isCliInstalled` gate (`index.ts:264-290`) dead, incl.
`errors.ts` (`IsvAuthSetupError`, its only export) and nls key `isv_debug_config_environment_error`.

External consumers: `gh api search/code` for `projectPaths` / `fileExtensionsMatch` in `org:forcedotcom` returns only
this repo + its `salesforcedx-vscode-ui-preview` / `salesforcedx-vscode-ci-testing` mirrors (same
`packages/salesforcedx-utils-vscode/**` paths). No external importer -> export removal safe.

Semantics change (intentional): old `stateFolder()` returned `''` with no workspace; the new Effects fail
`NoWorkspaceOpenError`. All 3 replay-debugger call sites already sit behind an `isEmpty` early-return or inside a
command whose `.catch` surfaces the error, so no `''`-path is reachable.
