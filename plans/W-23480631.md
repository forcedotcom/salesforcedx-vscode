# W-23480631 — Delete GlobalCliEnvironment; TerminalService gathers CLI env at exec-time

## Context

- `GlobalCliEnvironment` (`packages/salesforcedx-utils/src/cli/globalCliEnvironment.ts`) = 1 static Map, was the push channel for 3 env vars into spawned `sf` children. Its core-side reader (`CliCommandExecutor.patchEnv` in the deleted utils-vscode commandExecutor) went away in 6c135f9a6 → core still writes, nothing in that process reads.
- Live regression on develop: `NODE_EXTRA_CA_CERTS` (corp TLS proxy) + `SF_DISABLE_TELEMETRY` never reach core-launched `sf`. `SF_LOG_LEVEL` survives only because `setSfLogLevel` also writes `process.env` (`vscode-core/src/util/cliConfiguration.ts:20`).
- Fix: pull at exec-time in `TerminalService.simpleExec` (`vscode-services/src/terminal/terminalService.ts`) for `sf ` commands, merged at lowest precedence (below the existing `SF_JSON_TO_STDOUT`/`FORCE_COLOR`/`SFDX_TOOL` and below caller `env`). Kills the push-once staleness: settings take effect next command, no reload. `bootstrapCmd` (ISV debug) uses `simpleExec` → gains all 3.
- Settings move (keys unchanged) to the contributing extension that now reads them: services. Core `extensionDependencies` includes services (`vscode-core/package.json:52`) → activation ordering holds.
- Web: `simpleExec` fails fast on `ESBUILD_PLATFORM === 'web'` (`terminalService.ts:62`); env build must sit after that guard so no `vscode`/aggregator work happens on web.

Accepted consequences (call out in PR body):

- Deleting `setSfLogLevel` also drops the `process.env.SF_LOG_LEVEL` write. Extension-host `@salesforce/core` Logger verbosity is no longer seeded from that setting — incidental side effect of a setting documented as "SF_LOG_LEVEL CLI environment variable value"; extension-side log level is `salesforcedx-vscode-salesforcedx.logLevel` (the `observability/localTracing.ts:28` env fallback is already dead: manifest default `error` means `get('logLevel')` never returns undefined).
- `@salesforce/salesforcedx-utils` is published; dropping the `GlobalCliEnvironment` export is a breaking export removal. `gh` code search across `org:forcedotcom` / `org:salesforcecli`: only this repo's forks (`salesforcedx-vscode-ui-preview`, `salesforcedx-vscode-ci-testing`) reference it.
- `TelemetryServiceInterface` (`@salesforce/vscode-service-provider`, `lib/src/types/telemetry/telemetryTypes.d.ts`) requires `setCliTelemetryEnabled(isEnabled: boolean): void` → the method stays as a documented no-op; only its call site + `disableCLITelemetry` go.
- Per-`sf `-exec cost: 2-4 `SettingsService.getValue` calls (in-memory `workspace.getConfiguration`) + 1 `ConfigAggregator` read (cached aggregator + `reload()` on desktop), the latter short-circuited when VS Code telemetry is already off.
