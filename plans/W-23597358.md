# W-23597358 — 1 Redact Salesforce secrets from span sinks

## Context

Pkg `salesforcedx-vscode-services`, dir `src/observability/`.

Leak today: `@effect/opentelemetry` `internal/tracer.js:104-119` sets `status.message = Cause.pretty(cause)` and calls `span.recordException(firstError)` with `firstError.stack = Cause.pretty(...)` on every failed span. `SpanImpl.recordException` turns that into an `exception` event (`exception.message` / `exception.stacktrace` / `exception.type`). Azure maps the event to Breeze `ExceptionData`; `O11ySpanExporter` separately egresses `status.message` (`o11ySpanExporter.ts:126`). Third-party error text from jsforce / `@salesforce/core` therefore egresses on the DEFAULT Node path.

Chosen point of interception: ONE `SpanProcessor.onEnding` implementation, registered unconditionally and first.

- `SpanImpl.end()` (`node_modules/@opentelemetry/sdk-trace-base/build/src/Span.js:265-270`): `onEnding(this)` -> `_ended = true` -> `onEnd(this)`. `MultiSpanProcessor.onEnding` loops ALL processors before any `onEnd`, so one processor covers every registered sink (console, App Insights gated, O11y gated, OTLP http, OTLP file).
- `spanProcessor: [...]` array in `NodeSdk.js:25` / `WebSdk.js:25` becomes `spanProcessors`, i.e. `MultiSpanProcessor`. Confirmed.
- `BatchSpanProcessor` has no `onEnding`, so `SpanTransformProcessor` ordering is irrelevant — register first anyway for intent.
- `attributes` / `events` are public fields on `SpanImpl` (`Span.d.ts`); `readonly` only blocks reassigning the reference, index signatures are mutable. `status` is a plain mutable field. `_ended` gates only `setAttribute`/`setStatus`, and is still `false` during `onEnding`, so either route works — use direct field writes.

Value patterns copied WITH attribution from `@salesforce/core` `util/sfdc` + `logger/filters` (`node_modules/@salesforce/core/lib/util/sfdc.js:51-54`, `lib/logger/filters.js:42-44`). NOT importable: `@salesforce/core` `package.json` `exports` map has no `./util/sfdc` and no `./logger/filters` entry.

`@salesforce/core`'s key-name filters (`filters.js:13-16` `buildTokens` / `buildKeyRegex`) match JSON-shaped `"key": "value"` text only — structurally cannot catch `Bearer x`, `sid=x`, or a bare refresh token in a prose stack trace. Hence the extra shapes here.

Cost is customer-facing, not dev-only: the App Insights `SpanTransformProcessor` is registered unconditionally in both `spansNode.ts` and `spansWeb.ts`, so `onEnding` runs synchronously on every span end in every session. The `String.includes` pre-check guard is required, not an optimisation.

ADR-0019 constraint: must not drop `orgId` / `userId` / `webUserId` / `devHubOrgId`. Satisfied structurally — `accessTokenRegex` requires the `!` separator, so a bare 18-char `00D...` orgId does not match. Assert in unit tests.

Out of scope (W-23597360): the Effect logger path. `Logger.minimumLogLevel` + `OtlpLogger.layer` (`spansNode.ts:130-138`) and `OtlpFileLogExporterNode` (`spansNode.ts:127`) carry log RECORDS, not spans, and no `SpanProcessor` sees them.

Note: `otlpFileSpanExporterNode.ts:30` comment claims `otlp-{timestamp}.jsonl`; the real filename is `{timestamp}.jsonl` (`otlpFileSpanExporterNode.ts:25`). The WI's `otlp-*.jsonl` glob is wrong — e2e must glob `~/.sf/vscode-spans/*.jsonl`.

## Phases

### Phase 1 — redactSecrets module

New `packages/salesforcedx-vscode-services/src/observability/redactSecrets.ts`. Must stay web-safe (no `node:` imports) — consumed by `spansWeb.ts`.

Pattern table, ordered; alternation is left-biased at each match position:

| # | label | source | attribution / delta |
|---|-------|--------|---------------------|
| 1 | `<REDACTED AUTH URL TOKEN>` | `force:\/\/(?:[a-zA-Z0-9._-]+):(?:[a-zA-Z0-9._-]*):(?:[a-zA-Z0-9._-]+={0,2})@(?:[a-zA-Z0-9._-]+)` | core `sfdxAuthUrlRegex`, inner groups made non-capturing |
| 2 | `<REDACTED JWT TOKEN>` | `eyJ[A-Za-z0-9+=_-]+\.[A-Za-z0-9+=_-]+\.[A-Za-z0-9+=_-]+` | core `jwtTokenRegex`, verbatim |
| 3 | `<REDACTED ACCESS TOKEN>` | `00D\w{12,15}![^\s'"]+` | core `accessTokenRegex`, tail WIDENED from `[.\w]*` to `[^\s'"]+`; segment after `!` is the secret and `[.\w]*` stops at the first `-`/`=`/`+`, leaving real token bytes in the log. Capture group dropped — whole match replaced, as core does |
| 4 | `<REDACTED BEARER TOKEN>` | `Bearer [^\s'"]+` | new; case-sensitive to match the `'Bearer '` guard hint |
| 5 | `<REDACTED SID>` | `sid=[^\s'"&;]+` | new |
| 6 | `<REDACTED REFRESH TOKEN>` | `refresh_?[Tt]oken["']?\s*[:=]\s*["']?[^\s'"&,;}]+` | new; key-shaped, covers `refresh_token=...`, `"refresh_token":"..."`, `refreshToken: ...` |

Assembly: one combined `RegExp` built at module load as ``PATTERNS.map(([, src]) => `(${src})`).join('|')`` with the `g` flag; single `String.replace` pass, replacer picks the label by index of the first defined capture group. Every pattern's internal groups MUST be non-capturing or the label index shifts.

Guard, before the replace: `HINTS.some(h => value.includes(h))`, else return `value` unchanged.

Hints: `'force://'`, `'eyJ'`, `'!'`, `'Bearer '`, `'sid='`, `'refresh_token'`, `'refreshToken'`.

DEVIATION from the WI's 5-hint list, deliberate: WI lists `!`, `eyJ`, `force://`, `Bearer `, `sid=` but also asks for a refresh-token shape. With no refresh hint that pattern can never fire, so hints 6 and 7 are added. All hints are case-sensitive `includes` and every pattern is case-sensitive, so hints and patterns agree.

Public surface: `redactSecrets(value: string): string`. Const arrow, no `function` keyword.

commit: `feat(services): redactSecrets module for Salesforce secret patterns`
