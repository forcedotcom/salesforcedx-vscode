# In the org extension, CLI shell-out is always an allowed implementation

Root [ADR-0009](../../../../docs/adr/0009-reduce-cli-deps-web-no-cli.md) prefers in-process libraries and permits the CLI for known-never-web code; [ADR-0002](./0002-deliberately-not-web.md) puts `salesforcedx-vscode-org` permanently in that category. Within this extension that permission is unconditional: `sf` shell-out via `TerminalService.simpleExec` is an accepted implementation for ANY command, not a last resort for commands that lack an in-process alternative — an existing `@salesforce/core` path is not a reason to keep or prefer it. The CLI is the same code customers run, so its output (including its own secret redaction and connected-status logic) is the source of truth and cannot drift from ours; every avoided `AuthInfo`/`Connection`/`Org` + SOQL reimplementation is bundle weight and behavior we no longer own. Consistency within the extension matters more than per-command optimization: `orgCreate`, `orgDelete`, `orgOpen`, and `orgDisplay` all shell out, so reviewers should not ask a new org command to go in-process, and moving an existing one from in-process to the CLI is a valid refactor rather than a regression.
