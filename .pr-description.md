### What does this PR do?

Implements a changelog strategy that separates cumulative repository history from release-specific packaging, avoiding branch-dependent content on the same path.

**Architecture:**

- `/CHANGELOG.md` — Full cumulative history (lives on develop, grows with each release)
- `/packages/salesforcedx-vscode/CHANGELOG.md` — Current release notes only (replaced each week, packaged into VSIX)

This separation eliminates merge conflicts and the need for specialized merge strategies (`-X ours`), while keeping release branches small and marketplace-ready.

**How it works:**

1. **Release branch creation**: Package CHANGELOG contains only new release notes (~50 lines)
2. **Packaging**: VSIX includes only the package CHANGELOG (marketplace size compliant)
3. **Merge to develop**: Package CHANGELOG is prepended to root CHANGELOG (idempotent, with version dedup)

**Key changes:**

- Moved full history to `/CHANGELOG.md` (root) with 191 releases restored
- Modified [scripts/change-log-generator-utils.js](scripts/change-log-generator-utils.js) — continues writing to package location
- Updated [scripts/prepend-release-changelog.js](scripts/prepend-release-changelog.js) — idempotent prepend from package to root, no longer takes branch argument
- Updated [.github/workflows/mergeReleaseBranch.yml](.github/workflows/mergeReleaseBranch.yml) — removed `-X ours` merge strategy, regular merge now works
- Added [scripts/restore-changelog-history-from-github.js](scripts/restore-changelog-history-from-github.js) — one-time restoration of historical changelog from GitHub releases

**Result:**
- ✅ Root CHANGELOG: Full history (191 releases, 3,811 lines, grows forever)
- ✅ Package CHANGELOG: Only current release (~50 lines, replaced each week)
- ✅ VSIX packages: Contain only latest release (meets size limits)
- ✅ No merge conflicts: Different file paths, no branch divergence
- ✅ Regular merges work: No `-X ours` or special strategies needed
- ✅ Idempotent: Version dedup prevents duplicate entries

### What issues does this PR fix or reference?

Fixes the issue where CHANGELOG.md was truncated each week, losing all historical release notes from the repository. History was only accessible via GitHub releases.

Addresses [review feedback](https://github.com/forcedotcom/salesforcedx-vscode/pull/7659#pullrequestreview-4776815096) to separate artifacts by location and remove branch-dependent merge behavior.

### Functionality Before

**On develop:**
- CHANGELOG.md: 49 lines (1 release only)
- Historical changes lost from repository
- Full history only in GitHub releases

**On release branch:**
- Same as develop (49 lines)

**During merge:**
- Required `-X ours` strategy to preserve develop's content
- Risk of silently discarding changes on conflicts

### Functionality After

**On develop:**
- Root CHANGELOG.md: 3,811 lines (191 releases, 2022-2026)
- Package CHANGELOG.md: ~50 lines (current release)
- Full history maintained and grows with each release

**On release branch:**
- Package CHANGELOG.md: ~50 lines (just this week's changes)
- Root CHANGELOG.md: Inherited from develop (full history)

**During packaging:**
- `vsce package` runs from `packages/salesforcedx-vscode/`
- Only includes local CHANGELOG.md (~50 lines)
- VSIX meets marketplace size limits

**During merge:**
- Regular merge (no special strategy)
- No conflicts (different file paths)
- Prepend script is idempotent (skips if version exists)

**Example flow:**
```
Create release branch from develop
├─> Root CHANGELOG: 3,811 lines (inherited, unchanged)
└─> Package CHANGELOG: replaced with ~50 lines (new release)

Package & publish
└─> VSIX contains ~50 lines from packages/salesforcedx-vscode/CHANGELOG.md ✅

Merge release → main → develop (regular merge, no -X ours)
└─> Script prepends package CHANGELOG to root CHANGELOG
└─> Root CHANGELOG now has 3,860 lines (history grows)

Next week repeats from step 1
```

### Technical Details

**One-time restoration:**
- Ran [scripts/restore-changelog-history-from-github.js](scripts/restore-changelog-history-from-github.js) to fetch all historical releases from GitHub
- Script extracts only the first changelog section from each release
- Reconstructed 191 releases with proper deduplication
- Result committed to root `/CHANGELOG.md`

**Idempotent prepending:**
- [scripts/prepend-release-changelog.js](scripts/prepend-release-changelog.js):
  - Reads package CHANGELOG, extracts version from first line
  - Checks if version already exists in root CHANGELOG
  - Skips if present (idempotent), prepends if new
  - No branch argument needed (reads from local filesystem)

**Simplified merge workflow:**
- [.github/workflows/mergeReleaseBranch.yml](.github/workflows/mergeReleaseBranch.yml):
  1. Merges release → main (rebase)
  2. Merges main → develop (regular merge, no `-X ours`)
  3. Runs `prepend-release-changelog.js` (idempotent)
  4. Commits root CHANGELOG only if script made changes
